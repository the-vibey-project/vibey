# 8.a: the sovereign lane is primary for the diff half of review (delivered; close with live evidence)

## Summary

Delivered in code. When the operator's runner reports a fresh heartbeat, the self-hosted
local model now reviews the exact-head diff **first**. For a trusted author it carries the
diff-groundable half of the verdict (`pass`, `summary`, `findings`). The paid reviewer is
asked only for the requires-wider-context half: the sixteen documentation judgments plus
its own `wider_summary` / `wider_findings`. The gate composes one verdict and names the
lane behind each half. With no heartbeat, behaviour is the previous gate word for word.
With no credits, it is the #277 local fallback. The only thing not yet evidenced is a
**live** run on this repository. Two follow-ups come from canon ratified after this issue
was written: the default reviewer model (8.d) and routing through the sovereign loop's
queue (8.c). Both belong in new issues, not in this one.

This body records the evidence so the issue can be closed. Suggested closing condition: one
live pull request whose gate summary names the sovereign lane for the diff half and whose
paid call used the narrowed schema, linked here.

## Why

- **8.a** (`src/vibey_tools/gh/docs/doctrines.md:99-118`): the sovereign path is the
  preference, never the fallback. Paid is the move that must be justified.
- **10 decomposition clarification** (`:371-383`): decompose the review into what each
  lane can carry, rather than choosing one lane for the whole job.
- **Constitution Article III.2 and III.4** (`constitution.md:90-92`, `:97-99`): separation
  of powers, and machine speech labelled at the exact head.
- **10.f** (`:419`): a verdict is not completion. This issue closes on evidence.

## Original text

Issue #133, "8.a: make the sovereign lane primary for the half of review it can fully carry", opened by @adammatthewsteinberger on 2026-09-15T10:17:58Z. Body, verbatim:

~~~~markdown
Doctrine **8.a** (ratified) says the 100% sovereign path is always the number one
preferred way to run this code, and that paid platforms are never prioritized.

#277 took the first step: both sovereign lanes are now **on by default**, gated on a
readiness probe so they can never queue against an offline runner. But the sovereign
lane is still structurally a *fallback* — it runs only when the paid review returned
**no verdict at all**. Under 8.a, that ordering is backwards.

## Why it was not simply inverted in #277

The local verdict is narrower **by construction**, and this is a real capability floor
rather than a preference:

- constrained decoding guarantees the output *shape*, not the *judgment*;
- it reviews the **diff only** — the documentation-contract fields are not evaluated at
  all.

Doctrine 10's decomposition clarification is the right tool here: decompose the review
into the parts each lane can actually carry, rather than choosing one lane for the whole
job.

## Proposed shape

1. **Split the review contract** into what is diff-groundable (the sovereign lane can
   carry this in full) and what requires the wider context (documentation contract,
   cross-file reasoning).
2. **Sovereign goes first** on the diff-groundable half whenever the probe reports ready.
3. **Paid runs** for the remainder — and only for the remainder — so a healthy sovereign
   lane *reduces* paid spend rather than being bypassed by it.
4. **Gate composition**: the published verdict states which lane carried which half, so a
   human can always see what was actually evaluated and by what.
5. The paid lane remains the fallback for the sovereign half when the probe says not
   ready — the current relationship, inverted.

## Acceptance

- with a fresh heartbeat and credits available, the diff review is carried by the
  sovereign lane and the paid call is measurably smaller;
- with no heartbeat, behaviour is exactly today's;
- with no credits, behaviour is exactly #277's;
- the gate names the lane behind each half of the verdict;
- 100% coverage maintained.
~~~~
