## Why
ADR-0044 §1 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`) says the composition root is the only place that knows which queue backend runs. Today the CLI knows:

- `vibey worker` imports `PostgresJobReadyNotifier` (`src/vibey/cli/main.py:1467`) and builds it itself (`:1713-1714`), closing it in the drive loop's `finally` (`:1754-1758`);
- `AppResources` types `jobs` as the concrete `PostgresJobRepository` (`src/vibey/bootstrap.py:136`).

This lane moves the notifier's construction into `bootstrap.py` behind a declared seam and changes no behaviour. Sub-doctrine 9.b (`src/vibey_tools/gh/docs/doctrines.md:349`): substitution happens at the declared seam, never by patching an import. The opener therefore takes its notifier factory as a constructor argument, and the new tests inject one.

**Transition.** 26 tests in `tests/cli/test_operational_commands.py` (first at `:1255`) and one in `tests/cli/test_sovereign_provider_options.py:151` still `patch("vibey.infrastructure.db.notifier.PostgresJobReadyNotifier")`. They must keep passing unchanged until lane `fakes-job-wakeup` replaces them. So the opener's **default** factory looks the class up on the module at call time. That default exists only for those legacy tests; no new test may rely on it. Lane `orm-notifier` keeps `PostgresJobReadyNotifier(dsn)`'s signature for the same reason.

Verified at integration `739536ea`.

## Required behaviour
1. `AppResources.jobs` is annotated as the `JobRepository` Protocol (`vibey.application.interfaces.queue`, `:90`). The value is still `PostgresJobRepository(...)` as `build_app` builds it today (`bootstrap.py:918`).
2. `bootstrap_interface.py` declares two `@runtime_checkable` Protocols:
   - `ConnectingJobReadyNotifierInterface(JobReadyNotifier, Protocol)` with `async def connect(self) -> None` and `async def close(self) -> None`. (Lane `orm-notifier` later declares the same contract as `PostgresJobReadyNotifierInterface`; if that name already exists on the integration branch when this lane starts, use it instead and do not declare a second one.)
   - `JobWakeupOpenerInterface` with `async def open(self) -> JobReadyNotifier` and `async def close(self, notifier: JobReadyNotifier) -> None`.
3. A new class `JobWakeupOpener` in `src/vibey/bootstrap.py`:
   - `__init__(self, dsn: str, *, notifier_factory: Callable[[str], ConnectingJobReadyNotifierInterface] | None = None)`.
   - `open()` builds the notifier with `self._notifier_factory(self._dsn)` when a factory was given; otherwise with `self._default_notifier(self._dsn)`. It awaits `connect()` and returns the notifier.
   - `_default_notifier(self, dsn)` does `from vibey.infrastructure.db import notifier as db_notifier` inside its body and returns `db_notifier.PostgresJobReadyNotifier(dsn)`. Its docstring says: "Transitional: resolved at call time only so the CLI tests that still patch this class keep working until `fakes-job-wakeup` removes them. New code and tests pass `notifier_factory`."
   - `close(notifier)` awaits `notifier.close()` when the notifier has a `close` attribute that is callable, and otherwise does nothing.
4. `AppResources` gains a required field `wakeup: JobWakeupOpenerInterface`, placed before `integration_lock` (which has a default). `build_app` builds it once from `url or database_url()` and passes it in its single `yield AppResources(...)` (`bootstrap.py:916`). `AppResourcesInterface` gains `@property def wakeup(self) -> JobWakeupOpenerInterface: ...`.
5. `vibey worker` gets its notifier from `notifier = await resources.wakeup.open()` where it built one before (`cli/main.py:1713-1714`), and closes it with `await resources.wakeup.close(notifier)` in the existing `finally` (`:1754-1758`). The import at `:1467` goes away.
6. Behaviour is unchanged: same channel, same 5-second wait, same output lines.
7. **The in-memory fake.** Add `InMemoryJobWakeupOpener` (implements `JobWakeupOpenerInterface`):
   - `__init__(self, notifier: JobReadyNotifier)`;
   - `open()` increments `self.opened` and returns the notifier;
   - `close(notifier)` increments `self.closed`.

   Put it in `tests/fakes/queue.py` if that file exists on the integration branch when the lane starts (lane `fakes-registry` creates it); otherwise in `tests/application/fakes.py` beside `FakeJobRepository`. If `tests/fakes/registry.py` exists, register it (`JobWakeupOpenerInterface → InMemoryJobWakeupOpener(<a notifier that never fires>)`) and add `JobWakeupOpenerInterface` to `DRIVER_SEAMS`. This is the exact shape `fakes-job-wakeup` specifies, so that lane extends it instead of adding a second one.
