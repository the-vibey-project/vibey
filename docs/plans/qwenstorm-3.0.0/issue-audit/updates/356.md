## Why
ADR-0044 §8 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`), and ADR-0024: every bounded ladder parks with a grant. Neither the claim nor the reaper bounds a job that takes its worker down:

- the claim increments `attempts` with no upper bound (today `src/vibey/infrastructure/db/job_repository.py:182-187`; as Core, `JobStatements.claim`, lane `orm-job-statements-settle`);
- `reap()` re-readies every expired lease unconditionally (today `:311-320`; as Core, `JobStatements.reap`, run through the seam by lane `orm-job-settle`).

A handler that kills its process on every attempt therefore never reaches `_settle_failure` (`src/vibey/application/worker.py:224-272`), and it is re-claimed forever. The RabbitMQ backend bounds the same failure through the broker's delivery limit (#358). This lane gives the PostgreSQL backend the same bound under the same gate kind, `delivery_exhausted`.

The job repository reaches PostgreSQL only through `PostgresOrmInterface` once the ORM wave's four job-queue lanes land (`orm-job-statements-enqueue`, `orm-job-statements-settle`, `orm-job-enqueue`, `orm-job-settle`); `specs/orm-job-settle.md` names this lane as landing after it and extending `reap`. So the new statements are SQLAlchemy Core on `JobStatements`, and the in-memory `FakeJobRepository` (made PostgreSQL-faithful by `fakes-queue-gates`) learns the same bound.

Verified at integration `739536ea` (line numbers above are today's; the ORM lanes move them).

## Required behaviour
1. **Statements** on `JobStatements` (`src/vibey/infrastructure/db/job_statements.py`), each declared on `JobStatementsInterface`, with `JOBS`, `GATES = TABLES.table("human_gate")` and typed literals only (no `text()`, no `literal_column`):
   - `reap()` gains `JOBS.c["attempts"] < JOBS.c["max_attempts"]` in its WHERE. Nothing else in it changes.
   - `reap_exhausted()`: `update(JOBS).where(JOBS.c["state"] == "leased", JOBS.c["lease_expires_at"] < func.now(), JOBS.c["attempts"] >= JOBS.c["max_attempts"]).values(state="awaiting_human", lease_owner=None, lease_expires_at=None, attempts=func.greatest(JOBS.c["attempts"] - 1, 0), updated_at=func.now()).returning(JOBS.c["id"], JOBS.c["project_id"], JOBS.c["kind"], JOBS.c["max_attempts"])`.
   - `delivery_exhausted_prompt(kind: str, max_attempts: int) -> str`: `f"job {kind!r} was abandoned mid-run on each of its {max_attempts} deliveries (its worker died, was killed, or lost its lease every time). Answer anything to retry it once."`
   - `delivery_exhausted_gates(rows: Sequence[Mapping[str, Any]])`: `insert(GATES).values([{"project_id": r["project_id"], "job_id": r["id"], "kind": "delivery_exhausted", "prompt": self.delivery_exhausted_prompt(r["kind"], r["max_attempts"])} for r in rows]).returning(GATES.c["gate_id"])`.
   - `notify_gate_raised(gate_id: UUID)`: `select(func.pg_notify("vibey_gate_raised", str(gate_id)))`, the function form of today's `NOTIFY vibey_gate_raised` (`human_gate_repository.py:58`).
2. **Repository.** `PostgresJobRepository` gains a protected method `async def _park_exhausted(self, conn: AsyncConnection) -> int`: execute `reap_exhausted()`; when it returns rows, execute `delivery_exhausted_gates(rows)` and then `notify_gate_raised` once per returned gate id; return the number of parked jobs. #358's child 2 reuses this method; do not duplicate it.
3. `PostgresJobRepository.reap()` runs one `self._orm.transaction()`: `parked = await self._park_exhausted(conn)`, then `readied = (await conn.execute(JOB_SQL.reap())).rowcount`, and returns `parked + readied`.
4. A gate raised by the park is answered through the ordinary path (`PostgresHumanGateRepository.answer`, today `human_gate_repository.py:61-86`), which re-readies the job. Because the park refunded one attempt, each answer buys exactly one more delivery.
5. Nothing else in the class changes.
6. **The fake.** `FakeJobRepository.reap` (`tests/fakes/queue.py`, lane `fakes-queue-gates`) applies the same bound: each `LEASED` job with `lease_expires_at < now` and `attempts >= max_attempts` becomes `AWAITING_HUMAN` with the lease cleared and `attempts = max(attempts - 1, 0)`, and a `HumanGateRecord` with `kind="delivery_exhausted"`, `job_id` set and the prompt from `JOB_SQL.delivery_exhausted_prompt(...)` is added to `store.gates`; the others re-ready as before (calling `on_ready`). It returns parked plus re-readied.
7. **Stop rule:** if an existing test in `tests/infrastructure/db/test_job_repository.py` or `tests/fakes/test_fake_queue.py` asserts that `reap()` re-readies a row whose `attempts >= max_attempts`, stop and report. Do not edit that test.
