Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §4 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`). When a job becomes claimable it must get a dispatch generation and an outbox row **in the same transaction** as the state change. There are two such moments:

- it is enqueued with every dependency already met;
- the ack of its last dependency commits.

Otherwise a crash between the commit and the publish could lose the dispatch. `PostgresJobRepository` owns the enqueue (`_enqueue_on`, today `src/vibey/infrastructure/db/job_repository.py:66-134`) and the fenced ack (`:223-235`). After the ORM wave's job-queue lanes (`orm-job-statements-enqueue`, `orm-job-statements-settle`, `orm-job-enqueue`, `orm-job-settle`) they run as SQLAlchemy Core (`JOB_SQL`) through `PostgresOrmInterface`, and `_enqueue_on` takes an `AsyncConnection`; `specs/orm-job-enqueue.md` names this lane as overriding `_enqueue_on` after them. The RabbitMQ backend reuses both through a subclass and adds only the dispatch-writing steps. The PostgreSQL backend class is not modified. Its shared unmet-dependency clause is `JOB_SQL.deps_unmet` (`orm-job-statements-settle`, behaviour 1), which these statements reuse instead of restating it.

Verified at integration `739536ea` (line numbers above are today's; the ORM lanes move them).

## Required behaviour
1. **Statements.** `class DispatchStatements` in `src/vibey/infrastructure/db/dispatch_statements.py`, with `JOBS = TABLES.table("job")`, `DEPENDENCIES = TABLES.table("job_dependency")` and `DISPATCH_COLUMNS = (id, project_id, dispatch_seq, kind, run_after)` of `JOBS`; typed literals only (no `text()`, no `literal_column`):
   - `release_enqueued(job_id: UUID)`: `update(JOBS).where(JOBS.c["id"] == job_id, JOBS.c["state"] == "ready", JOBS.c["dispatch_seq"] == 0, ~JOB_SQL.deps_unmet(JOBS)).values(dispatch_seq=1, dispatched_at=None).returning(*DISPATCH_COLUMNS)`.
   - `release_dependents(acked_job_id: UUID)`: `update(JOBS).where(JOBS.c["state"] == "ready", JOBS.c["dispatch_seq"] == 0, exists().where(DEPENDENCIES.c["job_id"] == JOBS.c["id"], DEPENDENCIES.c["depends_on_job_id"] == acked_job_id), ~JOB_SQL.deps_unmet(JOBS)).values(dispatch_seq=1, dispatched_at=None).returning(*DISPATCH_COLUMNS)`.
   - `DISPATCH_SQL: Final[DispatchStatementsInterface] = DispatchStatements()` (stateless; one instance serves).
2. **Writer.** `class DispatchOutboxWriter` in `src/vibey/infrastructure/db/dispatch_records.py` has one method, `async def write(self, conn: AsyncConnection, dispatch: JobDispatch, *, key_suffix: str = "") -> bool`. It builds `vibey_bootstrap.db.outbox.AsyncOutbox(conn, table="job_outbox", track_claims=True)` (#352, R05) and enqueues the idempotency key `f"dispatch:{dispatch.job_id}:{dispatch.dispatch_seq}{key_suffix}"` with payload `JOB_DISPATCH_CODEC.encode(dispatch)` (#353, R06). It returns whether a row was inserted.
3. **Records.** `class DispatchingJobRecords(PostgresJobRepository)` takes `orm: PostgresOrmInterface`, keyword `writer: DispatchOutboxWriterInterface` and keyword `rows: JobRowMapperInterface = JOB_ROWS`.
   - It overrides `_enqueue_on(conn, request, enqueued)`: `record = await super()._enqueue_on(conn, request, enqueued)`, then executes `DISPATCH_SQL.release_enqueued(record.id)` on the same `conn`. A returned row gets one outbox row through the writer with `not_before = row["run_after"]`. A replayed enqueue, where the row exists and `dispatch_seq` is already ≥ 1, writes nothing.
   - `async def ack_and_release(self, job_id: UUID, *, owner: str) -> tuple[bool, tuple[JobDispatch, ...]]` runs one `self._orm.transaction()`: execute `JOB_SQL.ack(job_id, owner=owner)`; if its `rowcount` is not 1, return `(False, ())` and change nothing else; otherwise execute `DISPATCH_SQL.release_dependents(job_id)`, write one outbox row per returned job, and return `(True, dispatches)`.
   - `ack()` is overridden to `return (await self.ack_and_release(job_id, owner=owner))[0]`, so the class still satisfies the `JobRepository` Protocol (`application/interfaces/queue.py:90`).
   - The class never publishes. Publishing belongs to the relay (#360, R13).
4. **Interfaces** (9.b): `DispatchStatementsInterface` in `infrastructure/db/interfaces/dispatch_statements_interface.py`; `DispatchOutboxWriterInterface` and `DispatchingJobRecordsInterface(JobRepository, Protocol)` (adds `ack_and_release`) in `infrastructure/db/interfaces/dispatch_records_interface.py`. Driver types (`AsyncConnection`) under `TYPE_CHECKING` only; copy `interfaces/job_repository_interface.py`. Export them from `interfaces/__init__.py`. `vibey.infrastructure.db.interfaces` is already in `.importlinter`'s `infrastructure-interfaces-declare-only` contract (`.importlinter:108`).
5. **The in-memory fakes** in `tests/fakes/queue.py`, over the shared `InMemoryQueueStore` (lane `fakes-queue-gates`):
   - `FakeDispatchOutboxWriter` (`DispatchOutboxWriterInterface`): `write(conn, dispatch, *, key_suffix="")` builds the same key; a key it has seen returns `False`; otherwise it appends `(key, dispatch)` to `self.written` and returns `True`. `conn` is ignored (the in-memory store is the transaction).
   - `FakeDispatchingJobRecords(FakeJobRepository)` with a keyword `writer: FakeDispatchOutboxWriter | None = None` and `self.dispatch_seq: dict[UUID, int]` (absent means 0). `enqueue` and `enqueue_batch` call the parent, then move each returned job that is `READY`, at sequence 0, with every dependency `SUCCEEDED`, to sequence 1 and write its dispatch (`not_before = run_after`); a batch that raises writes nothing. `ack_and_release` calls the parent's `ack`; on `False` it returns `(False, ())`; otherwise it releases every `READY` sequence-0 job that depends on `job_id` and whose dependencies have all `SUCCEEDED`. `ack` returns `ack_and_release(...)[0]`.
   - Register both in `tests/fakes/registry.py` (`REGISTRY`, and both ports in `DRIVER_SEAMS`).

## Acceptance criteria
- [ ] Enqueueing a job with no dependencies gives `dispatch_seq = 1` and exactly one `pending` `job_outbox` row, whose payload decodes to the `JobDispatch`; the same on the fakes (`writer.written` has one entry).
- [ ] Enqueueing again with the same key leaves one outbox row and `dispatch_seq = 1`.
- [ ] A job with an unmet dependency stays at `dispatch_seq = 0` with no outbox row.
- [ ] In a batch where B depends on A: A is at 1 and B at 0. A batch rolled back by a bad dependency key leaves no outbox rows.
- [ ] Acking A releases B (B goes to 1 with an outbox row). An ack by a non-owner releases nothing and returns `(False, ())`.
- [ ] A dependent with two dependencies is released only by the second ack.
- [ ] `isinstance(records, JobRepository)`, `isinstance(records, DispatchingJobRecordsInterface)`, and the same for the fake; `tests/fakes/test_port_parity.py` passes.
- [ ] 100% infrastructure coverage.
