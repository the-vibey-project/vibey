# One book, one paper, from one source each: retire the eight tenant papers and book definitions

## Summary

The operator asked for "a single book.pdf and single paper.pdf so there aren't multiple of
each anymore". A follow-up comment asked that the paper be "FULLY COMPREHENSIVE", built on
the entire development cycle and all the data collected, and that it carry the claim that
software engineering is commodity work apart from governance, which is scarce.

Much has happened since:

- The published paper is **one family paper**. `docs/paper.md` grew from 234 to 1,469
  lines and absorbed the engine family, exact-head evaluation, retrieval, bootstrap, and a
  measured production-rate section.
- Its abstract closes on "the scarce inputs were governance and correct judgment, not
  production".
- Its figures are recomputed by `scripts/paper_evidence.py`.
- Each documentation channel publishes one `paper.pdf`/`paper.docx` and one
  `book.pdf`/`book.docx`/`book.epub`.

What remains is at the **source** level. Eight tenant `docs/paper.md` files and eight
tenant `properdocs.yml` book definitions are still tracked. They are separate papers with
their own theses, several now out of date against the canon. The "fully comprehensive"
half now overlaps #301 (the paper revision) and should live there.

## Why

- **Doctrine 6** (`src/vibey_tools/gh/docs/doctrines.md:60-63`): "Every repository produces
  a journal-grade research paper". Since ADR-0021/0037 there is one repository and one
  distribution, so doctrine 6 asks for one paper here. Whether tenant papers survive as
  appendices is the operator's call.
- **ADR-0032** (the documentation ships as a paper and a book): designed for one paper per
  repository plus companions. It needs an amendment if the companions go.
- **7 the never-lost reader** (`:65-70`): one paper and one book means no reader lands on a
  stale sibling.
- **10.f** (`:419`): stale tenant papers make claims the code no longer supports. For
  example, the qwenloop paper names Qwen 2.5 Coder as its default, but 8.d now designates
  GPT-OSS 20B.

## Scope / Required behaviour

1. Exactly **one** paper source (`docs/paper.md`) and **one** book definition
   (`properdocs.yml`) are tracked for publication.
2. Each tenant paper is either folded into `docs/paper.md` (as a section or appendix,
   updated to current canon), or removed with its content preserved in history and
   pointed to from the root paper's references. The choice is the operator's.
3. Tenant `properdocs.yml` files are removed, or proven unused and marked as such. If
   tenant documentation should be in the book, it joins the root nav instead.
4. ADR-0032 is amended to record the single-source decision.
5. A meta test prevents regression: only one `docs/paper.md` and one publishing
   `properdocs.yml` are tracked.
6. "Fully comprehensive" and the entire-dev-cycle evidence move to **#301**.
