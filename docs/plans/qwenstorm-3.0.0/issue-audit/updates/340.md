Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
Sub-doctrine 8.b (`src/vibey_tools/gh/docs/doctrines.md:138-139`) makes self-hosted Forgejo
the default forge, with GitHub and GitLab declared-only; `[platform] kind` defaults to
`forgejo` (`vibey_gh/config.py:288`). `vibey_gh/promote.py` opens, reads, rewrites, waits on
and merges the promotion pull request through two private `gh` runners: the module-level
`_gh` (`promote.py:78-80`, used at 85-99, 111-127, 132, 139-142) and
`PromotionPullRequest._gh` (386-389, used by `read` 317-329 and `write` 331-354). On the
sovereign default it would still drive GitHub.

Promotion is live release machinery: `promote-to-main.yml` runs `vibey-gh promote` from the
repository root to rebase-merge `develop` into `main` (CLAUDE.md, ADR-0028), and a push to
`main` publishes `vibey` to PyPI. Once this lane merges, promotion follows `[platform]`, so
this repository must already declare GitHub (see **Depends on**).

When a paid forge is declared, 8.b says it "relays through the sovereign host rather than
replacing it" (`doctrines.md:179-184`). That relay belongs behind `ForgeAdapterInterface`;
this lane keeps every forge call on the interface so it can be added without touching
promotion again.

## Conventions this lane relies on (everything needed is here)
**C1 — the adapter contract.** Every adapter verb answers `(value, problem)`. `problem` is
`""` exactly when the forge answered; otherwise `value` is the empty value for its type and
`problem` is one sentence. No verb raises for a failed call, a missing client, a non-2xx
status or unreadable output (`vibey_gh/interfaces/forge_adapter_interface.py:9-16`). A verb
a forge has no equivalent for answers `(<empty>, NotSupported(kind, verb, reason).problem)`,
text `f"{kind.value} does not support {verb}: {reason}"`; the caller reports it like any
other problem (10.f) and never special-cases a forge.

**C6 — how this module calls the adapter.** Every public function that reaches the forge
gains a keyword-only last parameter `forge: ForgeAdapterInterface | None = None` and resolves
with `forge = ForgeSelector().resolve(forge, cfg)`; `resolve` (#332) returns the injected
forge, else `select(cfg)`. Pass `forge=forge` down. A site that raised keeps raising; a site
that returned a value keeps returning it; a site that ignored a result keeps ignoring it.
Promotion never passed `--repo`, so nothing here binds.

**C7 — tests (amended for 9.b and the fakes standard).**
- The tenant floor is 100% line and branch coverage of `vibey_gh`
  (`src/vibey_tools/gh/pyproject.toml:64-71`). Focused runs need `--no-cov`.
- Substitute only at a declared seam: pass `forge=` (or the `PromotionPullRequest`
  constructor's `forge`). Never `monkeypatch.setattr` a module or class attribute
  (`ForgeSelector.resolve`, `subprocess.run`, a module function), never `mock.patch` or
  `MagicMock`. `monkeypatch.setenv/delenv/chdir` are fine.
- `RecordingForge` (`test/forge_doubles.py`, #332): each scripted verb returns its value (or
  calls it, if callable); `.calls` lists `(verb, *args, *sorted(kwargs.items()))`; an
  unscripted verb raises `AttributeError`.
- No test leaves the machine: every promotion test either injects `forge=` or uses
  `cfg_for` (which now declares GitHub) with the module's fake `gh` on PATH. A call without
  either would resolve Forgejo and open `https://forgejo.local/…`.

**C8 — the formatter trap.** Checked by both `black --line-length 100` + `isort` and the root
`ruff format`. Keep lines ≤ 100 columns (≤ 95 with nested calls); bind long comparisons to a
local before asserting; no implicit string concatenation that would fit on one line; one
argument per line with a trailing comma in multi-line calls; no backslash continuations.
