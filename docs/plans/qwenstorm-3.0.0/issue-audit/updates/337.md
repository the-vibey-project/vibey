This is part 0f of the forge-adapter wave. Every path below is relative to `src/vibey_tools/gh/` (package `vibey_gh`).

## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge (`docs/doctrines.md:138`, `vibey_gh/config.py:288`), and every forge call must go through `ForgeAdapterInterface` (`docs/doctrines.md:168-176`). Two places still speak raw `gh`:
- Release publication creates an immutable tag and a release through five `gh` calls (`github_release.py:22-92`).
- `install` inventories secrets with `gh secret list` (`install.py:465-487`).

The adapter's existing `create_release` cannot serve on any forge:
- GitHub (`forge_github.py:255-264`) sends through `survey`, which demands JSON, but `gh release create` prints a URL. It also uses `-t`/`-b` and has no `--target` or `--generate-notes`.
- Forgejo (`forge_forgejo.py:229-238`) sends the notes as `"note"`, a field the Forgejo API does not read.
- GitLab (`forge_gitlab.py:243-252`) sends no `ref`, so it cannot create a release for a tag that does not exist yet.

vibey-gh ADR 0001: a verb arrives with its first caller and answers `(value, problem)`. Parts 3 and 4 of the wave are the callers.

## Required behaviour
Conventions:
- Every verb answers `(value, problem)` and never raises. `problem` is `""` exactly when the forge answered.
- Forgejo is the default adapter (8.b): implement and test it first.
- Helpers already on the branch, from #332's child lanes:
  - `GitHubForge._scoped(head, tail)` adds `--repo <name>` right after the subcommand's positional argument, and only when the adapter is bound;
  - `GitHubForge._read(args)` returns `(JSON | None, problem)`;
  - `GitHubForge._run(args)` returns `(CompletedProcess | None, problem)`;
  - `GitHubForge._failed(run, label)`;
  - `repository_name()` returns `(name, problem)` on every adapter;
  - `ForgejoForge._pages` / `GitLabForge._pages(path, *, most=None)`;
  - `_absent(problem)`, which is true for the transport's 404 sentence.
- `{R}` on GitHub is `repository_name()`'s name. A problem there is returned at once, with the verb's empty value. Forgejo `{R}` = `self._repository()`, GitLab `{P}` = `self._project()`.
- Mutation bodies are `json.dumps(payload)`, sent as `self.transport.survey([path, METHOD, body], cwd=self.root)`.

Declare in `vibey_gh/interfaces/forge_adapter_interface.py`, with one-line docstrings, and implement on all three adapters:

1. `secret_names(self) -> tuple[frozenset[str], str]`
   - Forgejo: `_pages(f"repos/{R}/actions/secrets")` → the `name`s. An older Forgejo answers 404, which comes back as the transport's problem. Do not special-case it.
   - GitLab: `_pages(f"projects/{P}/variables")` → the `key`s.
   - GitHub: `_read(self._scoped(["secret", "list"], ["--json", "name"]))`.
     - problem → `(frozenset(), problem)`;
     - a list → the str `name` of every dict item;
     - anything else → ``(frozenset(), "`gh secret list` returned JSON that is not a list")``.
2. `tag_target(self, tag: str) -> tuple[str | None, str]`
   - The answer means: `(sha, "")` the tag exists, `(None, "")` the forge said it does not, `(None, problem)` the adapter could not ask.
   - Forgejo: GET `repos/{R}/git/refs/tags/{tag}`.
     - `_absent(problem)` → `(None, "")`; another problem → `(None, problem)`.
     - The answer is a list or one object. Take the entry whose `ref == f"refs/tags/{tag}"` and answer its `object.sha`. No such entry → `(None, "")`: Forgejo prefix-matches, so `v1` also returns `v10`.
   - GitLab: GET `projects/{P}/repository/tags/{quote(tag, safe='')}` → `commit.id`. `_absent` → `(None, "")`.
   - GitHub: `_run(["api", f"repos/{R}/git/ref/tags/{tag}"])`.
     - rc ≠ 0 → `(None, "")` when `"(HTTP 404)"` is in `run.stderr`, else `(None, self._failed(run, "gh api"))`;
     - stdout that is not JSON, or has no str `object.sha` → ``(None, "`gh api` returned a tag reference that could not be read")``.
3. `create_tag(self, tag: str, sha: str) -> tuple[bool, str]`
   - Forgejo: POST `repos/{R}/tags` with `{"tag_name": tag, "target": sha}`.
   - GitLab: POST `projects/{P}/repository/tags` with `{"tag_name": tag, "ref": sha}`.
   - GitHub: `_run(["api", f"repos/{R}/git/refs", "--method", "POST", "--field", f"ref=refs/tags/{tag}", "--field", f"sha={sha}"])`. rc 0 → `(True, "")`, else ``(False, (run.stderr or "").strip() or f"`gh api` exited {run.returncode}")``, which is today's suffix at `github_release.py:66-67`.
4. `release_by_tag(self, tag: str) -> tuple[ForgeRelease | None, str]`
   - Forgejo: GET `repos/{R}/releases/tags/{quote(tag, safe='')}` → `ForgeRelease(tag=tag_name, name=name, draft=bool(draft))`. `_absent` → `(None, "")`.
   - GitLab: GET `projects/{P}/releases/{quote(tag, safe='')}` → `ForgeRelease(tag=tag_name, name=name)`. `_absent` → `(None, "")`.
   - GitHub: `_run(self._scoped(["release", "view", tag], []))`.
     - rc 0 → `(ForgeRelease(tag=tag), "")`;
     - `"release not found"` in the lower-cased stderr → `(None, "")`;
     - else `(None, self._failed(run, "gh release view"))`.
5. `create_release(self, tag: str, *, target: str, title: str, generate_notes: bool) -> tuple[ForgeRelease | None, str]`
   - This **replaces** the old `create_release(tag, name, body, draft=False)` in the protocol (`interfaces/forge_adapter_interface.py:111-115`) and in all three adapters.
   - Forgejo: POST `repos/{R}/releases` with `{"tag_name": tag, "target_commitish": target, "name": title, "body": "", "draft": False, "prerelease": False}` → `ForgeRelease(tag=tag, name=title)`.
   - GitLab: POST `projects/{P}/releases` with `{"tag_name": tag, "ref": target, "name": title}` → the same record.
   - Neither Forgejo nor GitLab has a notes generator, so `generate_notes` is ignored there. The method docstrings say so.
   - GitHub: `_run(self._scoped(["release", "create", tag], ["--target", target, "--title", title]) + (["--generate-notes"] if generate_notes else []))`.
     - rc 0 → `(ForgeRelease(tag=tag, name=title), "")`;
     - else ``(None, (run.stderr or "").strip() or f"`gh release create` exited {run.returncode}")``.

**Formatter trap.** `black`+`isort` (CI tools-lint) and root `ruff format` must both be clean, and they disagree on some wraps. So:
- keep lines at or under 100 columns;
- bind a long expected value to a local before the `assert`;
- do not use implicit string concatenation;
- write multi-line calls with one argument per line and a trailing comma;
- do not use backslash continuations.
