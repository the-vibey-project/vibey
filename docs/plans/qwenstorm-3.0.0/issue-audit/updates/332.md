## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge, with GitHub and GitLab declared-only (`docs/doctrines.md:138`), and every surface speaks one vibey-owned protocol, which for the forge is `ForgeAdapterInterface` (`docs/doctrines.md:168-176`). vibey-gh ADR 0002 set `[platform] kind = "forgejo"` (`vibey_gh/config.py:288`). The two HTTP transports under the Forgejo and GitLab adapters have three defects the rest of the wave depends on:

1. **An empty 2xx body is reported as a failure.** `ForgejoTransport.survey` does `json.loads` on the body (`vibey_gh/forgejo_transport.py:67-72`). A `204 No Content` (every DELETE, many PATCHes) raises `ValueError`, and `:75-76` reports `"Forgejo transport failure: …"`. So every successful delete would read as refused. `vibey_gh/gitlab_transport.py:72-81` has the same defect.
2. **There is no timeout.** `urllib.request.urlopen(req)` (`forgejo_transport.py:67`, `gitlab_transport.py:72`) waits forever, so one hung forge hangs the command.
3. **The only test substitutes by patching an import.** `test/test_forge_adapters.py:483-519` does `monkeypatch.setattr("urllib.request.urlopen", …)` eight times. Sub-doctrine 9.b (`docs/doctrines.md:349`) says "Substitution happens at the declared seam, never by patching an import". The transports need a declared seam, an injected `opener`.

Later parts also need a record for "this forge has no equivalent for this verb" (vibey-gh ADR 0001: every verb answers `(value, problem)` and never raises). That record is `NotSupported`, added here because it is pure data.

## Required behaviour
1. `vibey_gh/forge.py` gains, after `ProtectedRef` (line 164):
   ```python
   @dataclass(frozen=True)
   class NotSupported:
       """A verb this forge has no equivalent for, and why (vibey-gh ADR 0001)."""

       kind: ForgeKind
       verb: str
       reason: str

       @property
       def problem(self) -> str:
           return f"{self.kind.value} does not support {self.verb}: {self.reason}"
   ```
   Add `"NotSupported"` to `__all__` (lines 25-37), keeping the list in alphabetical order (between `"ForgeUser"` and `"ProtectedRef"`). Example: `NotSupported(ForgeKind.GITLAB, "subject_facts", "numbers collide").problem == "gitlab does not support subject_facts: numbers collide"`.
2. `vibey_gh/interfaces/class_contracts.py` gains `NotSupportedInterface`, directly after `ProtectedRefInterface` (lines 167-170). It is `@runtime_checkable` and has read-only properties `kind -> ForgeKindInterface`, `verb -> str`, `reason -> str` and `problem -> str`, written like `ForgeRepositoryInterface` (lines 41-56). Export it from `vibey_gh/interfaces/__init__.py` in the same two places as `ProtectedRefInterface` (the import block near line 68 and `__all__` near line 202), keeping both in alphabetical order.
3. `ForgejoTransport` and `GitLabTransport` each gain two dataclass fields after `token`:
   - `timeout: float = 30.0`
   - `opener: Callable[..., Any] = field(default=urllib.request.urlopen, repr=False, compare=False)`

   `survey` calls `self.opener(req, timeout=self.timeout)` in place of `urllib.request.urlopen(req)`. With `compare=False`, two transports that differ only in `opener` still compare equal, so `test/test_platform.py:192-198` passes unmodified. Imports: `from collections.abc import Callable, Sequence` and `from dataclasses import dataclass, field`.
4. In both transports, a 2xx response whose decoded body is empty or only whitespace answers `({}, "")`. Every other path is unchanged: JSON list or object → `(value, "")`, other JSON → the existing "neither a list nor an object" problem, `HTTPError` → `"<Forge> API error <code>: <reason>"`, and `OSError`/`TimeoutError`/`ValueError` → `"<Forge> transport failure: <error>"`. Put the response text in a new local called `text`. Do not reuse `data`, which already holds the request bytes.
5. `vibey_gh/interfaces/class_contracts.py`: `ForgejoTransportInterface` and `GitLabTransportInterface` (lines 193-201) each declare `timeout -> float` as a read-only property.
6. No other module changes. The adapters, the selector and every consumer are untouched.

### 2. fix(gh): the Forgejo and GitLab adapters page every listing and read Forgejo's real field names
**Scope.**
- `ForgejoForge` / `GitLabForge` (`vibey_gh/forge_forgejo.py:26-270`, `vibey_gh/forge_gitlab.py:26-285`) gain `host: str = "forgejo.local"` / `"gitlab.com"` as the **last** dataclass field.
- `ForgeSelector._forgejo` / `_gitlab` (`vibey_gh/forge_selector.py:73-89`) pass `host=host`.
- Both adapters gain `_pages(self, path, *, most: int | None = None) -> tuple[list[dict[str, Any]], str]`, which appends `?` or `&` and then the page query.
  - Forgejo: query `page=N&limit=50`. It stops at an **empty** page, not a short one: a Forgejo instance caps `limit` at its own `[api] MAX_RESPONSE_ITEMS`, so a page shorter than 50 may not be the last.
  - GitLab: query `page=N&per_page=100`, stopping at a page shorter than 100 raw items.
  - Both stop once `most` dict items are held (answer the first `most`).
  - A non-list page → `([], f"{Forge} answered {path} with something other than a list")`.
  - More than 100 pages → `([], f"{Forge} listed more than 100 pages of {path}; the listing is incomplete")`. `{Forge}` is `Forgejo` or `GitLab`.
- Both adapters gain `_absent(self, problem: str) -> bool`: true exactly when `problem` starts with `"Forgejo API error 404"` / `"GitLab API error 404"`.
- Forgejo fixes:
  - `open_change_request_heads` reads `pull["head"]["ref"]`, not `branch` (`forge_forgejo.py:72`), through `_pages(f"repos/{R}/pulls?state=open", most=limit)`.
  - `releases` goes through `_pages(f"repos/{R}/releases", most=limit)` with `draft=bool(row.get("draft"))`, not `False` (`:85`).
  - `get_change_request` reads `number=int(val["number"])` and `head_ref=head["ref"]` (`:102-103`).
  - `get_issue` reads `number=int(val["number"])` (`:123`).
  - `get_issue_thread` reads only `repos/{R}/issues/{n}/comments`, paged. The non-existent `pulls/{n}/comments` fallback at `:136-139` goes. The author is `user.login`, falling back to `user.username`.
- GitLab fix: `open_change_request_heads` / `releases` page through `_pages(…, most=limit)`, because GitLab caps `per_page` at 100 and tidy asks for 200 heads.
- New `test/forge_doubles.py` with `RoutedTransport` (class docstring). It answers keyed by `"<path>"` for a GET and `"<path> <METHOD>"` otherwise, records every `args` tuple in `.calls`, and answers an unrouted request with `([], "no route for <key>")`.
- Tests: `test/test_forge_foundation.py` (append), plus `test/test_forge_adapters.py` updates. The Forgejo fixtures move to `{"head": {"ref": …}}` and `"number"` (lines 287, 305-306). Paged paths end `page=1&limit=50` / `page=1&per_page=100`.
- `test/test_forge_github.py` and `test/test_tidy.py` pass unmodified.

### 3. feat(gh): the forge adapter names its repository and deletes a branch
**Scope.**
- `GitHubForge` (`vibey_gh/forge_github.py:37-299`) gains:
  - `_scoped(head, tail)` = `head + (["--repo", self.repository] if self.repository else []) + tail`.
  - `_read(args, *, stdin=None) -> tuple[Any, str]`, over `self.transport.json(args, cwd=self.root, stdin=stdin)`. It maps `FileNotFoundError` → ``f"the GitHub CLI (`{self.transport.executable}`) is not installed"``, `RuntimeError` → `str(error)`, and `ValueError` → ``f"`{exe} {args[0]} {args[1]}` returned output that is not JSON"``.
  - `_run(args, *, stdin=None) -> tuple[subprocess.CompletedProcess[str] | None, str]`, over `self.transport.run(...)` with the same not-installed sentence.
  - A static `_failed(run, label, *, with_stdout=False)` = `(run.stderr or (run.stdout if with_stdout else "") or "").strip()` or ``f"`{label}` exited {run.returncode}"``.
- Declare on `ForgeAdapterInterface` (`vibey_gh/interfaces/forge_adapter_interface.py:36-123`) and implement on all three adapters:
  - `repository_name(self) -> tuple[str, str]`. GitHub: the bound `self.repository`, else a non-empty `$GH_REPO`, else `_read(["repo", "view", "--json", "nameWithOwner"])["nameWithOwner"]`. Forgejo/GitLab: `(self.repository, "")`, or `("", "no Forgejo repository is named: set [platform] repository, or give the clone an origin remote")`, with "GitLab" in the GitLab text.

Forgejo/GitLab tests use `RoutedTransport`. For "no gh installed", build `GhTransport(executable="gh-not-installed")`. Never patch a module attribute.
