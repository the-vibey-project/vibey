## Why
ADR-0044 §13–§14 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md:434`, `:449`, `:541`) extracts the run-directory machinery from `LoopProcessAdapter` into `infrastructure/engines/run_dir.py`, with no behaviour change. Draft ADR-0046 (`specs/ADR-two-loops.md`) replaces ADR-0044's one-service-per-engine design, but keeps this extraction: "The inbox and tailer are R20's extracted classes" (line 339). Its consumers are ADR-0046's **seat host**, which writes control commands into a running runner's inbox, and its caller-side **adapter** (`infrastructure/loop_service/adapter.py`, §10 line 304), which tails `events.jsonl` on the shared volume. Those lanes are not filed yet; this lane only prepares the classes they will use.

The machinery lives today in `src/vibey/infrastructure/engines/loop_process_adapter.py` (verified at integration `739536ea`):

- tailing `events.jsonl` into `EngineEvent`s: `tail`, `:418-589` (body `:425-589`), including the "process exited without a terminal status" check at `:567-580`;
- writing inbox commands: `send_prompt`, `:591-614`, and the stop file in `stop`, `:653-657`;
- waiting for and reading `stop-summary.md`: `:659-673`.

Duplicating it would break sub-doctrine 10.e (`src/vibey_tools/gh/docs/doctrines.md:417`). Sub-doctrine 9.b (`doctrines.md:349`) requires classes with an interface beside each. **The adapter's behaviour does not change.**

## Required behaviour
1. **`src/vibey/infrastructure/engines/run_dir.py`** holds three classes.
   - `class RunDirTailer`, built with `descriptor: EngineDescriptor`, with
     `async def tail(self, run_dir: Path, *, run_id: object, process_exit_code: Callable[[], int | None]) -> AsyncIterator[EngineEvent]`.
     - Its body is `LoopProcessAdapter.tail`'s body (`:425-589`) moved verbatim, with `handle.run_dir` → `run_dir` and `handle.run_id` → `run_id`.
     - The `_active_processes` check (`:567-580`) becomes `returncode = process_exit_code()`: when it is not `None`, the same one-poll grace applies (break once more than 1.0 s has passed since it was first seen), and the same `process_exited_without_terminal_status` warning is logged with `returncode=returncode`. When it is `None`, the grace timer resets, as today.
     - (The original R20 used `process_exited: Callable[[], bool]`; the callable returns the exit code instead so that the warning keeps its `returncode` field byte for byte.)
   - `class RunInbox`, built with `run_dir: Path`:
     - `write_prompt(self, text: str, *, now: bool) -> Path` does what `:593-605` does: it creates `run_dir/"inbox"` with parents, and writes `<ts>-prompt-now.json` (or `<ts>-prompt-at-break.json`) holding `{"command": "prompt-now" | "prompt-at-break", "text": text}`, where `<ts>` is `datetime.now(UTC).strftime("%Y%m%dT%H%M%S%f")`. It returns the path.
     - `write_command(self, command: str) -> Path` writes `<ts>-<command>.json` holding `{"command": command}`.
     - `write_stop(self) -> Path` is `write_command("stop")`, which is exactly what `:653-657` writes today.
   - `class StopSummaryReader`, built with `descriptor: EngineDescriptor`, with
     `async def read(self, run_dir: Path, *, wait_seconds: float = 30.0) -> tuple[str, bool]`.
     It does what `:659-673` does: it polls every 0.5 s, at most `int(wait_seconds / 0.5)` times (60 by default), until `stop-summary.md` exists and is non-empty. It returns `(text, descriptor.done_marker in text)`, or `("", False)` when the file never appears.
2. **`LoopProcessAdapter` delegates** to these classes:
   - `tail` yields from `RunDirTailer(self.descriptor).tail(handle.run_dir, run_id=handle.run_id, process_exit_code=...)`, where the callable returns `_active_processes[handle.run_id].returncode` when that process is registered, else `None`;
   - `send_prompt` calls `RunInbox(handle.run_dir).write_prompt(text, now=now)` and then logs `prompt_sent` exactly as `:609-614` does, with `file=str(path)`;
   - `stop` calls `RunInbox(handle.run_dir).write_stop()` and then `StopSummaryReader(self.descriptor).read(handle.run_dir)`. The rest of `stop` (`:675-706`) is unchanged.
   - If you keep instances on the adapter rather than building them per call, declare them with `field(init=False, compare=False, repr=False)` and set them in `__post_init__`, like `_reaper` (`:145-158`). `tests/infrastructure/process/test_call_sites.py::test_the_reaper_does_not_change_how_adapters_compare` must keep passing.
3. **Everything else stays in `loop_process_adapter.py`**, with the same names and signatures: `_active_processes`, `_diagnostic_files`, `_help_text_cache`, `isolate_python_env`, `ProcessError`, `_render_plan`, `_spawn`, `_communicate`, `_engine_environment`, and every public method. `__all__` is unchanged.
4. **Behaviour is byte-identical**: the same log event names and fields (`events_file_missing`, `event_missing_type`, `unknown_event_type`, `event_parse_failed`, `process_exited_without_terminal_status`, `tail_error`, `prompt_sent`), the same file names and JSON bodies, and the same poll intervals and bounds (100 × 0.1 s for `events.jsonl` to appear, a 0.5 s tail poll, 60 × 0.5 s for the summary).

### 2. refactor(engines): the engine process launcher, with injected spawner and executable-resolver seams
Extract `_engine_environment` (`loop_process_adapter.py:160-164`), `_spawn` (`:166-192`) and the binary resolution in `start` (`:357-359`) into `class EngineProcessLauncher(descriptor, *, env_overlay, python_env, spawner, resolver)` in `src/vibey/infrastructure/engines/process_launcher.py`, with the methods `environment()`, `async spawn(*argv, env, stdout, stderr, cwd, start_new_session)` and `resolve(argv)`. Per 9.b and D7, the launcher does **not** rely on module-attribute patching. It takes two injected seams declared in `infrastructure/engines/interfaces/process_launcher_interface.py`: `ProcessSpawnerInterface`, whose default `AsyncioProcessSpawner` calls `asyncio.create_subprocess_exec(...)` **at call time**, and `ExecutableResolverInterface`, whose default `ShutilExecutableResolver` calls `shutil.which(...)` at call time. Calling the stdlib at call time is why the unedited legacy tests that patch `module.asyncio.create_subprocess_exec` and `module.shutil.which` (`test_loop_process_adapter.py:1565-1566`, `:1607-1608`, `:1679`, `:1922`) still pass. New tests inject `FakeProcessSpawner`, `FakeProcess` and `FakeExecutableResolver` from a new `tests/fakes/process.py` instead. To avoid an import cycle (launcher → adapter → launcher), `isolate_python_env` (`:87-111`) moves into `src/vibey/infrastructure/process/python_env.py`, whose docstring already names it. `loop_process_adapter.py` re-imports it with the explicit re-export form `from vibey.infrastructure.process.python_env import isolate_python_env as isolate_python_env`, which mypy's `--strict` no-implicit-reexport requires, so that `infrastructure/build/gate_runner.py:45` and `tests/infrastructure/process/test_python_env.py:12` keep working unedited. `LoopProcessAdapter` gains `spawner` and `resolver` fields declared `field(default_factory=..., compare=False, repr=False)`. `_spawn`, `_communicate` and `_engine_environment` stay adapter methods that delegate, because `test_loop_process_adapter.py:680` and `:696` call them. If `tests/fakes/registry.py` exists (lane `fakes-registry`), append both interfaces to `DRIVER_SEAMS` and register their fakes. If lane `fakes-process-executor` has landed a process fake, reuse it rather than writing a second one (10.e); that lane owns the `CommandExecutor` fake, which is a different seam. Tests: `tests/infrastructure/engines/test_process_launcher.py` (`test_environment_strips_the_orchestrator_venv_and_applies_the_overlay`, using `monkeypatch.setenv` only; `test_resolve_uses_the_injected_resolver_and_keeps_an_unresolved_name`; `test_spawn_merges_the_overlay_last`; `test_spawn_passes_cwd_streams_and_the_session_flag`; `test_default_spawner_runs_sys_executable`; `test_classes_satisfy_their_interfaces`), plus `tests/infrastructure/engines/test_loop_process_adapter_seams.py::test_adapter_starts_through_injected_seams`.
