# Ecosystem expansion, re-cut for 8.b: declared relays over sovereign defaults, and the interaction primitive every emitting surface shares

## Summary

The original ask (2026-08-27) was to grow the family with eight sibling repositories: jira,
social, career, opencode, aws/azure/gcp and word-of-mouth. Every one had to be
**interactive, never broadcast-only**, and free at full capability for FOSS use. Three
things have changed since:

1. **There are no sibling repositories.** The family is one tree (ADR-0021) and one
   distribution (ADR-0037). A new member is a workspace tenant, an adapter behind an
   existing port, or nothing.
2. **Sub-doctrine 8.b defines a sovereign default for most of these surfaces**, with the
   paid or hosted platform declared-only and relaying through the sovereign host.
   - ticketing → **Plane** (Jira declared)
   - cloud → **OpenStack** (AWS, Azure and GCP declared; AWS the default paid cloud)
   - messaging → **Matrix**
   - email → self-hosted **SMTP**
   - SMS → **Kannel**
   The ports and sovereign adapters for tracker, cloud target, email, SMS and messaging
   already exist.
3. **`vibey-opencode` shipped and was then repealed.** PR #314 added the `opencode`
   tenant. On 2026-09-22 the amended 8.b repealed OpenCode "as an engine of either loop;
   VS Code takes its place in both, and the runner that drove OpenCode is retired once the
   VS Code adapter carries its work."

This issue is re-cut as an umbrella for the remaining rows, each restated against 8.b, plus
the shared **interaction primitive** that makes "interactive, never broadcast" true
everywhere.

## Scope / Required behaviour

1. **The interaction primitive first.** Extract `conversation.py`'s rules into one
   family-level contract. Every emitting surface (tracker comments, Matrix, email, SMS,
   social) inherits it: opt-in, identity labelling, per-thread budget, self-exclusion,
   text-is-data, rate limits.
2. **Each remaining row is an adapter or tenant, restated:**
   - **Jira**: a declared relay adapter on `IssueTrackerPort`. Plane stays the source of
     truth (8.b).
   - **AWS / GCP**: declared relay adapters on `CloudClientPort`, with AWS as the default
     paid cloud. OpenStack stays the default (#331).
   - **social**: Matrix by default. Hosted networks (Moltbook #139, and every platform 8.b
     lists) are declared relays.
   - **word-of-mouth**: email through SMTP and SMS through Kannel by default. Postal
     outreach needs an operator decision (see open questions).
   - **career**: scope undefined (see open questions).
3. **OpenCode retirement:** specified by the QwenStorm draft ADR-0046 "Two loops"
   (`specs/ADR-two-loops.md` §8–§9). Lanes L38/L39 retire `opencodeloop` only after the
   `vscode` adapter passes live conformance, and until then OpenCode is declared-only, never
   always-on. See #290. This issue only records that the row is repealed.
4. Every new adapter ships with an in-memory fake and fixture tests (no outside service),
   plus an opt-in live test.

## Acceptance criteria

- [ ] One shared interaction contract, with an interface and an in-memory fake, used by at
      least `conversation.py` and one new surface.
- [ ] A Jira relay adapter passes the `IssueTrackerPort` contract suite and is
      declared-only. Plane remains the default.
- [ ] An AWS relay adapter passes the `CloudClientPort` contract suite and is
      declared-only. OpenStack remains the default.
- [ ] Each emitting surface proves "interactive": a reply to an inbound message is handled
      within budget, labelled, and recorded in the ledger (7.c).
- [ ] No row gains a hook that a FOSS user needs an account for (Bill of Rights IV).

## The one design principle that applies to every repo above

**Interactive, never broadcast-only.** Nothing in this family just posts. Every surface
that emits (a social post, an email, a Jira comment, a LinkedIn update) must also be able
to *respond* — to people and to bots — with rate limits, identity labelling, and per-repo
opt-in. A poster is a spam cannon; a participant is a teammate. This is the acceptance bar
for each repo, not a nice-to-have.

## Doctrine (binding on every repo in this list)

For engineers, by engineers, forever free. Each of these tools works standalone, for free,
for FOSS use, at full capability — the paid dimension (see the monetization issue) is
tailoring, hosting, and convenience, never capability withheld from the free path. A new
repo that cannot satisfy that does not join the family.

## Sequencing

Not all at once. Propose: vibey-opencode first (nearest to existing runner work), then
vibey-jira (feeds the conductor), then the outreach set once the interaction machinery
exists to share.
