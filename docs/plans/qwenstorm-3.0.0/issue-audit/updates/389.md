Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
Sub-doctrine 8.d (`src/vibey_tools/gh/docs/doctrines.md:236-269`) designates **GPT-OSS 20B on Ollama**
(`gpt-oss:20b`) as this era's default free model. It was measured on 2026-09-22 on an M5 with 24 GB:
86 s for a ten-turn agent session at a 131,072-token context in 13.1 GB, against 215 s at 32,768
tokens for Qwen2.5-Coder-14B on llama.cpp. #387 (integrated at `ddf2bf05`) moved vibey's and
qwenloop's defaults. vibey-gh still defaults to the old model in four places:
- the sovereign review fallback's dataclass default, `src/vibey_tools/gh/vibey_gh/config.py:502`
  (`PrAutomationFallbackConfig.model`);
- its loader default, `config.py:1754` (`fallback.get("model", "qwen2.5-coder:14b")`);
- `vibey-gh fit --model`, `src/vibey_tools/gh/vibey_gh/cli.py:1615`;
- the tenant's own config, `src/vibey_tools/gh/.vibey-gh.toml:56` (`model = "qwen2.5-coder:14b"`).

The model is also rendered into the managed workflows. `install()`
(`src/vibey_tools/gh/vibey_gh/install.py:529`, rendering at `:260`) replaces
`__VIBEY_GH_FALLBACK_MODEL__` in `vibey_gh/templates/workflows/pr-review.yml:345`, `:363`, `:1399` and
`issue-automation.yml:610`. The rendered copies therefore carry the old literal:
- the repository root's `.github/workflows/pr-review.yml:345`, `:363` and `:1408`, rendered from the
  root `.vibey-gh.toml`, which sets no model and so takes the default;
- the tenant's `src/vibey_tools/gh/.github/workflows/pr-review.yml:345`, `:363`, `:1399` and
  `issue-automation.yml:611`.

`installed()` (`install.py:620`) reports a stale rendered file as drift. The `tools-lint` CI job
checks that. So changing the default without re-rendering fails the drift check.

## Required behaviour
1. The three code defaults (`config.py:502`, `config.py:1754`, `cli.py:1615`) and the tenant config
   (`.vibey-gh.toml:56`) are `gpt-oss:20b`.
2. The managed automation is re-rendered in both places, so every rendered workflow names
   `gpt-oss:20b`. Run these commands from the repository root:
   ```bash
   uv run python -c "from vibey_gh.config import load_config; from vibey_gh.install import install; install(load_config(), hooks_path=False)"
   (cd src/vibey_tools/gh && uv run python -c "from vibey_gh.config import load_config; from vibey_gh.install import install; install(load_config(), hooks_path=False)")
   ```
   Commit exactly the files these rewrite. `git diff --stat` should show only the workflow files
   listed in *Why*. If it shows anything else (a hook, dependabot), stop and say so in the commit
   body instead of committing it.
3. Tests that assert the **default** follow it. For example,
   `src/vibey_tools/gh/test/test_sovereign_first.py:893` (`"local model (qwen2.5-coder:14b)"`) is
   rendered from the tenant config, so it becomes `gpt-oss:20b`. Tests whose fixtures record
   **measurements** of qwen2.5-coder:14b stay unchanged: `test_fit.py`, `test_fitloop.py` and
   `test_operation_estimate.py` (33 occurrences). So do `vibey_gh/fit.py`'s measured constants
   (`fit.py:15`). They are evidence, not defaults (sub-doctrine 10.f).
4. The rendered automation installs without drift in both directories. The check is behaviour 2's
   command with `installed(load_config(), local=False)` in place of `install(...)`, printed. It must
   print `(True, [])`.
