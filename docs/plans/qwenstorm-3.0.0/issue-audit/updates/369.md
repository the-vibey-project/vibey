Closing as superseded by draft ADR-0046 (two loops). **Nothing from this issue was merged.**

`LoopServiceHost` is one long-lived process per engine consuming `vibey.runs.<engine_id>` — seven loops, which sub-doctrine 8.c as ratified by #392 (`doctrines.md:196-234`) forbids. ADR-0046 splits it into one **router** per loop, consuming `vibey.runs.<loop>` exclusively and routing through `route_store.py`, and one **seat host** per model, consuming `vibey.runs.<loop>.<seat>` exclusively so the broker itself refuses a second instance of a model (§3, §10: `router.py`, `seat_host.py`, `route_store.py`).

ADR-0046 also records two defects in this design (*Context*, lines 55–58):
- rule 3g (`specs/rabbitmq-lanes.md:2606-2611`) stops an orphaned lower attempt only when its successor is *delivered*, which cannot happen at the default prefetch 1 while the orphan holds its delivery;
- rule 3g's "active run on the same `cwd`" is checked per service instance, so two engines' services can edit one worktree.
Both are replaced by the worktree fence (§6, `worktree_lock.py`): `<cwd>/.vibey/run.lock` created with `O_EXCL`, plus `supersede.json` high-water marks, shared by both loops.

Carried over: rules 3a–3f and 3h (dead-letter a malformed message, rebind a redelivered active run, republish a persisted result, abandon a non-terminal run directory, reject past `start_by`, reject an unsafe request, persist and publish before the ack) become the seat host's "a run" row in §3's idempotency table; the queue arguments become §3's topology table; the SIGTERM drain becomes the loop's drain (§11, `strategy: Recreate`).

Evidence: `specs/ADR-two-loops.md` §3, §6, §10. ADR-0046's lanes are still to be filed.
