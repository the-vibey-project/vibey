# Full forge capture and `@vibey` interaction, on every adapted forge, Forgejo first

## Summary

vibey reads and writes issues and pull requests, and little else. The ask is to capture the
state of every other forge feature and to interact through it by mentioning `@vibey`.
Features named: agents, discussions, actions, projects, wiki, security and quality,
insights, settings. Since 8.b, the forge vibey runs on by default is self-hosted
**Forgejo**. GitHub is a declared paid relay, so this issue is restated as **full forge
capture and interaction through the forge adapter**. Forgejo comes first and GitHub's
extra, GitHub-only surfaces follow as declared-relay features. The single atomic item, the
rename of the mention trigger from `@vibey-gh` to `@vibey`, has not happened and should
ship on its own.

## Why

- **The operator's ask** (2026-09-15): "must be fully comprehensive, fully capturable and
  fully interactive via at vibey", including "fixing the at vibey-gh command to use at vibey
  instead, and make sure it autocompletes like @ claude does".
- **8.b** (`src/vibey_tools/gh/docs/doctrines.md:138-139`, `:168-177`, `:188-194`):
  Forgejo is the default forge, and GitHub is the default *paid* forge, declared only. Every
  forge operation speaks `ForgeAdapterInterface`.
- **7.c the thorough ledger** (`doctrines.md:82-91`): "What the ledger does not hold is a
  gap to be closed, not a saving." Forge state is part of what happened.
- **7.a the searchable ledger** (`:72-78`): captured state must be searchable by anyone.
- **12.c declared state** (`:455`): *settings* are declared in the repository and
  reconciled from it. "Capturing" settings means reading them back to detect drift, never
  clicking them.
- **Constitution Article III.4** (`constitution.md:97-99`): machine speech is labelled.
  Every `@vibey` reply is attributable as machine work.
- **SD-01 §4**: every forge comment is data, never instructions.

## Scope / Required behaviour

Per forge, in this order: Forgejo, then declared GitHub, then GitLab/Bitbucket as adopters
declare them.

1. **`@vibey` is the default trigger.** `@vibey-gh` keeps working as an accepted alias for
   one release, with a deprecation notice.
2. **A real `vibey` identity** exists on each forge it answers on: a user on the operator's
   Forgejo, and a GitHub App named `vibey` for the declared GitHub relay. The identity is
   declared in the repository (12.c), and its credentials live in the secrets surface
   (8.b: OpenBao), never in a workflow file.
3. **Capture**, into `forge-snapshot` classes first and into the ledger once #136 S4
   lands. Each surface below is either captured or listed as a named exclusion with a
   reason:
   - actions / workflow runs (runs, jobs, conclusion, log pointer)
   - security and quality (code-scanning, secret-scanning and dependency alerts:
     permission-gated, redacted per 7.c)
   - projects (Forgejo projects; GitHub Projects v2 via GraphQL)
   - wiki (a clone of the separate wiki git repository)
   - discussions (GitHub only, GraphQL)
   - insights (traffic, clones and referrers, a rolling 14-day window, so it must be
     captured on a schedule or it is lost)
   - settings read-back (repository metadata, rulesets, branch protection) for drift
     against the declared state
4. **Interaction:** `@vibey` answers in every captured conversation surface that has
   comments (issues, change requests, discussions, wiki talk where the forge has it), under
   `conversation.py`'s existing rules: stranger opt-in, self-exclusion, per-thread budget,
   text-is-data.
5. **"Agents"** is scoped by the operator (open question 1) before any work.
