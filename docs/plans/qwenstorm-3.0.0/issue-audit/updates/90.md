# Marketplace: a hybrid human/bot venue for work, specified first and built last

## Summary

The marketplace is a place where clients post work, the discovery bot (#87) posts work it
found, and engineers and bots take and deliver it through the conductor. It has milestone
billing (#88) and identity, roles and payments (#89). Every participant is labelled as
human or bot, interacts rather than broadcasts, and carries a track record. It is on web
and mobile, with mobile first-class for approvals, thread replies and delivery status. The
doctrine boundary is part of the ask: the marketplace is a **venue, not a toll booth**:

- FOSS work flows through it free, forever
- the family's tools never require it
- paid work pays its way

The original says to build this **last** and **specify it first**, "a design doc before any
code, with the doctrine section above copied into it verbatim as acceptance criteria". That
design doc does not exist.

Since filing, **10.b** requires every payment to be cryptocurrency, so "paid work pays the
usual way (#88)" must read "over the family's crypto rail". The web and mobile surfaces
should share **#143**'s API and clients rather than be built twice.

## Why

- **Bill of Rights IV** (full capability, free) and **V** (the Right to Leave): the tools
  never require the marketplace.
- **10.b** (`src/vibey_tools/gh/docs/doctrines.md:390-393`): crypto only.
- **4.a** (`:42-52`): machine participants' activity is never presented as human social
  proof. Labelling is mandatory.
- **Constitution III.4**: machine speech labelled. **SD-01 §1–§4**: one standard for every
  counterparty, unverified by default, and nothing presumed human. This matters for a
  venue mixing people and bots.
- **8.a / 8.b** (`:99-194`): self-hostable, sovereign defaults. A hosted marketplace would
  itself be a counterparty to its users.
- **11 the living roadmap** (`:421-426`): a project this size needs its own roadmap before
  code.
