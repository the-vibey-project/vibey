Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

This is **child lane 1 of 2** of the doctor half of the original R33. The install half is not a child lane: the installer wave delivers it (see *Why*).

## Why
Once #381 flips the defaults, two failures are silent without this check:

- a laptop with no broker fails with R17's `QueueBackendNotConfigured` (#364);
- a worker whose runs sit on a queue that nobody consumes looks healthy.

`vibey doctor` (`src/vibey/cli/main.py:1185-1391`) checks only PostgreSQL (the line printed at `:1341`) and the engines.

**The install half is gone from this issue.** The draft installer ADR (`specs/ADR-installer.md:257-260`) asks that #380 "drop `RabbitMqLocalService` and its `install --rabbitmq` half, since the catalogue serves RabbitMQ on both default OSes; keep its doctor checks, broker reachability and loop services". RabbitMQ is catalogue data on Arch Linux (pacman `rabbitmq`, `rabbitmq.service`) and on macOS (Homebrew formula and `brew services`). Lane `installer-broker-cache` declares it, and lane `installer-cli` owns `vibey install --rabbitmq`. The original plan covered brew, apt and dnf only, with no Arch path. That fails sub-doctrine 8.h (`src/vibey_tools/gh/docs/doctrines.md:326-333`), and it copied `PostgresLocalService` (`src/vibey/infrastructure/postgres.py:134-397`), which the installer wave replaces (10.e, `doctrines.md:417`).

**The doctor half follows ADR-0046** (`specs/ADR-two-loops.md`), not ADR-0044's service per engine:

- there are exactly two loops (8.c, `doctrines.md:196-234`);
- each loop has one **router** consuming `vibey.runs.<loop>` and one **seat host** per model consuming `vibey.runs.<loop>.<seat>`, both exclusively (§3);
- probes go to `vibey.runs.<loop>.probe` and are answered by the loop, from its last real result when the model is not resident (§4, lines 216–220);
- on a machine, sovereignloop consumes **only the resident seat** (§4, line 207), so an idle non-resident sovereign seat is normal, not a fault. paidloop has no residency, so each of its declared seats must have its host.

Sub-doctrine 8.g (`doctrines.md:316-324`) asks that every queue report its depth, so the doctor prints it.

This child builds the check as an infrastructure class, tested in memory. Child 2 wires it into `vibey doctor`.

## Required behaviour
1. **Value types**, in `src/vibey/infrastructure/loop_service/doctor.py`:
   - `@dataclass(frozen=True, slots=True) class LoopCheck` with `loop_id: str`, `seats: tuple[str, ...]` (declared names: model names for sovereignloop, engine ids for paidloop) and `residency: bool` (True for sovereignloop);
   - `@dataclass(frozen=True, slots=True) class LoopDoctorReport` with `lines: tuple[str, ...]` and `ok: bool`.
2. **`class LoopDoctor`**, built with keyword arguments:
   - `amqp: AmqpClientInterface`, the family client from `vibey_bootstrap.amqp` (R04, #351);
   - `redacted_url: str`, from R04's `AmqpSettings.redacted_url()`;
   - `queues`, ADR-0046's loop queue names (intake `vibey.runs.<loop>`, seat `vibey.runs.<loop>.<slug>`), taken from its run-protocol lane;
   - `client`, ADR-0046's loop client (`infrastructure/loop_service/client.py`), for `probe`;
   - `loops: Sequence[LoopCheck]`;
   - `probe_cwd: str`, the `[loop_services] root`;
   - `probe_timeout: timedelta = timedelta(seconds=10)`.

   `async def check(self) -> LoopDoctorReport` produces these lines, in this order:
   - **Broker.** On connect, `broker: ok <redacted_url>`. On failure, `broker: unreachable (<error>)`; then `ok` is False and **no further line** is produced.
   - **Router**, per loop. Probe `("--version",)`:
     - an answer gives `loop <loop>: router answering (<first stdout line, stripped, at most 80 characters>)`. If the reply says it was answered from cache (ADR-0046 §4), append ` (cached <time>)`;
     - no answer within `probe_timeout` gives `loop <loop>: no router answered within <n>s; start one with vibey loop-service --loop <loop>`, and `ok` is False.
   - **Seats**, per seat of that loop. The slug comes from ADR-0046's `SeatSlug` (`domain/residency.py`, §3 "Seat names"). The depth and consumer count come from a passive declare of the seat queue. The line is `seat <loop>.<slug>: <depth> waiting, <consumers> consumer(s)`, with one suffix:
     - ` (not declared yet)` when the queue does not exist; it counts as 0 waiting and 0 consumers;
     - ` (not resident)` when `residency` is True and the count is 0.
   - **Failures**, each its own line, and each makes `ok` False:
     - `seat <loop>.<slug>: <c> consumers; sub-doctrine 8.c allows a single instance per model`, when any seat has more than 1 consumer;
     - `loop <loop>: no seat host consumes; start one with vibey loop-service --loop <loop>`, when a `residency` loop has no seat with a consumer;
     - `seat <loop>.<slug>: no seat host; start one with vibey loop-service --loop <loop>`, when a loop without `residency` has a seat with 0 consumers.
3. The doctor only reads. It never publishes a run, and never declares a queue except passively.
4. `LoopCheck`, `LoopDoctorReport` and `LoopDoctor` satisfy their interfaces in `src/vibey/infrastructure/loop_service/interfaces/doctor_interface.py`.

## Proposed child lanes

### 1. feat(loop-service): a loop doctor that checks the broker, each loop's router and each model's seat (this issue)
The spec above: `LoopDoctor`, `LoopCheck` and `LoopDoctorReport`, with their interface and in-memory tests. Infrastructure only. Depends on R04 (#351), ADR-0046's run-protocol, client and L21 lanes, and ADR-0045's T21.

### 2. feat(cli): vibey doctor reports the broker and both loops when the queue or the engines use the bus
Add `bootstrap.build_loop_doctor(config, environ) -> LoopDoctorInterface`. It resolves:
- the AMQP URL through R17's `QueueBackendSettings.from_sources` (#364);
- sovereignloop with its declared models, defaulting to the 8.d model `gpt-oss:20b`;
- paidloop only when a paid engine id is in `[engines].enabled` (8.b: declared-only);
- the probe root from `[loop_services] root`.

`vibey doctor` (local mode only) takes `ctx: typer.Context`. When the resolved queue backend is `rabbitmq`, or the resolved invocation is `service` (`VIBEY_ENGINE_INVOCATION`, then `[engines] invocation`), it prints the report's lines after the PostgreSQL line (`cli/main.py:1341`) and after lane `installer-doctor`'s stack lines, and exits non-zero when `ok` is False (beside `:1345-1346`). In that mode with no URL, it prints R17's `QueueBackendNotConfigured` remedies and exits non-zero. With the defaults (`postgres` and `subprocess`), the output and exit code are unchanged, and nothing connects to a broker.

Substitution is at a declared seam, never by patching: a CLI-layer `DoctorSeams` dataclass with its interface (`loop_doctor`, `adapter_factory`, `local_stack`), passed as `CliRunner.invoke(..., obj=DoctorSeams(...))`. A bare `LocalStackFactory` in `ctx.obj` is still accepted, as lane `installer-doctor` passes it.

The engine preflight must be faked through ADR-0046's adapter-factory seam (`LocalEngineSettings.adapter(..., factory=...)`, the carried-over R28 behaviour 2). Today's doctor tests patch `LoopProcessAdapter.preflight` (`tests/cli/test_operational_commands.py:939-947`), and new tests must not.
