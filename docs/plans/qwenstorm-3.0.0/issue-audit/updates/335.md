## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge (`docs/doctrines.md:138`, `vibey_gh/config.py:288`), and every forge call must go through `ForgeAdapterInterface` (`docs/doctrines.md:168-176`). The merge train and promotion create, edit and merge pull requests with raw `gh`:
- `promote.py:103-127` (`pr create`);
- `pr_automation.py:712-733` (`pr create`);
- `promote.py:331-353` (`pr edit`, with a REST fallback for Projects-classic refusals);
- `merge_train.py:378-388` and `promote.py:136-142` (`pr merge`, then `--admin`).

The adapter's existing `update_change_request` and `merge_change_request` cannot stand in:
- GitHub sends them through `survey`, which demands JSON, but `gh pr edit/merge` print a URL or nothing. So each reports failure after succeeding (`forge_github.py:231-253`), and uses `-t`/`-b` where today's callers use `--title`/`--body`.
- Forgejo merge sends no `Do` field (`forge_forgejo.py:218-227`).
- GitLab merge uses POST where the API takes PUT (`forge_gitlab.py:230-241`).

Neither verb has a caller yet, so both are reshaped to what their first callers need (vibey-gh ADR 0001: a verb arrives with its first caller).

## Required behaviour
Conventions:
- Every verb answers `(value, problem)` and never raises. `problem` is `""` exactly when the forge answered.
- Forgejo is the default adapter (8.b): implement and test it first.
- A verb a forge has no equivalent for answers `(False, NotSupported(kind, verb, reason).problem)`. `NotSupported` is in `vibey_gh.forge` (from #332).
- Helpers already on the branch:
  - `GitHubForge._scoped(head, tail)` adds `--repo <name>` right after the two-word subcommand, only when bound;
  - `GitHubForge._run(args)` returns `(CompletedProcess | None, problem)`;
  - `GitHubForge._failed(run, label, *, with_stdout=False)`.
- Forgejo `{R}` = `self._repository()`, GitLab `{P}` = `self._project()`.
- Mutation bodies are always `json.dumps(payload)`, sent as `self.transport.survey([path, METHOD, body], cwd=self.root)`.

In `vibey_gh/interfaces/forge_adapter_interface.py`, add the first verb and **replace** the two old signatures (lines 96-109). Implement all three on every adapter.

1. `create_change_request(self, *, base: str, head: str, title: str, body: str) -> tuple[int | None, str]`
   - Forgejo: POST `repos/{R}/pulls` with `{"base": base, "head": head, "title": title, "body": body}`. An answer dict with an int `number` → `(number, "")`; else `(None, "Forgejo opened a pull request but did not answer its number")`.
   - GitLab: POST `projects/{P}/merge_requests` with `{"source_branch": head, "target_branch": base, "title": title, "description": body}` → `iid`, with the matching GitLab sentence.
   - GitHub: `self._run(self._scoped(["pr", "create"], ["--base", base, "--head", head, "--title", title, "--body", body]))`.
     - rc ≠ 0 → `(None, self._failed(run, "gh pr create"))`;
     - `digits = "".join(c for c in run.stdout.strip().rsplit("/", 1)[-1] if c.isdigit())`, the rule at `promote.py:126-127` → `(int(digits), "")`;
     - no digits → ``(None, "`gh pr create` printed no pull request number")``.
2. `update_change_request(self, number: int, *, title: str, body: str) -> tuple[bool, str]`
   - Forgejo: PATCH `repos/{R}/pulls/{n}` with `{"title", "body"}`. GitLab: PUT `projects/{P}/merge_requests/{n}` with `{"title", "description"}`.
   - GitHub, byte-identical to `promote.py:331-353` and `:391-396`:
     - `run` = `self._run(self._scoped(["pr", "edit", str(number)], ["--title", title, "--body", body]))`. rc 0 → `(True, "")`.
     - Else `detail = " ".join(((run.stderr or run.stdout) or "").split())[:300] or f"gh pr edit exited {run.returncode}"`.
     - If `_PROJECTS_CLASSIC` does not match `detail` → `(False, detail)`. `_PROJECTS_CLASSIC` is copied to the top of `forge_github.py` from `promote.py:52`: `re.compile(r"projects \(classic\)|projectcards", re.IGNORECASE)`. Part 2 deletes promote's copy.
     - If it matches → `self._run(["api", f"repos/{{owner}}/{{repo}}/pulls/{number}", "--method", "PATCH", "-f", f"title={title}", "-f", f"body={body}"])`. Keep the literal `{owner}/{repo}`, which are gh's own placeholders, with no scope. rc 0 → `(True, "")`.
     - Else `(False, f"{detail}; the REST fallback failed too — {detail2}")`, with `detail2` built the same way and labelled `"gh api"`.
3. `merge_change_request(self, number: int, *, method: str, commit_body: str | None = None, bypass_rules: bool = False) -> tuple[bool, str]`
   - Forgejo:
     - a `method` outside `{"squash", "rebase", "merge"}` → `(False, f"Forgejo cannot merge with method {method!r}")`;
     - else POST `repos/{R}/pulls/{n}/merge` with `{"Do": method, "force_merge": bypass_rules}`, plus `"MergeMessageField": commit_body` when it is not `None`.
   - GitLab:
     - `method == "rebase"` → `NotSupported(ForgeKind.GITLAB, "merge_change_request(method='rebase')", "GitLab sets the merge method per project, not per merge").problem`;
     - `bypass_rules` → `NotSupported(ForgeKind.GITLAB, "merge_change_request(bypass_rules=True)", "GitLab has no per-merge override of approval rules").problem`;
     - another method outside `{"squash", "merge"}` → `(False, f"GitLab cannot merge with method {method!r}")`;
     - else PUT `projects/{P}/merge_requests/{n}/merge` with `{"squash": method == "squash"}`, plus `"squash_commit_message"` (squash) or `"merge_commit_message"` (merge) = `commit_body` when given.
   - GitHub: `self._scoped(["pr", "merge", str(number)], [f"--{method}"])` + `(["--body", commit_body] if commit_body is not None else [])` + `(["--admin"] if bypass_rules else [])`. Failure → `(False, self._failed(run, "gh pr merge", with_stdout=True))`.
4. Delete the old `update_change_request(number, title=None, body=None) -> tuple[ChangeRequest | None, str]` and `merge_change_request(number, method="squash", admin=False)` bodies from all three adapters. Remove imports that become unused.

### 2. feat(gh)!: the forge adapter readies, closes, comments on and updates change requests, and names a fork's clone URL
**Scope.** Declare and implement on the three adapters. Every verb returns `tuple[bool, str]` unless stated otherwise.
- `mark_ready(number)`:
  - Forgejo: GET the pull and strip `r"^\s*(?:WIP:|\[WIP\])\s*"` (case-insensitive) from its title. If the title is unchanged and the pull is not `draft` → `(True, "")`. Else PATCH `repos/{R}/pulls/{n}` with `{"title": stripped}`.
  - GitLab: the same with `r"^\s*(?:Draft:|\[Draft\]|\(Draft\))\s*"`, and a PUT.
  - GitHub: `_scoped(["pr", "ready", str(n)], [])`.
- `close_change_request(number)`:
  - Forgejo: PATCH `{"state": "closed"}`. GitLab: PUT `{"state_event": "close"}`.
  - GitHub: `pr close N [scope]`.
- `comment_on_change_request(number, body)`:
  - Forgejo: POST `repos/{R}/issues/{n}/comments` with `{"body"}`. GitLab: POST `…/merge_requests/{n}/notes` with `{"body"}`.
  - GitHub: `pr comment N [scope] --body B`.
  - **Remove `create_comment`** from the protocol and all three adapters (`forge_*.py`, see the `create_comment` methods). It has no caller outside the adapters. Delete its assertions in `test/test_forge_adapters.py`, so that `grep -rn create_comment vibey_gh test` finds nothing.
- `update_change_request_branch(number)`:
  - Forgejo: POST `repos/{R}/pulls/{n}/update?style=merge`.
  - GitLab: `NotSupported(GITLAB, "update_change_request_branch", "GitLab can only rebase a merge request's source branch server-side, which rewrites it")`.
  - GitHub: `R` from `repository_name()`, then `_run(["api", f"repos/{R}/pulls/{n}/update-branch", "--method", "PUT"])`. Failure → `lines = (run.stderr or "").strip().splitlines()` and `(False, lines[-1] if lines else "refused")`. That is `reconcile.py:258-260`'s text, without its IndexError on whitespace-only stderr.
- `fork_clone_url(owner: str, name: str) -> tuple[str, str]`:
  - An empty owner or name → `("", "the change request names no fork repository")`.
  - Forgejo/GitLab: `f"https://{self.host}/{owner}/{name}.git"`.
  - GitHub: `f"https://github.com/{owner}/{name}.git"`, today's literal at `pr_automation.py:688`.
- Tests: `fake_gh` for every GitHub argv, bound and unbound. `RoutedTransport` for Forgejo/GitLab. New file `test/test_forge_change_request_actions.py`.
- Depends on child 1.

### 3. feat(gh): the forge adapter adds, removes and creates labels
**Scope.** Declare and implement:
- `add_label(number, label) -> tuple[bool, str]`:
  - Forgejo: POST `repos/{R}/issues/{n}/labels` with `{"labels": [label]}`.
  - GitLab: PUT on the merge request with `{"add_labels": label}`.
  - GitHub: `pr edit N [scope] --add-label L`.
- `remove_label(number, label) -> tuple[bool, str]`:
  - Forgejo: find the label's id in `_pages(f"repos/{R}/labels")`. None → `(True, "")`; else DELETE `repos/{R}/issues/{n}/labels/{id}`.
  - GitLab: PUT with `{"remove_labels": label}`.
  - GitHub: `pr edit N [scope] --remove-label L`.
- `create_label(name, *, colour: str, description: str, update_existing: bool) -> tuple[bool, str]`:
  - Forgejo: look the name up in `_pages(f"repos/{R}/labels")`.
    - Found and `update_existing` → PATCH `repos/{R}/labels/{id}` with `{"color": f"#{colour}", "description"}`.
    - Found otherwise → `(False, f"label {name!r} already exists")`.
    - Absent → POST `repos/{R}/labels` with `{"name", "color": f"#{colour}", "description"}`.
  - GitLab: POST `projects/{P}/labels`. A problem starting `"GitLab API error 409"` with `update_existing` → PUT `projects/{P}/labels/{quote(name, safe='')}` with `{"color", "description"}`.
  - GitHub: `label create NAME [scope] --color C --description D`, plus `--force` when `update_existing`.
- Tests: new file `test/test_forge_labels.py`.
- Depends on child 2. #336 depends on this child.
