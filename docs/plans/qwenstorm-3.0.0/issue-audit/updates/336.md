This is **child lane 1 of 4** of part 0e of the forge-adapter wave (issues, comments and review threads). The other three are listed at the end. Every path below is relative to `src/vibey_tools/gh/` (package `vibey_gh`).

## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge (`docs/doctrines.md:138`, `vibey_gh/config.py:288`), and every forge call must go through `ForgeAdapterInterface` (`docs/doctrines.md:168-176`). Issue automation and conversation still read issues with raw `gh`:
- `issue_automation.py:265-277` (`issue view N --repo R --json number,title,body,state,author,labels,comments,createdAt,url`);
- `issue_automation.py:402-420` (`issue list --repo R --state open --limit N --json <the same fields>`);
- `conversation.py:369-386` (`issue view N --repo R --json number,title,body,state,author,labels,comments,url`).

`issue_automation.evaluate` and `conversation` read these as dicts with `gh`'s key spellings. So this lane returns mappings with exactly those keys, which is the wave's transitional schema. It also adds the `isPullRequest` flag that `conversation.py:162-174` derives from the URL. vibey-gh ADR 0001: a verb arrives with its first caller and answers `(value, problem)`.

## Required behaviour
Conventions:
- Every verb answers `(value, problem)` and never raises.
- Forgejo is the default adapter (8.b): implement and test it first.
- Helpers already on the branch:
  - `GitHubForge._scoped(head, tail)`, which adds `--repo <name>` right after the two-word subcommand only when bound;
  - `GitHubForge._read(args)`, which returns `(decoded JSON | None, problem)`;
  - `ForgejoForge._pages` / `GitLabForge._pages(path, *, most=None)`;
  - `ForgejoFacts` / `GitLabFacts` (`vibey_gh/forge_forgejo_facts.py`, `vibey_gh/forge_gitlab_facts.py`, from #333), including their `comment(raw)` / `comment(note)` methods.
- Forgejo `{R}` = `self._repository()`, GitLab `{P}` = `self._project()`.

1. `vibey_gh/forge.py` gains, in `__all__` in alphabetical order:
   - `ISSUE_FACT_KEYS = ("number", "title", "body", "state", "author", "labels", "comments", "createdAt", "url")`
   - `SUBJECT_FACT_KEYS = ("number", "title", "body", "state", "author", "labels", "comments", "url", "isPullRequest")`

   The values: `state` is `"OPEN"` \| `"CLOSED"`, `author` is `{"login": str}`, `labels` is a list of `{"name": str}`, and `comments` is a list of the comment mappings `comment()` builds (`{"id", "url", "body", "author": {"login"}, "createdAt"}`).
2. `ForgejoFacts` gains:
   - `issue(raw, comments) -> dict[str, Any]` builds every `ISSUE_FACT_KEYS` key: `number=int(raw["number"])`, `state="OPEN"` if `raw["state"] == "open"` else `"CLOSED"`, `author={"login": user.login or user.username}`, `createdAt=created_at`, `url=html_url`, `body=body or ""`. It adds `"pull_request": raw["pull_request"]` **only** when that value is not `None`, which `issue_automation.evaluate` already skips.
   - `subject(raw, comments) -> dict[str, Any]` builds every `SUBJECT_FACT_KEYS` key, with `isPullRequest = raw.get("pull_request") is not None`.
3. `GitLabFacts` gains `issue(raw, notes) -> dict[str, Any]`: `number=iid`, `state` `opened`→`OPEN` else `CLOSED`, `body=description or ""`, `author.login=author.username`, labels as strings → `{"name": s}`, `createdAt=created_at`, `url=web_url`. Notes with `system: true` are dropped, and the rest go through `comment(note)`.
4. Both facts interfaces (`interfaces/forge_forgejo_facts_interface.py`, `interfaces/forge_gitlab_facts_interface.py`) declare the new methods with one-line docstrings.
5. Declare in `vibey_gh/interfaces/forge_adapter_interface.py`, in a new `# --- Issues ---` block, and implement on all three adapters:
   - `issue_facts(self, number: int) -> tuple[dict[str, Any] | None, str]`
     - Forgejo: GET `repos/{R}/issues/{n}` and `_pages(f"repos/{R}/issues/{n}/comments")` → `ForgejoFacts().issue(...)`.
     - GitLab: GET `projects/{P}/issues/{n}` and `_pages(f"projects/{P}/issues/{n}/notes?sort=asc")` → `GitLabFacts().issue(...)`.
     - GitHub: `_read(self._scoped(["issue", "view", str(n)], ["--json", ISSUE_FACT_FIELDS]))` with `ISSUE_FACT_FIELDS = "number,title,body,state,author,labels,comments,createdAt,url"` (the string at `issue_automation.py:275`, as a module constant at the top of `forge_github.py`). A non-dict answer → ``(None, "`gh issue view` returned JSON that is not an object")``.
     - Any read problem → `(None, problem)`.
   - `subject_facts(self, number: int) -> tuple[dict[str, Any] | None, str]`
     - Forgejo: the same two reads → `ForgejoFacts().subject(...)`.
     - GitLab: `(None, NotSupported(ForgeKind.GITLAB, "subject_facts", "GitLab numbers issues and merge requests separately, so a bare number names no single thread").problem)`, with no request.
     - GitHub: `_read(self._scoped(["issue", "view", str(n)], ["--json", "number,title,body,state,author,labels,comments,url"]))` (`conversation.py:384`), then add `isPullRequest` by the rule at `conversation.py:172-174`: `segments = [p for p in urlparse(str(url)).path.split("/") if p]`, true when `len(segments) >= 2 and segments[-2] == "pull"`. A non-dict answer → the same problem text as above.
   - `open_issues(self, *, limit: int) -> tuple[tuple[dict[str, Any], ...], str]`
     - Forgejo: `_pages(f"repos/{R}/issues?state=open&type=issues", most=limit)`, then each issue's paged comments → `issue()`.
     - GitLab: `_pages(f"projects/{P}/issues?state=opened", most=limit)`, then each issue's notes → `issue()`.
     - GitHub: `_read(self._scoped(["issue", "list"], ["--state", "open", "--limit", str(limit), "--json", ISSUE_FACT_FIELDS]))`. `None` → `((), "")`; a list → its dict items; anything else → ``((), "`gh issue list` returned JSON that is not a list")``.
     - Any read problem → `((), problem)`.
6. No consumer changes. `issue_automation` and `conversation` move in part 5.

### 3. feat(gh): the forge adapter reads one review comment
**Scope.**
- `forge.py` gains `REVIEW_COMMENT_KEYS = ("id", "body", "user", "path", "line", "original_line", "diff_hunk", "pull_request_url")`. `user` is `{"login"}`, and the last path segment of `pull_request_url` is the change-request number, which `conversation.py:213-215` checks.
- Declare and implement `review_comment(self, number: int, comment_id: str) -> tuple[dict[str, Any] | None, str]`:
  - Forgejo: `_pages(f"repos/{R}/pulls/{n}/reviews")`, then `_pages(f"repos/{R}/pulls/{n}/reviews/{review_id}/comments")` for each review until one has `str(id) == comment_id`. The match goes through the new `ForgejoFacts().review_comment(c)`, with `line=position`, `original_line=original_position`, `user.login`, `diff_hunk` and `pull_request_url`. Not found → `(None, f"review comment {comment_id} is not on #{number}")`.
  - GitLab: GET `projects/{P}/merge_requests/{n}/notes/{comment_id}` → the new `GitLabFacts().review_comment(note, f"https://{self.host}/{self.repository}/-/merge_requests/{n}")`, with `path=position.new_path`, `line=position.new_line`, `original_line=position.old_line` and `diff_hunk=""`.
  - GitHub: `R` from `repository_name()`, then `_read(["api", f"repos/{R}/pulls/comments/{comment_id}"])`. `number` is unused, because the caller checks `pull_request_url`. A non-dict answer → problem.
- The facts interfaces declare `review_comment`.
- Tests: new file `test/test_forge_review_comment.py`.
- Depends on child 2.

### 4. feat(gh): the forge adapter pages a branch's review threads
**Scope.** Declare and implement `review_thread_page(self, head_ref: str, cursor: str) -> tuple[dict[str, Any], str]`. The answer is the GraphQL envelope that `flatten.py:691-736` walks: `{"data": {"repository": {"pullRequests": {"nodes": [{"number", "reviewThreads": {"pageInfo": {"hasNextPage", "endCursor"}, "nodes": [{"isResolved", "comments": {"nodes": [{"path", "line", "originalLine", "body", "author": {"login"}}]}}]}}]}}}}`.
- GitHub:
  - `name, problem = self.repository_name()` and `owner, _, repo = name.partition("/")`.
  - Args: `["api", "graphql", "--raw-field", f"query={REVIEW_THREADS_QUERY}", "--raw-field", f"owner={owner}", "--raw-field", f"name={repo}", "--raw-field", f"branch={head_ref}"]`, plus `["--raw-field", f"after={cursor}"]` when `cursor` is set.
  - Answer through `self.transport.survey(args, cwd=self.root)`, so the problems are flatten's texts today.
  - A list answer → ``({}, "`gh api graphql` returned a JSON list where an object was expected")``.
  - `REVIEW_THREADS_QUERY` and `REVIEW_THREADS_PER_PAGE = 100` are copied verbatim from `flatten.py:131,152-169`. Part 6 deletes flatten's copy.
- Forgejo:
  - Take the open pulls with `head.ref == head_ref`, the lowest two numbers. None → `{"data": {"repository": {"pullRequests": {"nodes": []}}}}`.
  - Else read the first pull's review comments and pass them to the new `ForgejoFacts().thread_page(numbers, comments)`:
    - group comments by `(path, position or original_position)`;
    - a group is resolved when any comment has a non-null `resolver`, and its node is the earliest comment;
    - `pageInfo = {"hasNextPage": False, "endCursor": None}`;
    - a second pull becomes a sibling node with empty threads.
- GitLab:
  - Read `merge_requests?state=opened&source_branch=…` (the lowest two) and `_pages(f"projects/{P}/merge_requests/{iid}/discussions")`.
  - A resolvable discussion is a thread. It is resolved when all its resolvable notes are `resolved`.
- `cursor` is ignored on Forgejo and GitLab, which each answer one page.
- Tests: new file `test/test_forge_review_threads.py`, covering none, one and two pulls, the first page without `after=` and the second with `after=c1`.
- Depends on child 3. #337 depends on this child.
