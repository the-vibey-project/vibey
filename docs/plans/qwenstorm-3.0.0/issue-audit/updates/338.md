This is part 0g, the last adapter part of the forge-adapter wave. Every path below is relative to `src/vibey_tools/gh/` (package `vibey_gh`).

## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge (`docs/doctrines.md:138`, `vibey_gh/config.py:288`), and every forge call must go through `ForgeAdapterInterface` (`docs/doctrines.md:168-176`).

`vibey-gh rulesets` reconciles GitHub rulesets through `gh api` (`rulesets.py:179-222`). The forges express protection differently:
- Forgejo expresses branch protection as `branch_protections`, which covers only part of a ruleset.
- GitLab spreads it across protected branches and paid-tier approval and push rules.

`rulesets.reconcile_one` refuses to skip silently (`rulesets.py:225-231`). So a rule a forge cannot express must come back as a problem and never be dropped. vibey-gh ADR 0001: every verb answers `(value, problem)`.

Operator note, not lane work: the default `[rulesets]` integration policy (`config.py:1022-1024`, with `RulesetConfig` defaults at `config.py:961-975`) cannot be expressed on Forgejo. It requires linear history, requires conversation resolution, and names the bypass actor `RepositoryRole:5`. So on the default forge `vibey-gh rulesets` will refuse its own default configuration until the operator decides a mapping. This lane reports that refusal honestly. It does not change the policy.

## Required behaviour
Conventions:
- Every verb answers `(value, problem)` and never raises.
- Forgejo is the default adapter (8.b): implement and test it first.
- A verb a forge has no equivalent for answers `(<empty>, NotSupported(kind, verb, reason).problem)`. `NotSupported` is in `vibey_gh.forge`, and its problem text is `f"{kind.value} does not support {verb}: {reason}"`.
- Helpers already on the branch, from #332's child lanes:
  - `GitHubForge._read(args)` returns `(JSON | None, problem)`, and its problem text for a failed `gh` is exactly `"gh <args>: <stderr>"`;
  - `GitHubForge._run(args, *, stdin=None)` returns `(CompletedProcess | None, problem)`;
  - `repository_name()`;
  - `ForgejoForge._absent(problem)`, which is true for the transport's 404 sentence.
- GitHub `{R}` is `repository_name()`'s name. A problem there is returned at once. Forgejo `{R}` = `self._repository()`.

1. New `vibey_gh/forge_forgejo_rules.py`, class `ForgejoBranchRules`. It is pure (no I/O, no state), with the interface `ForgejoBranchRulesInterface` in `vibey_gh/interfaces/forge_forgejo_rules_interface.py`. The interface is `@runtime_checkable`, imports only the standard library, and gives each method a one-line docstring.
   - `protection(self, document: dict[str, Any]) -> tuple[dict[str, Any] | None, str]` checks the ruleset document, as `rulesets.build_ruleset` makes it (`rulesets.py:122-131`), and collects every item Forgejo cannot express, in this order:
     1. `f"target {target!r}"` when `target != "branch"`;
     2. `f"enforcement {enforcement!r}"` when `enforcement != "active"`;
     3. `"bypass_actors"` when the list is non-empty;
     4. `"conditions"` unless `conditions == {"ref_name": {"include": [f"refs/heads/{b}"], "exclude": []}}` for one branch `b`;
     5. each rule `type` outside `{"deletion", "non_fast_forward", "required_signatures", "pull_request", "required_status_checks"}` (for example `required_linear_history`, `merge_queue`), in rule order;
     6. each of the `pull_request` parameters `require_code_owner_review`, `require_last_push_approval`, `required_review_thread_resolution` that is true.

     Any item → `(None, NotSupported(ForgeKind.FORGEJO, "branch rules", f"no equivalent for {', '.join(items)}").problem)`. Otherwise answer `(payload, "")` with:
     ```python
     {"enable_push": False,
      "require_signed_commits": <a required_signatures rule is present>,
      "required_approvals": <pull_request.parameters.required_approving_review_count, else 0>,
      "dismiss_stale_approvals": <pull_request.parameters.dismiss_stale_reviews_on_push, else False>,
      "enable_status_check": bool(contexts),
      "status_check_contexts": contexts,   # [c["context"] for c in required_status_checks]
      "block_on_outdated_branch": <strict_required_status_checks_policy, else False>}
     ```
   - `branch(self, document) -> str` is `b` from item 4 above, `include[0].removeprefix("refs/heads/")`, or `""`.
   - `document(self, protection: dict[str, Any], name: str, branch: str) -> dict[str, Any]`:
     ```python
     {"id": branch, "name": name, "target": "branch", "enforcement": "active",
      "bypass_actors": [],
      "conditions": {"ref_name": {"include": [f"refs/heads/{branch}"], "exclude": []}},
      "rules": [{"type": "deletion"}, {"type": "non_fast_forward"}]
               + ([{"type": "required_signatures"}] if require_signed_commits else [])
               + [{"type": "pull_request", "parameters": {
                     "required_approving_review_count": int(required_approvals or 0),
                     "dismiss_stale_reviews_on_push": bool(dismiss_stale_approvals),
                     "require_code_owner_review": False,
                     "require_last_push_approval": False,
                     "required_review_thread_resolution": False}}]
               + ([{"type": "required_status_checks", "parameters": {
                     "required_status_checks": [{"context": c} for c in contexts],
                     "strict_required_status_checks_policy": bool(block_on_outdated_branch)}}]
                  if enable_status_check and contexts else [])}
     ```
   - Round trip: for a document `rulesets.build_ruleset(branch, policy)` makes from an expressible policy, `rulesets.diff_ruleset(doc, document(payload, doc["name"], branch)).changed is False`. Here `payload, _ = protection(doc)`.
2. Declare in `vibey_gh/interfaces/forge_adapter_interface.py`, in a new `# --- Branch rules ---` block, and implement on all three adapters:
   - `branch_rules(self, name: str, branch: str) -> tuple[dict[str, Any] | None, str]`
     - Forgejo: GET `repos/{R}/branch_protections/{quote(branch, safe='')}`.
       - `_absent(problem)` → `(None, "")`; another problem → `(None, problem)`;
       - a non-dict answer → `(None, "Forgejo answered a branch protection that is not an object")`;
       - else `(ForgejoBranchRules().document(protection, name, branch), "")`.
     - GitHub (`branch` is unused), `rulesets.py:198-209` moved in:
       - `listing, problem = self._read(["api", f"repos/{R}/rulesets"])`; problem → `(None, problem)`; `None` → `[]`;
       - take the first dict item with `item.get("name") == name`, then `document, problem = self._read(["api", f"repos/{R}/rulesets/{item['id']}"])`; problem → `(None, problem)`; a dict → `(document, "")`; else `(None, "")`;
       - no match → `(None, "")`.
   - `create_branch_rules(self, document: dict[str, Any]) -> tuple[bool, str]`
     - Forgejo: `payload, problem = ForgejoBranchRules().protection(document)`; problem → `(False, problem)`; else POST `repos/{R}/branch_protections` with `json.dumps(payload | {"rule_name": ForgejoBranchRules().branch(document)})`.
     - GitHub: `run, problem = self._run(["api", f"repos/{R}/rulesets", "--method", "POST", "--input", "-"], stdin=json.dumps(document))`. `run is None` → `(False, problem)`; rc 0 → `(True, "")`; else `(False, f"{self.transport.executable} api repos/{R}/rulesets --method POST: {(run.stderr or '').strip()}")`. That is the exact text `rulesets._api` raises today (`rulesets.py:193-194`), which omits `--input -`.
   - `update_branch_rules(self, rules_id: str, document: dict[str, Any]) -> tuple[bool, str]`
     - Forgejo: PATCH `repos/{R}/branch_protections/{quote(rules_id, safe='')}` with the payload and no `rule_name`. A `protection()` problem → `(False, problem)`.
     - GitHub: as `create_branch_rules`, with `--method PUT`, the path `repos/{R}/rulesets/{rules_id}`, and the failure text `f"{self.transport.executable} api repos/{R}/rulesets/{rules_id} --method PUT: {(run.stderr or '').strip()}"`.
   - GitLab, all three: `NotSupported(ForgeKind.GITLAB, "branch rules", "GitLab expresses protection as protected branches plus paid-tier approval and push rules, which vibey-gh does not map rulesets onto")`, answered with `None` or `False`, and with no request.
