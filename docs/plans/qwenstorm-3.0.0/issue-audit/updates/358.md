## Why
ADR-0044 §4 and §5 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`). In the RabbitMQ backend a worker takes a delivery, then claims its row with a fenced compare-and-set **by job id and generation**, which also takes over an expired lease. This replaces the `SKIP LOCKED` scan (today `src/vibey/infrastructure/db/job_repository.py:178-208`; as Core, `JobStatements.claim`, lane `orm-job-statements-settle`) for that backend. When the claim misses, the worker reads a snapshot and asks `DispatchMissPolicy` (#354, R07) what the miss means. After the relay publishes a dispatch it stamps `dispatched_at`, but only for the generation it published, so a stale relay can never mark a newer episode.

The fences stay exactly the PostgreSQL backend's (`ack`, `park`, `heartbeat`, `grant_attempts`, `assign_engine` are inherited unchanged). Persistence goes through `PostgresOrmInterface` with SQLAlchemy 2 async Core (`specs/orm-tables.md:59-63`); `specs/orm-job-statements-settle.md` provides `JOB_SQL.deps_unmet` for these RabbitMQ statements to reuse.

Verified at integration `739536ea` (line numbers above are today's; the ORM lanes move them).

   - `snapshot(job_id: UUID)`: `select(JOBS.c["state"], JOBS.c["dispatch_seq"], JOBS.c["run_after"], JOBS.c["lease_expires_at"], (~JOB_SQL.deps_unmet(JOBS)).label("deps_met")).where(JOBS.c["id"] == job_id)`.
   - `mark_dispatched(job_id: UUID, dispatch_seq: int)`: `update(JOBS).where(JOBS.c["id"] == job_id, JOBS.c["dispatch_seq"] == dispatch_seq).values(dispatched_at=func.now())`.

### 2. feat(db): nack, defer and reap start a new dispatch episode in their own transaction
Every settle that starts a new dispatch episode bumps the generation and writes an outbox row in the same `self._orm.transaction()`. Statements on `DispatchStatements`, built from the ORM wave's own (`JOB_SQL.nack(...)`, `JOB_SQL.defer(...)`, `JOB_SQL.reap()`) with `.values(...)` and `.returning(...)` added, never restated: `nack_redispatch` adds `dispatch_seq=case((JOBS.c["attempts"] >= JOBS.c["max_attempts"], JOBS.c["dispatch_seq"]), else_=JOBS.c["dispatch_seq"] + 1)`, `dispatched_at=None` and returns `id, project_id, state, dispatch_seq, kind, run_after`; a returned `ready` row gets an outbox row at `run_after`, a `failed` one none. `defer_redispatch` always bumps and writes at `retry_at`. `reap` is overridden: `parked = await self._park_exhausted(conn)` (#356, unchanged and not duplicated), then `reap_redispatch` (`JOB_SQL.reap()` plus the bump and `RETURNING` of the dispatch columns) writes one outbox row per re-readied job; it returns parked plus re-readied. The fake's `nack`, `defer` and `reap` follow. Tests (compiled, fake, PostgreSQL): `test_nack_with_attempts_left_redispatches_at_run_after`, `test_nack_at_the_last_attempt_fails_without_dispatch`, `test_defer_redispatches_at_retry_at`, `test_reap_redispatches_and_still_parks_exhausted`, `test_stale_owner_ack_after_reap_is_refused`. Files: `dispatch_statements.py`, `dispatch_records.py`, their interfaces, `tests/fakes/queue.py`, the three test files. Depends on #357, #356 and child 1 (same files).

### 3. feat(db): the lost-dispatch sweep and the dead-letter park
`sweep_lost(*, redispatch_after: timedelta, limit: int) -> int` (the caller passes `QueueRabbitMqConfig.sweep_batch`, #348) runs one transaction: select candidates with `select(<dispatch columns>).where(state == "ready", run_after <= func.now(), or_(dispatch_seq == 0, dispatched_at < func.now() - literal(redispatch_after, Interval())), ~JOB_SQL.deps_unmet(JOBS)).order_by(run_after.asc()).limit(limit).with_for_update(skip_locked=True)`; a sequence-0 row moves to 1 and is written with the plain key; a row at ≥ 1 is written again at the **same** generation with `key_suffix=f":sweep:{int(epoch)}"`, `epoch` read once from `select(func.extract("epoch", func.now()))` (a harmless duplicate that keeps its FIFO position); every swept row gets `dispatched_at = func.now()`; a row with `dispatched_at IS NULL` at ≥ 1 (its outbox row is still pending) is never selected. `park_dead_letter(dispatch, *, delivery_limit) -> bool` runs one transaction: the fenced update (`id`, `dispatch_seq`, and `state = 'ready'` or an expired `leased`) to `awaiting_human` with the lease cleared and one attempt refunded, `RETURNING project_id, kind`; no row returns `False`; otherwise insert a `delivery_exhausted` gate with the prompt `f"job {kind!r} was delivered {delivery_limit} times and every consumer holding it died. Answer anything to retry it with a fresh delivery budget."`, run `JOB_SQL.notify_gate_raised(gate_id)` (#356), and return `True`. The fake follows (epoch from `store.clock`). Tests: `test_sweep_dispatches_the_seq_zero_race`, `test_sweep_duplicates_an_old_dispatch_at_the_same_generation`, `test_sweep_skips_a_pending_outbox_row`, `test_sweep_throttles_itself`, `test_park_dead_letter_parks_only_a_claimable_row`, plus compiled-statement tests (`FOR UPDATE SKIP LOCKED`, the generation fence). Depends on #357, #356 and child 1 (same files).
