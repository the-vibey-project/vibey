Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §1 and §13 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md:118-155`, `:370-477`) make RabbitMQ dispatch and loop services the defaults. Draft ADR-0046 (`specs/ADR-two-loops.md`) changes what "the loop service" is: two loops, each with a router and one seat host per model. It keeps the flip as a separate, final step:

- "service mode becomes the default when R34 flips it" (§2, line 138);
- "Every lane lands behind today's defaults (`invocation = subprocess`)" (non-negotiable 8, line 350).

This lane changes **only defaults**, so reverting it restores today's behaviour completely. That is CDD's bounded divergence (sub-doctrine 9.c, `src/vibey_tools/gh/docs/doctrines.md:351`).

Before the flip, all of this evidence must have landed and be green:

- the contract suite on both backends, and the chaos twin (#365, R18);
- ADR-0046's worktree-fence tests (§6) and the seat host's dedupe tests (§3, idempotency table). They replace the supersede and dedupe tests of the superseded #369;
- the cluster contracts for the broker, the two loops and the RabbitMQ `ScaledObject` (#379);
- a one-command local broker on Arch Linux and macOS (8.h): `vibey install` from lanes `installer-broker-cache` and `installer-cli`, with `--rabbitmq` narrowing it to the broker;
- the doctor's broker and loop checks (#380 and its child 2);
- the canon for two loops, now ratified. 8.c in `doctrines.md:196-234` was ratified by #392, which satisfies ADR-0046's *Owes* item 1.

Two other defaults flip in their own lanes, not here:

- ADR-0047's S33 flips the surface transport to `queue`;
- ADR-0045's T28 flips test-harness routing.

   - R01's `test_queue_defaults_to_postgres_and_subprocess` is renamed to `test_queue_defaults_to_rabbitmq_and_service` and asserts the new defaults.
   - That is the only edit to an existing assertion.
2. **The historical suite stays on its backends.** `tests/conftest.py`'s `pytest_configure` (`:146-156` today; after `fakes-harness-decouple` it no longer connects to anything) gains:
   ```python
   os.environ.setdefault("VIBEY_QUEUE_BACKEND", "postgres")
   os.environ.setdefault("VIBEY_ENGINE_INVOCATION", "subprocess")
   ```
   Add a comment saying three things:
   - the historical suite was written for these;
   - the contract suite (#365) proves both backends;
   - `setdefault` lets CI or a developer run the suite on another backend.

   The environment is a declared seam, so this is not patching. Leave any other pins in `pytest_configure` as they are (for example `VIBEY_SURFACES_TRANSPORT` from S33).
3. **A third remedy.** The message of `QueueBackendNotConfigured` (R17, `src/vibey/infrastructure/queue/selection.py`) adds `vibey install`, which installs the local stack including RabbitMQ; `vibey install --rabbitmq` installs the broker alone. This is in addition to the two remedies it already has.

5. **CI.** The step "Contract - the ScaledObject reconciles against real Postgres" (`.github/workflows/ci.yml:973-991`) adds `--set queue.backend=postgres` to its `helm upgrade` (`:977-978`), so that it keeps testing the PostgreSQL trigger.

The worker's `VIBEY_QUEUE_BACKEND`, `VIBEY_ENGINE_INVOCATION` and `wait-for-rabbitmq` change in every profile that renders the worker. `keda-latest` and `keda-project` stay byte-identical, because #378 pinned them to `postgres`. `keda-rabbitmq` stays unchanged as well.
7. **The commit** carries a `BREAKING CHANGE:` footer saying:
   - vibey now needs a RabbitMQ broker by default (`VIBEY_BUS_AMQP_URL`), and `vibey install` installs one on Arch Linux and macOS;
   - engine runs go through the two loops, so `vibey loop-service --loop sovereignloop` must be running (and `--loop paidloop` when a paid adapter is declared);
   - `VIBEY_QUEUE_BACKEND=postgres` with `VIBEY_ENGINE_INVOCATION=subprocess` restores the one-daemon behaviour;
   - in the chart, `keda.enabled` now needs `worker.project` unless `queue.backend=postgres`.
