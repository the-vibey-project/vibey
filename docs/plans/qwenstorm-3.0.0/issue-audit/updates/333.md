Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

This is **child lane 1 of 3** of part 0b of the forge-adapter wave (change-request reads). The other two are listed at the end. Every path below is relative to `src/vibey_tools/gh/` (package `vibey_gh`).

## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge (`docs/doctrines.md:138`), and vibey-gh ADR 0002 set `[platform] kind = "forgejo"` (`vibey_gh/config.py:288`). The merge train decides on a change request's full state with `merge_train.judge(pr, cfg)` (`vibey_gh/merge_train.py:124-246`), and PR automation does the same with `pr_automation.evaluate`. Both read a dict whose keys are `gh pr view --json` field names (`merge_train.py:237-246`, `pr_automation.py:480-482`). Their tests (thousands of lines) build those dicts.

For the default forge to reach these decisions, a Forgejo pull request (and a GitLab merge request) must be translated into a mapping with those keys and values. This lane adds that translation as two pure classes, which is the first step before the adapter verbs (child lanes 2 and 3) use it.

Keeping GitHub's key spellings is a deliberate, transitional deviation from 8.b's "the protocol is vibey's" (`docs/doctrines.md:168-176`). It is recorded in the wave's appendix for the operator, and converting the decision functions to neutral records is a later follow-up, not this lane.

## Required behaviour
1. `vibey_gh/forge.py` gains two tuple constants, both added to `__all__` in alphabetical order:
   - `CHANGE_REQUEST_FACT_KEYS = ("number", "title", "body", "state", "isDraft", "mergeable", "mergeStateStatus", "reviewDecision", "statusCheckRollup", "author", "labels", "headRefOid", "headRefName", "baseRefName", "isCrossRepository", "changedFiles")`
   - `THREADED_CHANGE_REQUEST_FACT_KEYS`: the same keys without `"changedFiles"`, followed by `"comments", "headRepository", "headRepositoryOwner"`.
2. The value schema, which every translator below produces:

   | key | value |
   |---|---|
   | `number` | int |
   | `title`, `body` | str |
   | `state` | `"OPEN"` \| `"CLOSED"` \| `"MERGED"` |
   | `isDraft` | bool |
   | `mergeable` | `"MERGEABLE"` \| `"CONFLICTING"` \| `"UNKNOWN"` |
   | `mergeStateStatus` | `"BEHIND"` or `"UNKNOWN"` |
   | `reviewDecision` | `"APPROVED"` \| `"CHANGES_REQUESTED"` \| `""` |
   | `statusCheckRollup` | list of `{"name", "status": "COMPLETED"\|"IN_PROGRESS", "conclusion": "SUCCESS"\|"FAILURE"\|"NEUTRAL"\|"SKIPPED"\|"CANCELLED"\|None, "startedAt", "completedAt", "detailsUrl"}` |
   | `author` | `{"login": str}` |
   | `labels` | list of `{"name": str}` |
   | `headRefOid`, `headRefName`, `baseRefName` | str |
   | `isCrossRepository` | bool |
   | `changedFiles` | int. **Omit the key** when the forge gives no count: the protected-paths guard then refuses rather than guesses. |
   | `comments` (threaded only) | list of `{"id": str, "url": str, "body": str, "author": {"login": str}, "createdAt": str}`. GitLab adds `"noteable_type"` and `"noteable_iid"`. |
   | `headRepository` / `headRepositoryOwner` (threaded only) | `{"name": str}` / `{"login": str}`, with empty strings when unknown |
3. New `vibey_gh/forge_forgejo_facts.py`, class `ForgejoFacts`. It is pure: no I/O and no state, a class for 9.b. Its inputs are the Forgejo REST objects.
   - `state(raw) -> str`: `"MERGED"` if `raw.get("merged")`, else `"OPEN"` if `raw.get("state") == "open"`, else `"CLOSED"`.
   - `draft(pull) -> bool`: `pull["draft"]` when it is a bool. Otherwise true when the title, after leading whitespace and case-insensitively, starts with `WIP:` or `[WIP]`.
   - `check_name(context) -> str`: strips one trailing ` (<event>)` matching `r" \([a-z_]+\)$"`. Forgejo Actions appends the event, so `"PR evaluate / gate (pull_request)"` becomes `"PR evaluate / gate"`.
   - `rollup_entry(status) -> dict[str, Any]`:
     - `name` = `check_name(status["context"])`;
     - `status` = `"IN_PROGRESS"` if `state == "pending"`, else `"COMPLETED"`;
     - `conclusion` from `{"success": "SUCCESS", "failure": "FAILURE", "error": "FAILURE", "warning": "NEUTRAL"}`, else `None`;
     - `startedAt` = `created_at`, `completedAt` = `updated_at`, `detailsUrl` = `target_url`. Each is the empty string when missing.
   - `check_result(status, sha) -> CheckResult`: `CheckResult(check_name(context), sha, {"success": "success", "failure": "failure", "error": "failure", "warning": "neutral"}.get(state, ""))`.
   - `review_decision(reviews) -> str`: among reviews with `dismissed` not true and `state` in `{"APPROVED", "REQUEST_CHANGES"}`, take the latest one per `user.login`, in list order. Any latest `REQUEST_CHANGES` → `"CHANGES_REQUESTED"`, else any `APPROVED` → `"APPROVED"`, else `""`. A later `COMMENT` review does not cancel an approval.
   - `comment(raw) -> dict[str, Any]`: `{"id": str(raw["id"]), "url": html_url or "", "body": body or "", "author": {"login": user.login or user.username or ""}, "createdAt": created_at or ""}`.
   - `change_request(pull, statuses, reviews) -> dict[str, Any]`: every key of `CHANGE_REQUEST_FACT_KEYS`:
     - `mergeable`: `True` → `"MERGEABLE"`, `False` → `"CONFLICTING"`, missing → `"UNKNOWN"`;
     - `mergeStateStatus` = `"UNKNOWN"` (Forgejo cannot say "behind");
     - `isCrossRepository` = `head.repo_id != base.repo_id` when both are ints, else `False`;
     - `changedFiles` only when `pull["changed_files"]` is an int;
     - `headRefOid` / `headRefName` / `baseRefName` from `head.sha` / `head.ref` / `base.ref`;
     - `author` from `user`.
   - `threaded(pull, statuses, reviews, comments) -> dict[str, Any]`: the threaded key set. `headRepository = {"name": head.repo.name}`, `headRepositoryOwner = {"login": head.repo.owner.login}`, with empty strings when absent.
4. New `vibey_gh/forge_gitlab_facts.py`, class `GitLabFacts`, with the same method names, over GitLab REST objects:
   - `state`: `"opened"` → `"OPEN"`, `"merged"` → `"MERGED"`, else `"CLOSED"`.
   - `draft` = `bool(mr.get("draft") or mr.get("work_in_progress"))`.
   - `mergeable` = `"CONFLICTING"` if `has_conflicts`, else `"MERGEABLE"`.
   - `mergeStateStatus` = `"BEHIND"` when `detailed_merge_status == "need_rebase"`, else `"UNKNOWN"`.
   - `review_decision(approvals)` = `"APPROVED"` if `approvals.get("approved")`, else `""`.
   - Rollup from commit statuses:
     - `success` → COMPLETED/SUCCESS, `failed` → COMPLETED/FAILURE, `canceled` → COMPLETED/CANCELLED, `skipped` → COMPLETED/SKIPPED;
     - anything else → IN_PROGRESS/`None`;
     - `name` = `status["name"]`, `startedAt` = `started_at or created_at`, `completedAt` = `finished_at`, `detailsUrl` = `target_url`, each `""` when missing.
   - `check_result(status, sha)` maps `success` → `"success"`, `failed` → `"failure"`, `canceled` → `"cancelled"`, `skipped` → `"skipped"`, else `""`.
   - `author.login` = `author.username`. `labels` are strings on GitLab, so each becomes `{"name": s}`.
   - `headRefOid` = `sha`, `headRefName` = `source_branch`, `baseRefName` = `target_branch`, `isCrossRepository` = `source_project_id != target_project_id`, `body` = `description or ""`, `number` = `iid`.
   - `changedFiles` = `int(changes_count)` only when `changes_count` is a string of digits (GitLab may send `"1000+"`).
   - `comment(note)`: `{"id": str(id), "url": "", "body", "author": {"login": author.username}, "createdAt": created_at, "noteable_type", "noteable_iid"}`. GitLab notes carry no web URL.
   - `change_request(mr, statuses, approvals)` and `threaded(mr, statuses, approvals, notes, source_project)`. Notes with `system: true` are dropped. `headRepository = {"name": source_project.get("path", "")}` and `headRepositoryOwner = {"login": source_project.get("namespace", {}).get("full_path", "")}`. Pass `source_project={}` when the merge request is not cross-repository.
5. Interfaces (ADR-0016 / 9.b): `vibey_gh/interfaces/forge_forgejo_facts_interface.py` (`ForgejoFactsInterface`) and `vibey_gh/interfaces/forge_gitlab_facts_interface.py` (`GitLabFactsInterface`), each a `@runtime_checkable` `Protocol` declaring every public method with a one-line docstring. ### 2. feat(gh): the forge adapter reads a change request's facts, thread and check results
**Scope.** Declare on `interfaces/forge_adapter_interface.py` and implement on the three adapters:
- `change_request_facts(self, number: int) -> tuple[dict[str, Any] | None, str]`.
  - Forgejo: GET `repos/{R}/pulls/{n}`, then `_pages(f"repos/{R}/commits/{sha}/statuses")` and `_pages(f"repos/{R}/pulls/{n}/reviews")`, then `ForgejoFacts().change_request(...)`.
  - GitLab: GET `projects/{P}/merge_requests/{n}`, `_pages(f"projects/{P}/repository/commits/{sha}/statuses")` and GET `…/merge_requests/{n}/approvals`, then `GitLabFacts().change_request(...)`.
  - GitHub: `_read(self._scoped(["pr", "view", str(n)], ["--json", CHANGE_REQUEST_FACT_FIELDS]))`. `CHANGE_REQUEST_FACT_FIELDS` is the joined string of `merge_train.py:237-246` with no spaces. A non-dict answer → ``(None, "`gh pr view` returned JSON that is not an object")``.
- `change_request_with_thread(self, number: int) -> tuple[dict[str, Any] | None, str]`.
  - Forgejo: plus paged `repos/{R}/issues/{n}/comments`.
  - GitLab: plus paged `…/merge_requests/{n}/notes?sort=asc`, and GET `projects/{source_project_id}` only when the project ids differ.
  - GitHub: `THREADED_CHANGE_REQUEST_FIELDS` = `pr_automation.py:480-482` joined.
- `get_check_results(self, head_sha: str) -> tuple[tuple[CheckResult, ...], str]`, reshaped from `tuple[Any, ...]`.
  - Forgejo: paged statuses, then `check_result`.
  - GitLab: the corrected route `projects/{P}/repository/commits/{sha}/statuses`, not `forge_gitlab.py:185`'s `commits/…`.
  - GitHub: the unchanged argv `api repos/{R}/commits/{sha}/check-runs` via `_read`. The conclusion only counts when `status == "completed"`, and the two existing shape problems are kept.
- Move the GitHub `get_check_results` assertions at `test/test_forge_adapters.py:117-125` to `fake_gh`, because `ScriptedTransport` has no `json()`. Update the Forgejo and GitLab ones to `CheckResult`.
- New test file `test/test_forge_change_request_reads.py`, including `test_every_read_passes_a_problem_through_with_nothing_read` (parametrised forge × verb).

### 3. feat(gh): the forge adapter reads a change request's text, comment bodies and changed paths
**Scope.** Declare and implement:
- `change_request_text(self, number: int) -> tuple[tuple[str, str] | None, str]`.
  - Forgejo: `(title, body)` of the pull. GitLab: `(title, description)`.
  - GitHub, byte-identical to `promote.py:317-329, 391-396`: `_run(self._scoped(["pr", "view", str(n)], ["--json", "title,body"]))`.
    - rc ≠ 0 → `(None, " ".join((run.stderr or run.stdout or "").split())[:300] or f"gh pr view exited {rc}")`;
    - not a JSON object → `(None, f"gh pr view {n} did not return a title and body")`.
- `change_request_comment_bodies(self, number: int) -> tuple[tuple[str, ...], str]`.
  - Forgejo: the bodies of paged `repos/{R}/issues/{n}/comments`. GitLab: the bodies of non-system notes.
  - GitHub: `_run(self._scoped(["pr", "view", str(n)], ["--json", "comments", "-q", ".comments[].body"]))`.
    - rc 0 → `(((run.stdout or "") + (run.stderr or ""),), "")`;
    - else `((), _failed(run, "gh pr view"))`.
- `changed_paths(self, number: int) -> tuple[tuple[tuple[str, ...], int] | None, str]`.
  - Forgejo: paged `repos/{R}/pulls/{n}/files` → `filename`, plus a non-empty `previous_filename`. `listed = len(entries)`.
  - GitLab: paged `…/merge_requests/{n}/diffs` → `new_path`, plus `old_path` when `renamed_file` and it differs.
  - GitHub: `_run(["api", "--paginate", f"repos/{{owner}}/{{repo}}/pulls/{n}/files?per_page=100"])`, with literal gh placeholders and no scope, parsed by `ProtectedPathsGuard().parse_listing(run.stdout)`.
    - `TypeError`/`ValueError` → ``(None, f"`gh api` returned a file listing that could not be read: {error}")``.
