Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §1 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`): `[queue] backend` chooses the backend in `bootstrap.py`, the one composition root, and nowhere else. Selecting `rabbitmq` without an AMQP URL fails loudly, naming the fix. There is no silent fallback, for the same reason ADR-0002 gives for `DatabaseNotConfigured` (`src/vibey/bootstrap.py:641-662`).

The worker learns its parallelism only after `build_app` has run (`count`, `src/vibey/cli/main.py:1697`), so the prefetch is set then. The drain must also return buffered deliveries on SIGTERM (ADR-0025, ADR-0026), in the worker's existing `finally` (`:1754-1758`, which #349 changed to close the wakeup).

The PostgreSQL repositories take the ORM seam by the time this lands (`orm-app-resources` puts `orm` in `build_app`; `orm-job-settle` and `orm-human-gate` switch the job and gate repositories), so the RabbitMQ composition builds from `orm`, not from the asyncpg pool. `QueueBackendSettings` is also the AMQP-endpoint resolver that draft ADR-0045 (test harness queue) and draft ADR-0047 (surface lanes, §4) name for the URL/vhost/prefix precedence, so it stays a small, dependency-free class. CLI tests substitute through `CliComposition` (`CliRunner.invoke(obj=...)`, lane `fakes-job-wakeup`), never by patching an import (9.b, `src/vibey_tools/gh/docs/doctrines.md:349`).

Verified at integration `739536ea`.

## Required behaviour
1. `class QueueBackendSettings` (frozen) with `@classmethod from_sources(cls, config: VibeyConfig | None, environ: Mapping[str, str]) -> QueueBackendSettings`. Fields: `backend`, `amqp_url`, `vhost`, `prefix`, `rabbitmq` (`QueueRabbitMqConfig`, #348). Precedence: `VIBEY_QUEUE_BACKEND`, `VIBEY_BUS_AMQP_URL`, `VIBEY_BUS_VHOST` and `VIBEY_BUS_PREFIX` first (an empty value counts as unset), then `config.queue` and `config.bus`, then #348's defaults. The environment is an argument (a declared seam), never read from `os.environ` inside the class.
2. `class QueueBackendNotConfigured(VibeyError)` beside `DatabaseNotConfigured` in `bootstrap.py`. Its message contains both remedies verbatim:
   - `export VIBEY_BUS_AMQP_URL=amqp://USER:PASS@HOST:5672/`
   - `export VIBEY_QUEUE_BACKEND=postgres`
3. `QueueConsumerControlInterface` (`set_prefetch(n: int) -> None`, `async drain() -> int`) with two implementations: `PostgresQueueConsumerControl` (both no-ops; `drain` returns 0) and `RabbitMqQueueConsumerControl(deliveries, jobs)` (`set_prefetch` calls `deliveries.set_prefetch(n)`; `drain` returns `await jobs.stop()`).
4. `build_app`:
   - **postgres (the default):** everything as today; `wakeup` is #349's opener; `queue_consumer` is `PostgresQueueConsumerControl()`.
   - **rabbitmq:** with no `amqp_url`, raise `QueueBackendNotConfigured` before the pool is used. Otherwise build: `AmqpClient(AmqpSettings(url))` (#351 child 2; it connects lazily); `QueueNames(prefix)`, `RabbitMqJobTopology`, `WaitTierPlan(rabbitmq.wait_tiers_seconds)`; `writer = DispatchOutboxWriter()`; `records = DispatchingJobRecords(orm, writer=writer)`; `DispatchPublisher` and `DispatchRelay(orm, ...)` (#360); `ProjectDeliveries`, `DispatchMissPolicy`; `RabbitMqJobRepository` as `jobs`; `PostgresHumanGateRepository(orm, dispatch_writer=writer)` as `gates`; a wakeup opener that returns `RabbitMqJobWakeup(deliveries)`; `queue_consumer = RabbitMqQueueConsumerControl(deliveries, jobs)`. The AMQP client is closed in `build_app`'s `finally`.
   - If lane `fakes-bootstrap-seam` has landed (a `PostgresResourcesFactory` exists in `bootstrap.py`), make this choice inside that factory instead, add `queue_consumer` to `PersistenceInterface`, and give `InMemoryResourcesFactory` a `PostgresQueueConsumerControl()` (it is already the in-memory no-op).
5. `AppResources` gains `queue_consumer: QueueConsumerControlInterface` (before `integration_lock`); `AppResourcesInterface` (`bootstrap_interface.py`) declares it.
6. `vibey worker`: after computing `count` (`cli/main.py:1697`), call `resources.queue_consumer.set_prefetch(count)`; when the drive loops end, `await resources.queue_consumer.drain()` in the existing `finally`, before closing the wakeup.
7. With the default backend, nothing observable changes.
8. **Fakes.** `RecordingQueueConsumerControl` in `tests/fakes/queue.py` (records `prefetch` values and counts `drain()` calls; `drain` returns a configurable count). Register it (`REGISTRY`, `DRIVER_SEAMS`).
