## Why
Ratified sub-doctrine 8.b (`src/vibey_tools/gh/docs/doctrines.md:138`) says: "**Forge** defaults
to **self-hosted Forgejo**". The chart installs Gitea instead: `image: gitea/gitea:latest@sha256:87a6…`
under `surfaces.gitea` (`deploy/helm/vibey/values.yaml:520-537`), and
`templates/surfaces.yaml:818-937` renders a Gitea Secret, PVC, Service and Deployment. The only
`VibeySurface` for the forge, `<fullname>-forge`, watches `<fullname>-gitea` (`surfaces.yaml:926-935`).
Forgejo reads the same configuration from environment variables: its
`modules/setting/config_env.go` (codeberg.org/forgejo/forgejo, checked 2026-09-22) matches
`^(FORGEJO|GITEA)__`, and the official docker docs use the `FORGEJO__` form. The rootful image
keeps the Gitea layout (`GITEA_CUSTOM=/data/gitea`, `VOLUME /data`, `EXPOSE 22 3000`;
`/etc/s6/gitea/setup` generates `/data/gitea/conf/app.ini` and applies the env through
`environment-to-ini`) and ships `curl` and `/usr/local/bin/forgejo`. So the swap changes only the
image and the config.

This Part also fixes a latent bug: the Service maps ssh `22 -> targetPort 2222`
(`surfaces.yaml:861-864`), but the rootful image's sshd listens on `SSH_LISTEN_PORT`, which
defaults to `SSH_PORT`, which defaults to `22`.

Renaming the forge resources has one irreversible side effect the chart must not take on its own.
Helm deletes on upgrade every resource the chart no longer renders, and the Gitea PVC
`<fullname>-gitea-data` (`surfaces.yaml:833-847`) carries no `helm.sh/resource-policy: keep`. A
`helm upgrade` from a Gitea release would therefore delete that volume and every repository on it.
The CLAUDE.md standing subdoctrine SD-01 §6.1 forbids an irreversible action without explicit human
approval, and sub-doctrine 9.a (doctrines.md:346-347) says automation "deletes only what is provably
redundant". So this Part refuses such an upgrade until a human has decided about that volume.

## Required behaviour
1. `values.yaml`: `surfaces.gitea` becomes `surfaces.forgejo`, and every knob is kept: `enabled`,
   `image.{repository,tag,digest}`, `adminUser`, `adminPassword`, `storage.{size,storageClass}`,

   (current stable 16.x as of 2026-09-22; 15.x is the LTS line), `adminUser: forgejo_admin`,
   `adminPassword: forgejo_password`. Storage and resources are unchanged (10Gi; 100m/256Mi
   requests, 1Gi limit).
2. **The digest is pinned from the registry and never typed from memory or invented.** Run
   `docker buildx imagetools inspect codeberg.org/forgejo/forgejo:16.0.5`, or
   `crane digest codeberg.org/forgejo/forgejo:16.0.5`. Copy the top-level index digest (`Digest:`
   line), not a per-platform manifest. The listing must include `linux/amd64` and `linux/arm64`. If
   neither tool exists, this curl pair does the same:
   ```
   tok=$(curl -s "https://codeberg.org/v2/token?service=container_registry&scope=repository:forgejo/forgejo:pull" | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
   curl -sI -H "Authorization: Bearer $tok" -H "Accept: application/vnd.oci.image.index.v1+json" https://codeberg.org/v2/forgejo/forgejo/manifests/16.0.5 | grep -i docker-content-digest
   ```
   For comparison only: at spec time (2026-09-22, registry HEAD) this returned
   `sha256:cf5f5ae6acf2ababca0ee3d255705b83a47f35b25e07fc931d694d60664053fe`, and the index listed
   linux/amd64, linux/arm64 and linux/arm/v6. Use the value **your** command prints. If you cannot
   reach the registry, STOP and report BLOCKED. Do not commit this spec's value unverified, an
   empty digest, or a guessed one.
3. **No deprecated alias.** If a user still passes `surfaces.gitea`, rendering fails loudly with:
   `surfaces.gitea was renamed to surfaces.forgejo: the forge surface runs Forgejo (sub-doctrine 8.b). Move these overrides under surfaces.forgejo.`
   An alias would map Gitea-specific overrides, such as `image.repository: gitea/gitea`, onto the
   Forgejo template without anyone noticing. Every knob survives under the new key, so this is an
   explicit breaking change with a migration message, not a loss of configurability (12.c). Use
   `hasKey .Values.surfaces "gitea"`, not `.Values.surfaces.gitea`, because `helm lint --strict`
   renders with `missingkey=error`.
4. **An upgrade never silently deletes the old Gitea volume.** When the release namespace already
   holds a PVC named `<fullname>-gitea-data` whose `metadata.annotations["helm.sh/resource-policy"]`
   is not `keep`, rendering fails with:
   `this upgrade would delete the old Gitea volume <fullname>-gitea-data (the forge now runs Forgejo on its own volume). Back it up, then either keep it with `kubectl annotate pvc <fullname>-gitea-data -n <namespace> helm.sh/resource-policy=keep` or delete it yourself, and run the upgrade again.`
   With the annotation (Helm skips deleting a live resource that carries it) or without the PVC,
   rendering proceeds. The check uses `lookup`, which returns nothing under `helm template` and
   `helm lint`, so the goldens and lint are unaffected; it acts on a real install or upgrade.
   Forgejo cannot reuse that volume anyway: it migrates data only from Gitea 1.22 or earlier, and
   the chart ran `gitea/gitea:latest`.
5. Rendered resource names: Secret `<fullname>-forgejo`, PVC `<fullname>-forgejo-data`, Service
   `<fullname>-forgejo`, Deployment `<fullname>-forgejo` (container `forgejo`), and label
   `app.kubernetes.io/component: forgejo` everywhere Gitea's was. The VibeySurface keeps its name
   `<fullname>-forge` and `spec.surface: forge`; its component becomes
   `deployment: <fullname>-forgejo`.
6. Container env names use `FORGEJO__`: `FORGEJO__security__INSTALL_LOCK=true`,
   `FORGEJO__database__DB_TYPE=sqlite3`, `FORGEJO__server__HTTP_PORT=3000`. `USER_UID=1000` and
   `USER_GID=1000` are unchanged. The mount stays `/data`, and the pod keeps no securityContext,
   because the rootful image's setup needs root to chown before it drops to uid 1000, the same as
   Gitea today.
7. Ports: container `- name: http, containerPort: 3000` and `- name: ssh, containerPort: 22`.
   Service ssh is `port: 22, targetPort: 22`; http stays `3000 -> 3000`. The probes stay `tcpSocket`
   on 3000 with the same delays (ADR-0043's Security Impact specifies TCP probes).
8. Goldens: only `default` and `ollama` change in content (about +25/-23 lines each, all inside the
   forge resources, plus any `helm.sh/chart` label change from item 10). Afterwards neither file
   contains the string `gitea` in any case. `surfaces-off`, `ollama-gpu-qwenloop`, `keda-latest` and
   `keda-project` render no forge resources. Items 3 and 4 add no rendered output.
9. CI `cluster-smoke`: the Available list replaces `vibey-vibey-gitea` with `vibey-vibey-forgejo`.
   One new contract step proves the pod is Forgejo, not Gitea (`/api/forgejo/v1/version` exists only
   on Forgejo, and the API is served only once `INSTALL_LOCK` from `FORGEJO__` has taken effect,
   which the step also reads back from `/data/gitea/conf/app.ini`). A second new step proves item 4
   against the live cluster.
10. `Chart.yaml`: if `version` is `0.3.0`, set it to `0.4.0`. If it is already `0.4.0` or higher
    because Part 1 landed, leave it.

"""The forge surface is Forgejo, not Gitea (sub-doctrine 8.b).

Read from the committed goldens, which deploy/helm/golden/render.sh keeps equal to
what the chart renders, so this needs no helm.
"""

from __future__ import annotations

import re
from pathlib import Path
from typing import Any

import yaml

REPO = Path(__file__).resolve().parents[2]
GOLDEN = REPO / "deploy" / "helm" / "golden"
VALUES = REPO / "deploy" / "helm" / "vibey" / "values.yaml"
SURFACES = REPO / "deploy" / "helm" / "vibey" / "templates" / "surfaces.yaml"
CI = REPO / ".github" / "workflows" / "ci.yml"
FORGEJO = "vibey-vibey-forgejo"
PINNED = re.compile(r"^codeberg\.org/forgejo/forgejo:[0-9][^@]*@sha256:[0-9a-f]{64}$")


def _docs(profile: str) -> list[dict[str, Any]]:
    text = (GOLDEN / f"{profile}.yaml").read_text(encoding="utf-8")
    return [doc for doc in yaml.safe_load_all(text) if doc]


def _one(docs: list[dict[str, Any]], kind: str, name: str) -> dict[str, Any]:
    found = [d for d in docs if d["kind"] == kind and d["metadata"]["name"] == name]
    assert len(found) == 1, f"expected exactly one {kind}/{name}, found {len(found)}"
    return found[0]


def test_values_name_the_forge_forgejo() -> None:
    surfaces = yaml.safe_load(VALUES.read_text(encoding="utf-8"))["surfaces"]
    assert "gitea" not in surfaces
    assert surfaces["forgejo"]["image"]["repository"] == "codeberg.org/forgejo/forgejo"


def test_the_forge_deployment_runs_a_pinned_forgejo_image() -> None:
    for profile in ("default", "ollama"):
        deployment = _one(_docs(profile), "Deployment", FORGEJO)
        container = deployment["spec"]["template"]["spec"]["containers"][0]
        assert PINNED.match(container["image"]), container["image"]
        config = [e["name"] for e in container["env"] if "__" in e["name"]]
        assert config and all(name.startswith("FORGEJO__") for name in config)


def test_the_forge_service_reaches_the_rootful_sshd() -> None:
    service = _one(_docs("default"), "Service", FORGEJO)
    ssh = [p for p in service["spec"]["ports"] if p["name"] == "ssh"]
    assert ssh == [{"name": "ssh", "port": 22, "targetPort": 22, "protocol": "TCP"}]


def test_the_forge_surface_watches_the_forgejo_deployment() -> None:
    surface = _one(_docs("default"), "VibeySurface", "vibey-vibey-forge")
    assert surface["spec"] == {"surface": "forge", "components": [{"deployment": FORGEJO}]}


def test_no_default_render_mentions_gitea() -> None:
    for profile in ("default", "ollama"):
        assert "gitea" not in (GOLDEN / f"{profile}.yaml").read_text(encoding="utf-8").lower()


def test_the_chart_refuses_to_delete_an_unkept_gitea_volume() -> None:
    template = SURFACES.read_text(encoding="utf-8")
    assert 'lookup "v1" "PersistentVolumeClaim" .Release.Namespace $giteaVolume' in template
    assert '"helm.sh/resource-policy"' in template
    assert "this upgrade would delete the old Gitea volume" in template


def test_cluster_smoke_waits_for_forgejo_and_proves_it() -> None:

    assert "Contract - an upgrade never silently deletes the old Gitea volume" in workflow
