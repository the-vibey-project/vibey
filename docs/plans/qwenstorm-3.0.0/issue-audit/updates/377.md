Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
The original lane charted ADR-0044 §15 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md:563-568`): one Deployment per engine id, with `qwenloop` and `opencode` enabled by default and a `replicas` value on each. The ratified canon now says otherwise:

- **8.c** (`src/vibey_tools/gh/docs/doctrines.md:196-234`): "the family runs **exactly two loops**", each "as **a single instance per model**", and "Throughput is raised by giving the one instance more capacity, never by starting another" (`:211`).
- **8.b** (`doctrines.md:128-137`): `sovereignloop` is always on; `paidloop` is declared-only, with `claudeloop` its default adapter (`:188-193`); "OpenCode is repealed as an engine of either loop".

Draft ADR-0046 §11 (`specs/ADR-two-loops.md:314-323`) turns that into the chart:

- `loopServices` has exactly two keys;
- each loop renders one **router** Deployment and one **seat-host** Deployment per model it declares;
- every one has `replicas` fixed at 1 with **no value**, and `strategy: Recreate`;
- `paidloop` is disabled by default;
- both mount the worktrees PVC at `/work`, and neither needs PostgreSQL.

What is kept from the original lane is still true of the tree at integration `739536ea`:

- a loop edits the worktree its caller tails, so it must mount the worker's worktrees PVC at the same path (`deploy/helm/vibey/templates/worker.yaml:277-286`);
- that PVC is `ReadWriteOnce` today (`worker.yaml:303`), so either every pod that mounts it co-locates on one node, or the operator chooses `ReadWriteMany`, which becomes a value (12.c, `doctrines.md:455`);
- the sovereign loop takes the Ollama wiring the worker has today (`worker.yaml:98-117`).

## Required behaviour
1. **`values.yaml`**
   - `worker.worktrees.accessMode: ReadWriteOnce`, with a comment: RWO co-locates every pod that mounts the worktrees on one node; RWX lets them spread.
   - `loopServices` has exactly these two keys, each with a comment like its neighbours':
     ```yaml
     loopServices:
       sovereignloop:
         enabled: true            # always on (8.b)
         models: []               # one seat host per model; empty = ollama.model alone (8.d)
         capacity: 1              # runs one instance of a model takes at once (8.c)
         terminationGracePeriodSeconds: 7200
         resources: {requests: {cpu: 250m, memory: 512Mi}, limits: {memory: 2Gi}}
         extraEnv: []
       paidloop:
         enabled: false           # declared-only (8.b)
         models: [claudeloop]     # one seat per adapter; claudeloop is the default (8.b)
         capacity: 1
         engineAuth: true
         terminationGracePeriodSeconds: 7200
         resources: {requests: {cpu: 250m, memory: 512Mi}, limits: {memory: 2Gi}}
         extraEnv: []
         seatEnv: {}              # {<engine id>: [EnvVar, ...]}, for that seat's host only
     ```
   - There is **no `replicas` key** under `loopServices`. The template fails the render in two cases, naming 8.c:
     - when `loopServices.<loop>.replicas` is set: "`loopServices.<loop>.replicas` is not a value: sub-doctrine 8.c runs a single instance per model; raise `capacity` instead";
     - when `loopServices` has a key other than `sovereignloop` and `paidloop`: "loopServices has exactly two loops (8.c): sovereignloop and paidloop".
2. **`templates/loop-services.yaml`** (new). For each enabled loop, `sovereignloop` first:
   - **Seats.** For `sovereignloop` the seats are its `models`, or `[ .Values.ollama.model ]` when that list is empty. For `paidloop` they are its `models` (engine ids).
   - **Seat slug** (ADR-0046 §3, "Seat names"): lower-case the name, then replace every character outside `[a-z0-9-]` with `-` (`gpt-oss:20b` becomes `gpt-oss-20b`). The render fails when a slug is `probe` or `dead`, or when two seats of one loop share a slug.
   - **Router Deployment** `<fullName>-<loop>-router`, labelled `app.kubernetes.io/component: <loop>-router`, with args `["loop-service", "--loop", <loop>, "--role", "router", "--seat", <seat 1>, "--seat", <seat 2>, …]`. Each seat is passed as declared; the CLI slugifies it.
   - **Seat-host Deployment**, one per seat: `<fullName>-<loop>-seat-<slug>`, labelled `app.kubernetes.io/component: <loop>-seat` and `vibey.dev/seat: <slug>`, with args `["loop-service", "--loop", <loop>, "--role", "seat", "--seat", <seat>, "--capacity", <capacity>]`.
   - **Every loop Deployment** has:
     - `replicas: 1` as a literal, and `strategy: {type: Recreate}` (a `RollingUpdate` would briefly run two instances of one model);
     - the worker's image, `serviceAccountName`, `podSecurityContext`, `securityContext`, `nodeSelector` and `tolerations`;
     - the loop's `terminationGracePeriodSeconds` and `resources`;
     - the worktrees volume (`claimName: <fullName>-worktrees`) mounted at `/work`, with `workingDir: /work`;
     - the `wait-for-rabbitmq` init container that #376 (R29) gives the worker, unconditionally, because a loop cannot run without the broker.
   - **Environment**, in this order:
     1. `VIBEY_BUS_AMQP_URL`, `VIBEY_BUS_VHOST` and `VIBEY_BUS_PREFIX`, exactly as #376 renders them for the worker;
     2. `VIBEY_LOOP_SERVICES_ROOT=/work`;
     3. for `sovereignloop` with `ollama.enabled`, the worker's lines (`worker.yaml:98-117`): `VIBEY_OLLAMA_URL`, `QWENLOOP_BASE_URL` (`<url>/v1`), `VIBEY_OLLAMA_MODEL` and `QWENLOOP_MODEL`, plus `VIBEY_FEATURE_QWENLOOP=1` when `ollama.qwenloopFeature`. On a seat host the two model variables hold **that seat's** model; on the router they hold `ollama.model`. (The `QWENLOOP_*` names stay until ADR-0046's rename lane.)
     4. for `paidloop` with `engineAuth`, the `engineAuth.keys` block exactly as `worker.yaml:91-97` renders it;
     5. the loop's `extraEnv`;
     6. on a paid seat host, `seatEnv.<seat>`.
   - **No `VIBEY_PG_URL`**, and no `wait-for-postgres`: the loops are database-free (ADR-0046 §2, §11).
3. **Co-location.** When `worker.worktrees.accessMode` is `ReadWriteOnce`:
   - the worker and every loop Deployment carry the pod label `vibey.dev/worktrees: <Release.Name>`;
   - each renders `affinity.podAffinity.requiredDuringSchedulingIgnoredDuringExecution` with one term: `labelSelector.matchLabels: {vibey.dev/worktrees: <Release.Name>}`, `topologyKey: kubernetes.io/hostname`. The first pod may schedule because it matches its own term;
   - `.Values.affinity`'s other keys (`nodeAffinity`, `podAntiAffinity`) render beside the term, as they do for the worker today (`worker.yaml:293-295`). If `.Values.affinity.podAffinity` is also set, the render fails and names `worker.worktrees.accessMode=ReadWriteMany`.
   With `ReadWriteMany`, no co-location term is rendered.
4. **The PVC.** `accessModes: [{{ .Values.worker.worktrees.accessMode }}]` (`worker.yaml:303`).
5. **The worker** also gets `VIBEY_LOOP_SERVICES_ROOT=/work` (the environment row that lane `loops-config-loop-services` declares; ADR-0046 moved the `[loop_services]` keys there from R01).
6. **Goldens.** Add two profiles to `deploy/helm/golden/render.sh`, after `surfaces-off`:
   ```
   profile paidloop --show-only templates/loop-services.yaml -- \
     --set loopServices.paidloop.enabled=true --set 'loopServices.paidloop.models={claudeloop,codexloop}'
   profile worktrees-rwx --show-only templates/worker.yaml --show-only templates/loop-services.yaml -- \
     --set worker.worktrees.accessMode=ReadWriteMany
   ```
   Regenerate with `render.sh --update` and review the diff: `default`, `ollama`, `ollama-gpu-qwenloop` and `surfaces-off` change, and `paidloop` and `worktrees-rwx` are new. `keda-latest` and `keda-project` **must not change**.

- [ ] `render.sh` passes, and the `keda-*` goldens are byte-identical.

## Hard repository rules (always)
- domain/ stays pure (no I/O, async, clock, network); enforced by tests/domain/test_domain_purity.py.
- Dependencies point inward: domain -> application -> infrastructure -> cli (import-linter).
- CreditsExhausted never has resets_at. A capacity rejection outranks a completion claim.
- Code lives in classes with an interface beside each (ADR-0016); module functions need a written reason.
- Every job idempotent under replay; the ledger is append-only.
- Substitution happens at a declared seam, never by patching an import (sub-doctrine 9.b).
- Protected tests are never edited: `tests/domain/test_noloss*.py`, `tests/domain/test_briefing.py`, `tests/infrastructure/db/test_chaos.py`, `tests/system/test_delivery_stage_set.py`, `tests/live/**`.
