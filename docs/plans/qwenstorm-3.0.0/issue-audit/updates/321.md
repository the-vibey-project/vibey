Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
Sub-doctrine 8.b (`src/vibey_tools/gh/docs/doctrines.md:120-194`, amended by the merge of #392
on 2026-09-22) makes the sovereign loop always on and the paid adapters declared-only:

- "**Engines** default to **`sovereignloop`** … this era's default model (8.d), and **VS Code**
  when its provider is local — always on, never needing declaration" (`:128-131`). Until
  ADR-0046's rename lane lands, `sovereignloop`'s native adapter is the engine id `qwenloop`.
- "`paidloop` and its adapters — `claudeloop`, `codexloop`, `cursorloop`, `agyloop`, and VS Code
  on a paid provider — are declared-only" (`:131-133`).
- "**OpenCode is repealed** as an engine of either loop; VS Code takes its place in both, and the
  runner that drove OpenCode is retired once the VS Code adapter carries its work" (`:133-135`).

The config schema still encodes the pre-#392 "sovereign pair": `DEFAULT_ENGINES = ("qwenloop",
"opencode")` (`src/vibey/domain/config.py:21`) and `_parse_engines` force-appends both
(`config.py:406-409`). And nothing at runtime reads `[engines].enabled`:

- `src/vibey/bootstrap.py:736-738` builds a `LoopProcessAdapter` for every `DEFAULT_DESCRIPTORS`
  engine (`src/vibey/infrastructure/engines/descriptors.py:404-410`: the paid four plus `OPENCODE`);
- `src/vibey/bootstrap.py:368-370` (`build_full_worker`) adds `qwenloop` only when its feature switch
  is on (`src/vibey/infrastructure/engines/local_engines.py:99-107`, `LocalEngineSettings.enabled`);
- `vibey doctor` checks `DEFAULT_DESCRIPTORS` plus switched-on local engines (`src/vibey/cli/main.py:1275`);
- cluster preflight defaults its pool to `DEFAULT_DESCRIPTORS`
  (`src/vibey/infrastructure/cluster_preflight.py:140`);
- the worker's "matches none" message still tells the operator to set `VIBEY_FEATURE_QWENLOOP=1`
  (`src/vibey/cli/main.py:1657-1662`).

So a config that lists `qwenloop` without its switch loads (`config.py:680-681` exempts it) but
never runs, undeclared paid engines still run, and the repealed `opencode` runs by default.

## Required behaviour
1. **The pool.** For a project, the candidate engine pool is, in this order:
   - `qwenloop` — always;
   - each paid engine (`claudeloop`, `codexloop`, `cursorloop`, `agyloop`) the project declares;
   - `claudeloop-local` only when its own switch (`VIBEY_FEATURE_CLAUDELOOP_LOCAL` /
     `[features] claudeloop_local`) is on;
   - `opencode` **only when the project declares it** (transitional: repealed by 8.b, kept
     declarable until ADR-0046's lane L38 retires it, so nothing becomes less configurable
     before the operator accepts that removal, 12.c). Each time a declared `opencode` enters a
     pool, log one warning: `"opencode is repealed (sub-doctrine 8.b) and will be retired when
     the VS Code adapter lands; it runs only because this project declares it"`.
2. **"Declares"** means: the project's stored config (`project.config`) has `engines` as a table
   whose `enabled` list names it (from `vibey.toml [engines]`), OR has `engines` as a list (the
   VibeyProject CR allow-list written by `src/vibey/infrastructure/operator/handlers.py:61-62`)
   that names it. Unknown names are ignored here (config validation already refuses them).
3. **Config defaults follow 8.b.** `DEFAULT_ENGINES = ("qwenloop",)` (`config.py:21`, with its
   comment changed from "The sovereign default pair" to "The sovereign default (always on, never
   needs declaration)"), and `_parse_engines` force-appends only `qwenloop` (`config.py:406-409`).
   `opencode` stays in `KNOWN_ENGINES` (`config.py:25-33`) so a declaration still validates.
4. **`qwenloop` cannot be switched off.** `LocalEngineSettings.enabled(EngineId.QWENLOOP)` returns
   True whatever `VIBEY_FEATURE_QWENLOOP` or `[features] qwenloop` says. When either explicitly says
   false, log one warning per `LocalEngineSettings` instance: `"qwenloop cannot be switched off
   (sub-doctrine 8.b); ignoring <source>"`, where `<source>` is `VIBEY_FEATURE_QWENLOOP` or
   `[features] qwenloop`. `claudeloop-local` keeps its switch unchanged. (The operator ruled on 2026-09-22 that `claudeloop-local` becomes a paidloop adapter, declared-only, because Claude Code is not FOSS; lane `loops-claudeloop-local-paid` makes that move. This lane therefore leaves the switch exactly as it is: it neither extends it nor adds a test that pins `claudeloop-local` as a local engine.)
5. **Worker narrowing.** `vibey worker --engines a,b` still narrows the pool this worker serves,
   after (1). An `--engines` list that names nothing in the pool keeps today's error and exit code
   (`cli/main.py:1657-1663`), but the message no longer mentions `VIBEY_FEATURE_QWENLOOP`: only
   `claudeloop-local` needs a switch (`VIBEY_FEATURE_CLAUDELOOP_LOCAL=1` or
   `[features] claudeloop_local`), and a paid engine joins only when the project declares it.
6. **Doctor.** `vibey doctor` checks exactly the pool from (1) for the `./vibey.toml` in the working
   directory. No file means `qwenloop` only (plus `claudeloop-local` when switched on).
7. **Cluster preflight.** Its default pool (`cluster_preflight.py:140`) is `(QWENLOOP,)` — the
   `QWENLOOP` descriptor from `descriptors.py:412` — and engines passed explicitly still add their
   auth requirements as today.
8. Selection is otherwise unchanged: LOCAL tier first (ADR-0038), recorded conformance still
   required before an engine is selected. An adapter injected by the faked harness
   (`engine_adapters=` on `build_full_worker`) is never dropped.

## Where to change
- **New** `src/vibey/infrastructure/engines/engine_pool.py`: `class EnginePool`, constructed with a
  `LocalEngineSettingsInterface` (keyword `local=`) and a `logging.Logger` (keyword `log=`, default
  the module logger). Methods:
  - `for_project(self, config: Mapping[str, object]) -> tuple[EngineId, ...]` implementing (1)–(2);
  - `filter_adapters(self, config: Mapping[str, object], adapters: Mapping[EngineId, EngineAdapter],
    *, injected: frozenset[EngineId] = frozenset()) -> dict[EngineId, EngineAdapter]` — keeps an
    adapter when its id is in `for_project(config)` or in `injected`.
- **New** `src/vibey/infrastructure/engines/interfaces/engine_pool_interface.py`: a
  `@runtime_checkable` Protocol `EnginePoolInterface` with both methods. Copy the layout of
  `local_engines.py` and `interfaces/local_engines_interface.py`.
- `src/vibey/domain/config.py:20-21` and `:406-409` (behaviour 3).
- `src/vibey/infrastructure/engines/local_engines.py:99-107` (behaviour 4); keep
  `enabled_engines` ordering (`:109-111`).
- `src/vibey/bootstrap.py:364-370` (`build_full_worker`): before adding local adapters, filter

- `src/vibey/cli/main.py:1275` (doctor: use the pool) and `:1657-1662` (the message, behaviour 5).
- `src/vibey/infrastructure/cluster_preflight.py:140` (behaviour 7).
