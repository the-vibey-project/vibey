Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §4 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`) dispatches jobs through a transactional outbox written **inside the same transaction** as the job's state change. vibey's persistence is moving onto SQLAlchemy 2 async behind `PostgresOrmInterface` (`src/vibey/infrastructure/db/orm.py`; lanes `orm-database-seam`, `orm-job-enqueue`, `orm-job-settle`), whose `transaction()` and `autocommit()` yield a `sqlalchemy.ext.asyncio.AsyncConnection`. The outbox must therefore take that connection. ADR-0044 §14 still says "any asyncpg-shaped executor"; the operator's ORM standard supersedes that in code (`specs/orm-tables.md:59-63`: no new `import asyncpg`, `text()`, `exec_driver_sql()` or SQL strings in `src/`), and the docs wave updates the ADR.

The family's outbox (`src/vibey_tools/bootstrap/vibey_bootstrap/db/outbox.py:57-183`) has two gaps:

- it is sync SQLAlchemy only, built on `text()` SQL strings (`:69-73`, `:100-104`, `:159-165`);
- a row a relay claimed as `sending` stays `sending` forever if that relay dies before `mark_sent` (`claim` `:97-112`, `drain_outbox` `:147-183`).

Sub-doctrine 10.e (`src/vibey_tools/gh/docs/doctrines.md:417`) says to close the gap in the family's package. The family cannot import vibey's `PostgresOrmInterface`, so the async outbox takes the `AsyncConnection` its caller hands it and builds its statements with SQLAlchemy Core. The sync API stays exactly as it is.

Verified at integration `739536ea`.

## Required behaviour
1. `class OutboxTable` with `build(self, name: str = "outbox", *, tracked: bool = False, metadata: MetaData | None = None) -> Table`:
   - validates `name` with `_validate_identifier` (`:24-28`);
   - columns mirror `OUTBOX_DDL` (`:31-42`): `id` UUID primary key, `idempotency_key` Text unique not null, `payload` JSONB not null, `status` Text not null server default `'pending'`, `attempt_count` Integer not null server default 0, `last_error` Text, `created_at` TIMESTAMP(timezone=True) not null server default `now()`, `sent_at` TIMESTAMP(timezone=True);
   - `tracked=True` adds `claimed_at` TIMESTAMP(timezone=True) and a status check built from the column, `CheckConstraint(status_column.in_(("pending", "sending", "sent", "failed")), name=f"{name}_status")`;
   - a fresh `MetaData()` when none is given, so building twice never collides.
   Server defaults are plain values or functions (`server_default="pending"`, `server_default="0"`, `server_default=func.now()`), never `text()`.
2. `class AsyncOutbox(conn: AsyncConnection, *, table: str = "outbox", track_claims: bool = False)`. Every statement is SQLAlchemy Core on `OutboxTable().build(table, tracked=track_claims)`:
   - `enqueue(idempotency_key: str, payload: Mapping[str, object]) -> bool`: `sqlalchemy.dialects.postgresql.insert(t).values(id=uuid4(), idempotency_key=..., payload=dict(payload), status="pending", attempt_count=0).on_conflict_do_nothing(index_elements=[t.c["idempotency_key"]])`; returns `result.rowcount == 1`.
   - `claim_batch(limit: int, *, max_attempts: int = 5) -> list[OutboxMessage]`: **one** statement, `update(t).where(t.c["id"].in_(select(t.c["id"]).where(t.c["status"] == "pending", t.c["attempt_count"] < max_attempts).order_by(t.c["created_at"]).limit(limit).with_for_update(skip_locked=True))).values(status="sending"[, claimed_at=func.now()]).returning(*t.c)`. It needs no long transaction. Rows map to `OutboxMessage` (`payload` decoded with `json.loads` when it arrives as `str`, as `drain_outbox` does at `:173`).
   - `mark_sent(msg_id)` and `mark_failed(msg_id, error, *, max_attempts=5)` behave as the sync methods do (`:114-144`); `mark_failed` uses `case(...)` for the status and truncates the error to 2000 characters; with tracking it also sets `claimed_at = None`.
   - `reclaim_stale(older_than: timedelta) -> int` returns `sending` rows whose `claimed_at < func.now() - literal(older_than, Interval())` to `pending` and returns the count. It raises `ValueError` unless `track_claims=True`.
3. `class AsyncOutboxDrainer(outbox: AsyncOutboxInterface, sender: Callable[[OutboxMessage], Awaitable[None]])`. `drain(limit: int, *, max_attempts: int = 5) -> int` claims a batch and sends each row: a success is marked sent; an exception is marked failed and logged at `warning`, never raised. It returns the count sent. Its docstring says the outbox should sit on an autocommit connection (vibey: `PostgresOrmInterface.autocommit()`), so each claim is durable before its send.
4. The `outbox.*` counters are bumped exactly as the sync class bumps them (`outbox.enqueued` only when a row was inserted).
5. Interfaces (9.b), in the family's style (`ABC` with `@abstractmethod`, as `vibey_bootstrap/services/interfaces/telemetry_manager_interface.py`): `OutboxTableInterface`, `AsyncOutboxInterface`, `AsyncOutboxDrainerInterface` in `vibey_bootstrap/db/interfaces/outbox_interface.py`, re-exported from `vibey_bootstrap/db/interfaces/__init__.py` (that package is created by lane `orm-bootstrap-async-engine`). The three classes subclass them.
6. `OUTBOX_DDL`, `Outbox`, `OutboxMessage` and `drain_outbox` are unchanged. Add the new names to `__all__` (`:186`). SQLAlchemy is imported lazily or at module top exactly as the module's existing sync code allows (the `db` extra carries it; vibey carries `sqlalchemy[asyncio]`).

## Acceptance criteria
- [ ] Compiled with `sqlalchemy.dialects.postgresql.asyncpg.dialect()`: `enqueue` renders `ON CONFLICT (idempotency_key) DO NOTHING`; `claim_batch` renders `FOR UPDATE SKIP LOCKED`, `ORDER BY`, `LIMIT` and `RETURNING`, and sets `claimed_at` only when tracking.
- [ ] `OutboxTable().build(tracked=False)` has exactly the columns of `OUTBOX_DDL`; `tracked=True` adds `claimed_at` and the status CHECK.
- [ ] `reclaim_stale` without tracking raises `ValueError`.
- [ ] The drainer marks sent and failed and never raises.
- [ ] The diff adds no `text(`, no `$n` placeholder and no `asyncpg` import to `outbox.py` (the sync functions keep theirs).
- [ ] Against a real PostgreSQL (integration, skipped without `VIBEY_TEST_DATABASE_URL`): two concurrent `claim_batch` calls never return the same row; `reclaim_stale` returns a stale `sending` row to `pending`; a duplicate `enqueue` returns `False`.
- [ ] The existing sync tests pass untouched, and the whole tenant suite keeps its 100% line floor.
