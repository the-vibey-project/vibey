Closing as superseded by draft ADR-0046 (two loops). **Nothing from this issue was merged.**

The three consumers here bind per engine id (control key `engine_id`, `vibey.runs.<engine_id>.probe`, `vibey.runs.<engine_id>.dead`). Under sub-doctrine 8.c as ratified by #392 (`doctrines.md:196-234`) there are two loops, so ADR-0046 §3 re-keys all three:
- **Control:** `vibey.runs.control` stays a topic exchange; each loop binds `<loop>` and `all`, and the new `SUPERSEDE` command is broadcast on it (§3 table; §6 last paragraph).
- **Probes:** one classic `vibey.runs.<loop>.probe` queue per loop. ADR-0046 §4 adds a rule this lane lacked: a probe that would load a non-resident model is answered from its last real result, marked cached with its time — never a fabricated pass, and never a model thrash.
- **Dead letters:** `vibey.runs.<loop>.dead` and `vibey.runs.<loop>.<seat>.dead`, each answered `DEAD_LETTERED`, so the caller fails the attempt and ADR-0024 parks it (§3 idempotency table, last row).

Carried over into ADR-0046's `infrastructure/loop_service/control.py` (§10): control reaching the runner's own inbox through R20's `RunInbox` (#367, kept); probes run where the runs run, so the environment whose auth matters is the one probed; unknown-run control messages are ignored and malformed ones are completed and logged; the `DEAD_LETTERED` reply carries the delivery count.

Evidence: `specs/ADR-two-loops.md` §3 (lines 140–191), §4 (lines 216–220), §10. ADR-0046's lanes are still to be filed.
