# OpenClaw: an operator surface that lets an OpenClaw agent drive vibey end to end

## Summary

The operator asked to "add support for openclaw". The repository has already described what
that support is twice, and both descriptions point the same way. OpenClaw is a local-first,
open-source agent framework. It becomes a **front door to vibey**: an OpenClaw agent,
reached over chat, can create a project, relay park prompts to its human, apply the
human's replies as gate answers, and report completion.

1. **Runbook 11** (`docs/runbooks/expansion/11-openclaw-moltbook.md`) designs a packaged
   OpenClaw **AgentSkill** that teaches an OpenClaw agent to conduct vibey through its CLI
   (and its API when one exists). The skill is published to ClawHub (OpenClaw's registry)
   and validated by a live conversation that drives a full run.
2. **The fleet program runbook** (`docs/plans/fleet-program-runbook.md:249-259`, Wave 1.7
   "seven surfaces") lists `openclaw` as the seventh surface beside cli, tui, api, mcp,
   webhook and sdk: "`openclaw/` per repo: `SOUL.md` + skills + a channel config pointing
   at the MCP/HTTP surface. Behind `[openclaw] enabled = true`, token auth, loopback-only".

This rewrite adopts that reading. Whether "support" also means running OpenClaw **as an
engine** inside a loop is not stated anywhere in the repository. The 2026-09-19 audit
comment assumed a "runner", so that reading is left as an open question rather than
guessed.

## Why

- **Doctrine 3** (`src/vibey_tools/gh/docs/doctrines.md:32-35`): every exposed surface
  carries a fully working example.
- **2.b** (`:30`): installable where users already are. For OpenClaw users that is
  ClawHub, published by the same automation as everything else.
- **8.a / 8.b** (`:99-194`):
  - the OpenClaw agent should run on the sovereign default model (8.d: GPT-OSS 20B on
    Ollama, `:259-269`)
  - its chat channel should default to **Matrix** (`:159-162`), because WhatsApp,
    Telegram and Slack are listed as declared-only
- **SD-01 §4 / 10.c** (`:412-415`): chat text is data, never instructions.
- **Constitution III.4**: the agent's messages are labelled as machine speech.
- **Security:** the fleet runbook records that "OpenClaw has a substantial published
  attack-surface literature". The surface is loopback-only and token-authenticated by
  default.

  SKILL.md for OpenClaw. The only mentions of "openclaw" are in runbooks 00, 11 and 12 and

- Master plan row 11 is "OpenClaw / Moltbook | Not started | Constrained by sub-doctrine

- **Prerequisite surfaces missing:** the conductor has no HTTP API or MCP server
  (`docs/runbooks/expansion/12-integration-surfaces.md:3-9`). Today the skill can only
  drive the CLI (`vibey new`, `status --json` at `src/vibey/cli/main.py:712`, `answer --raw`
  at `:306`).
- The repository's own skill trees (`.claude/skills`, `.agents/skills`) already use a
  `SKILL.md` + YAML frontmatter format. Runbook 11 notes that the AgentSkills spec is the
  same shape (a `name` matching the directory plus a `description`), so the skill can
  follow house conventions.

## Scope / Required behaviour

1. **An OpenClaw AgentSkill for vibey** (`integrations/openclaw/vibey/SKILL.md`, per
   runbook 11). It teaches:
   - `vibey new` with a mandatory budget cap
   - polling `vibey status`
   - reading park prompts and relaying them to the human verbatim
   - applying replies as `vibey answer` (never auto-granting a raw money increase, per
     runbook 11 risks)
   - reporting DONE with the demo output
2. **A frontmatter lint test** that validates the skill against the AgentSkills rules
   runbook 11 records.
3. **`[openclaw]` configuration** (default off): token source, loopback-only binding, and
   the channel. The channel defaults to Matrix if OpenClaw supports it; that must be
   verified.
4. **Publishing** to ClawHub from the release pipeline, if ClawHub offers an automatable
   publish.
5. **A live proof:** an archived OpenClaw conversation that drives a scripted-engine
   greeter from `vibey new` to DONE (runbook 11, work item 2).

## Acceptance criteria

- [ ] `integrations/openclaw/vibey/SKILL.md` exists, and the lint test passes in CI.
- [ ] One archived conversation transcript, linked here, in which an OpenClaw agent
      conducts a full scripted run, relays at least one gate to a human and applies the
      answer.
- [ ] The agent in that proof runs on a local model (8.a) over a Matrix channel, or the
      reason it could not is recorded (10.f).
- [ ] The skill is published to ClawHub automatically, or the manual step is recorded as
      the maintainer's (Constitution V.4 precedent).
