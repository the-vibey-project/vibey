## Required behaviour
1. `class RabbitMqJobRepository` is constructed with: `records: DispatchingJobRecordsInterface`, `relay: DispatchRelayInterface`, `deliveries: ProjectDeliveriesInterface`, `policy: DispatchMissPolicyInterface`, `codec: JobDispatchCodecInterface`, `client: AmqpClientInterface` (used only to read the dead queue), `names: QueueNamesInterface`, `settings: QueueRabbitMqConfigInterface`, `clock: Clock`, `logger: Logger`.
2. The methods that involve no broker delegate straight to `records`: `enqueue`, `enqueue_batch`, `list_for_cycle`, `heartbeat`, `grant_attempts`, `assign_engine`, `count_unsettled`, `queue_depth` and `get`. `enqueue` and `enqueue_batch` then `await relay.flush_soon()`.
3. `claim(project_id, *, owner, lease)`:
   - `await deliveries.ensure_started(project_id)`. On the **first** claim of this instance, if nothing is buffered, `await deliveries.wait_buffered(timedelta(seconds=settings.first_claim_wait_seconds))`.
   - Then loop:
     - `d = deliveries.next_buffered()`; if it is `None`, return `None`.
     - Decode `d.body`. On `MalformedDispatch`, or a dispatch whose `project_id` is not `project_id`, call `d.dead_letter()`, log `queue.malformed_dispatch` at `warning`, and continue.
     - `job = await records.claim_dispatched(dispatch, owner=owner, lease=lease)`. If there is a job: `deliveries.hold(job.id, d)` and return it.
     - Otherwise `decision = policy.decide(await records.snapshot(dispatch.job_id), dispatch.dispatch_seq, clock.now())`. On `REDELAY`, `await relay.publish(dataclasses.replace(dispatch, not_before=decision.not_before))`, then `await d.complete()`; if the publish raises, `await d.abandon()` instead and return `None`, so the message is never lost. On `DROP`, `await d.complete()`. Log `queue.dispatch_missed` at `info` with the verdict and reason, and continue.
4. `ack`, `nack`, `defer` and `park` each call the matching `records` method, then **always** `await deliveries.settle_held(job_id)`, whether or not the write landed (a refused write means the delivery is stale), then `await relay.flush_soon()`. Each returns the records method's boolean. Copy the settle-then-log discipline of `WorkerLoop._landed` (`worker.py:425-442`): log refused writes, never raise.
5. `reap()` is the reconciler, throttled by `clock` to at most once per `settings.reconcile_interval_seconds` (0 means every call). When throttled it returns 0. Otherwise it runs, in order, each step's exception logged and not stopping the later steps:
   - `n = await records.reap()`;
   - `await records.sweep_lost(redispatch_after=timedelta(seconds=settings.redispatch_after_seconds), limit=settings.sweep_batch)`;
   - `await relay.drain()`;
   - drain up to `settings.dead_drain_batch` dead pointers: `d = await client.get(names.dead_queue())` until it returns `None`; decode each, call `records.park_dead_letter(dispatch, delivery_limit=settings.delivery_limit)`, then `d.complete()`. A malformed dead pointer is completed and logged at `warning` with its first 200 bytes.

   It then logs `queue.reconciled` at `info` with `reaped`, `swept`, `relayed`, `dead_parked`, `dead_malformed` and `elapsed_ms`, and returns `n`.
6. `stop()` returns `await deliveries.stop()`, for the drain.
7. The interface `RabbitMqJobRepositoryInterface(JobRepository, Protocol)` adds `stop`, in `src/vibey/infrastructure/queue/interfaces/rabbitmq_job_repository_interface.py`.

## Acceptance criteria
- [ ] With **no service** (the fakes above): one `WorkerLoop` runs enqueue → claim → handler `Success` → ack; the job is `SUCCEEDED` and the delivery acked.
- [ ] A `Park` leaves no held delivery; answering the gate (with #362's fake redispatch) makes the job claimable again after `reap()`.
- [ ] A `Defer` re-delays the job through a tier, and it is claimable after `expire()` of that tier.
- [ ] A stale-generation delivery is dropped; a live-lease delivery is re-delayed; a re-delay whose publish fails abandons the delivery instead of losing it.
- [ ] A malformed delivery is dead-lettered; `reap()` parks a dead-lettered pointer's job as `delivery_exhausted` and logs `queue.reconciled`.
- [ ] `reap()` is throttled; `reconcile_interval_seconds = 0` reconciles on every call.
- [ ] With PostgreSQL and the in-memory broker (integration): the same end-to-end run succeeds with `DispatchingJobRecords` and `DispatchRelay`.
- [ ] `isinstance(repo, JobRepository)`; 100% infrastructure coverage.
