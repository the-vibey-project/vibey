## Why
Sub-doctrine 8.b makes self-hosted Forgejo the default forge (`docs/doctrines.md:138`, `vibey_gh/config.py:288`), and every forge call must go through `ForgeAdapterInterface` (`docs/doctrines.md:168-176`). Three modules list open pull requests through `gh`, each with its own argv:
- `merge_train.py:319-330` (`pr list --base <integration> --state open --json number --jq sort_by(.number)`);
- `promote.py:85-99` (`pr list --base <release> --head <integration> --state open --json number --jq '.[0].number // ""'`);
- `pr_automation.py:582-594` (`pr list --repo R --state open --label <exhausted> --json number`).

vibey-gh ADR 0001 has a verb arrive with its first caller and answer `(value, problem)`. This lane adds the three number-returning listings, so parts 1, 2 and 4 of the wave can move off `gh`.

## Required behaviour
Conventions:
- Every verb answers `(value, problem)` and never raises. `problem` is `""` exactly when the forge answered; otherwise `value` is `()` or `None`.
- Forgejo is the default adapter (8.b): implement and test it first.
- The helpers used below were added by #332's child lanes and are already on the branch:
  - on `GitHubForge`: `_scoped(head, tail)`, `_read(args)`, `_run(args)`, `_failed(run, label)`;
  - on `ForgejoForge`/`GitLabForge`: `_pages(path, *, most=None)`.
- Forgejo `{R}` = `quote(self.repository, safe="/")` (the existing `_repository()`). GitLab `{P}` = `quote(self.repository, safe="")` (`_project()`).
- GitHub argv is byte-for-byte today's: `self._scoped([...], [...])` adds `--repo <name>` right after the two-word subcommand only when the adapter is bound.

Declare in `vibey_gh/interfaces/forge_adapter_interface.py`, in a new `# --- Change-request listings ---` block with one-line docstrings, and implement on all three adapters:

1. `open_change_request_numbers(self, *, base: str) -> tuple[tuple[int, ...], str]`
   - Forgejo: `_pages(f"repos/{R}/pulls?state=open")`, keep pulls whose `base.ref == base`, answer their `number`s sorted.
   - GitLab: `_pages(f"projects/{P}/merge_requests?state=opened&target_branch={quote(base, safe='')}")`, answer sorted `iid`s.
   - GitHub: `_read(self._scoped(["pr", "list"], ["--base", base, "--state", "open", "--json", "number", "--jq", "sort_by(.number)"]))`.
     - problem → `((), problem)`; `None` → `((), "")`;
     - a list → the int `number` of every dict item, in the order given;
     - anything else → ``((), "`gh pr list` returned JSON that is not a list")``.
2. `open_change_request_between(self, *, base: str, head: str) -> tuple[int | None, str]`
   - Forgejo: open pulls, paged, with `base.ref == base`, `head.ref == head` and `head.repo_id == base.repo_id`. Answer the lowest `number`, or `None`.
   - GitLab: `_pages(f"projects/{P}/merge_requests?state=opened&target_branch={quote(base, safe='')}&source_branch={quote(head, safe='')}")`, keeping `source_project_id == target_project_id`. Answer the lowest `iid`, or `None`.
   - GitHub: `run, problem = self._run(self._scoped(["pr", "list"], ["--base", base, "--head", head, "--state", "open", "--json", "number", "--jq", '.[0].number // ""']))`.
     - `run is None` → `(None, problem)`;
     - rc ≠ 0 → `(None, self._failed(run, "gh pr list"))`;
     - stripped stdout all digits → `(int(...), "")`, else `(None, "")`.
3. `labelled_open_change_request_numbers(self, *, label: str) -> tuple[tuple[int, ...], str]`
   - Forgejo: open pulls, paged, whose `labels[].name` contains `label`, answered as sorted numbers.
   - GitLab: `_pages(f"projects/{P}/merge_requests?state=opened&labels={quote(label, safe='')}")` → sorted `iid`s.
   - GitHub: `_read(self._scoped(["pr", "list"], ["--state", "open", "--label", label, "--json", "number"]))`, parsed exactly like item 1 (`None` → `((), "")`).
4. No consumer changes. `merge_train`, `promote` and `pr_automation` move in parts 1, 2 and 4.

### 3. feat(gh): the forge adapter waits for a change request's checks
**Scope.** Declare and implement `wait_for_checks(self, number: int, *, interval_seconds: int, timeout_seconds: int) -> tuple[bool, str]`.
- GitHub, today's `promote.py:130-133`: `_run(self._scoped(["pr", "checks", str(number)], ["--watch", "--interval", str(interval_seconds)]))`. `timeout_seconds` is not passed, because gh has no timeout. rc 0 → `(True, "")`, else `(False, _failed(run, "gh pr checks", with_stdout=True))`.
- Forgejo/GitLab gain `sleep: Callable[[float], None] = field(default=time.sleep, repr=False, compare=False)`, the declared seam, so `ForgejoForge(root=…, transport=…)` still compares equal. They poll `rounds = max(1, timeout_seconds // interval_seconds)` times, sleeping `interval_seconds` between rounds but not after the last.
  - Forgejo: GET `repos/{R}/pulls/{n}` → `head.sha`, then GET `repos/{R}/commits/{sha}/status`.
    - `state == "success"` → `(True, "")`;
    - `failure`/`error` → `(False, f"checks on {sha[:12]} ended {state}")`;
    - `total_count == 0` → `(False, "no checks are reported on the change request's head")`;
    - else wait.
  - GitLab: GET `projects/{P}/merge_requests/{n}` → `head_pipeline.status`.
    - `success` → `True`;
    - `failed`/`canceled`/`skipped` → `(False, f"the head pipeline ended {status}")`;
    - no pipeline → `(False, "no pipeline ran on the merge request's head")`;
    - else wait.
  - Exhausted → `(False, f"checks did not settle within {timeout_seconds} seconds")`.
- Tests inject `sleep=calls.append` and take no wall time.
- Depends on child 2. #335 depends on this child.
