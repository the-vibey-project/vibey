Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §1, §13 and §14 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`) make two things selectable: the job-queue backend (`postgres` or `rabbitmq`) and how vibey invokes a loop engine (`subprocess` or `service`). Draft ADR-0046 (`specs/ADR-two-loops.md`, "How each non-negotiable still holds" item 7) keeps both invocation modes. Sub-doctrine 12.c (`src/vibey_tools/gh/docs/doctrines.md:455`) requires every tunable to be a key, never a constant.

Today `[bus]` has only `url`, `username` and `password` (`src/vibey/domain/config.py:289-296`, parsed by `_parse_bus` at `:623-629`), which is the management-HTTP endpoint. There is no AMQP URL, no queue backend, no invocation mode. The environment overlay a cluster uses is `_SURFACE_ENV_VARS` in `src/vibey/infrastructure/config_loader.py:17-59`.

This lane only declares and validates the keys. Nothing reads them yet: the queue backend is read by #364 (R17); the invocation mode by ADR-0046's invocation-selection work.

**What this lane no longer declares.** The earlier draft also declared per-engine `[loop_services.<engine_id>]` tables and `LoopServicesConfig.for_engine(...)`. Draft ADR-0046 replaces that design: sub-doctrine 8.c (`doctrines.md:196-234`) allows exactly two loops, a single instance per model, and ADR-0046's Migration table maps `[loop_services.<engine_id>]` to `[loop_services.<loop_id>]` with `.seats.<engine_id>` (keys: capacity, models, default model, residency bounds, unload-on-switch, route wait, run-queue wait, supersede grace, stale-lock bound, and the `[loop_services] root`). Those keys belong to ADR-0046's loop-configuration lane (§3, §4, §6; its lane list is still to be filed). Do not add any `loop_services` key here.

Verified at integration `739536ea`.

## Required behaviour
1. `BusConfig` gains three fields:
   - `amqp_url: str | None = None`
   - `vhost: str = "/"`
   - `prefix: str = "vibey"`, which must match `^[a-z][a-z0-9_-]{0,31}$`, else `ConfigError("bus.prefix", ...)`.
2. A new frozen, slotted dataclass `QueueRabbitMqConfig`:

   | field | default | constraint |
   |---|---|---|
   | `delivery_limit: int` | `20` | 1–1000 |
   | `consumer_timeout_seconds: int` | `21600` | ≥ 60 |
   | `wait_tiers_seconds: tuple[int, ...]` | `(1, 5, 30, 120, 600, 3600)` | non-empty, each ≥ 1, strictly ascending |
   | `reconcile_interval_seconds: int` | `30` | ≥ 0 (0 means "every call"; #365's chaos twin uses 0, which the earlier draft's "≥ 1" refused) |
   | `redispatch_after_seconds: int` | `900` | ≥ 60 |
   | `first_claim_wait_seconds: float` | `2.0` | ≥ 0 |
   | `relay_reclaim_seconds: int` | `60` | ≥ 1 (a relay's `sending` row older than this is reclaimed) |
   | `relay_batch: int` | `100` | 1–10000 (rows one relay drain publishes) |
   | `relay_flush_batch: int` | `20` | 1–10000 (rows the after-commit fast path publishes) |
   | `sweep_batch: int` | `500` | 1–100000 (rows one lost-dispatch sweep examines) |
   | `dead_drain_batch: int` | `100` | 1–10000 (dead pointers one reconcile parks) |

   The last five replace constants the downstream lanes would otherwise hard-code (12.c).
3. A new frozen, slotted `QueueConfig(backend: str = "postgres", rabbitmq: QueueRabbitMqConfig = QueueRabbitMqConfig())`. `backend` must be `postgres` or `rabbitmq`. It is parsed from `[queue]` and `[queue.rabbitmq]` by a new `_parse_queue`. `wait_tiers_seconds` is read as a TOML list and stored as a tuple.
4. `EnginesConfig` (`config.py:110-114`, the class at `:111`) gains `invocation: str = "subprocess"` (`subprocess` or `service`), read by `_parse_engines` (`:403-422`) from `[engines] invocation`.
5. **The default-pool rebuild keeps the new field.** `parse_config` rebuilds `EnginesConfig` when `[engines] enabled` is omitted (`config.py:691-695`). That rebuild must carry `invocation=engines.invocation` (use `dataclasses.replace(engines, enabled=tuple(unique_enabled))`), or `[engines] invocation = "service"` would be silently lost whenever `enabled` is omitted.
6. `VibeyConfig` (`config.py:318-342`) gains `queue: QueueConfig = field(default_factory=QueueConfig)`, and `parse_config` (`:652`) fills it with `_parse_queue(data)`.
7. `_SURFACE_ENV_VARS` in `config_loader.py` gains these rows, in this order, directly after the existing `bus` rows (`:48-50`):
   - `("bus", "amqp_url", "VIBEY_BUS_AMQP_URL", str)`
   - `("bus", "vhost", "VIBEY_BUS_VHOST", str)`
   - `("bus", "prefix", "VIBEY_BUS_PREFIX", str)`
   - `("queue", "backend", "VIBEY_QUEUE_BACKEND", str)`
   - `("engines", "invocation", "VIBEY_ENGINE_INVOCATION", str)`

   An empty value counts as unset, as for every existing row (`apply_env_overrides`, `:62-80`).
8. Every error names its dotted key (for example `queue.rabbitmq.delivery_limit`), the way `_optional` does (`config.py:358-364`).
