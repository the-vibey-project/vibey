Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
Sub-doctrine 8.b (`src/vibey_tools/gh/docs/doctrines.md:138-139`) makes self-hosted Forgejo
the default forge, with GitHub and GitLab declared-only; `[platform] kind` defaults to
`forgejo` (`vibey_gh/config.py:288`). `vibey_gh/reconcile.py` lists, comments on, closes,
updates and deletes through `gh` and `github_state`: `update_branch` (`reconcile.py:236-260`),
`open_pull_requests` (263-288), `close_pull_request` (339-360), `notify` (363-386) and
`delete_branch` (389-405), each resolving the repository with `github_state.repository()`
and passing `--repo`/`repos/<name>`. It ignores `[platform]` and would drive GitHub on a
repository whose forge is the sovereign default.

`realign.py:62` runs `reconcile.reconcile(cfg)` after every realign, and `vibey-gh
reconcile-branches` runs it directly, so this is live branch machinery. Once this lane
merges, it follows `[platform]` (see **Depends on**).

When a paid forge is declared, 8.b says it "relays through the sovereign host rather than
replacing it" (`doctrines.md:179-184`). That relay belongs behind `ForgeAdapterInterface`;
this lane keeps every forge call on the interface.

This issue was split: it now covers `reconcile.py` only. Release publication
(`github_release.py`) is child lane 2 below.

## Required behaviour
Every function below resolves (C6.1) and **binds** (C6.2), because each site today calls
`github_state.repository()`. A binding problem raises `RuntimeError(problem)`, except in
`update_branch`, which returns `(False, problem)`.
1. `update_branch(cfg, number, *, forge=None)`: `ok, problem =
   bound.update_change_request_branch(number)` → `(True, "the forge merged the base
   forward")` or `(False, problem)`. (D3: the success detail said "GitHub merged …". The
   docstring's first line becomes forge-neutral too.)
2. `open_pull_requests(cfg, *, forge=None)`: `requests, problem =
   bound.open_change_request_branches(limit=100)`; raise `RuntimeError(problem)` on
   problem; for each request build `BranchFacts(number=request.number,
   branch=request.head_ref, fork=request.cross_repository, unique_commits=0 if not fork
   and not _unsafe(branch) else 1)` — the same facts as today.
3. `close_pull_request(cfg, decision, *, forge=None)`: bind once;
   `bound.comment_on_change_request(decision.number, body)` (the same body text,
   342-347), then `bound.close_change_request(decision.number)`; results ignored, as today.
4. `notify(cfg, decision, *, forge=None)`: bind; `bound.comment_on_change_request(
   decision.number, <the same text as 375-380>)`; result ignored.
5. `delete_branch(cfg, branch, *, fork=False, forge=None)`: the `deletable` guard first,
   exactly as today (it raises `ValueError` before any forge call); then bind;
   `ok, _ = bound.delete_branch(branch)`; return `ok`.

   calls conflicting …") becomes forge-neutral ("the forge refuses …").
7. Drop `from vibey_gh import github_state`. `import subprocess` stays (git).
8. On GitHub the argv is unchanged byte for byte (the adapter runs the same `gh` command
   lines in `cfg.root`); deliberate differences: **D3** the update-branch success detail,
   **D5** a missing `gh` or unreadable output raises `RuntimeError(problem)`.
9. On Forgejo (default) and GitLab the same code runs; a forge without a server-side
   update-branch (GitLab answers NotSupported) returns `(False, <that sentence>)`, and
   `reconcile()` then falls back to `merge_forward` for a non-fork branch, exactly as it
   does for a refusal today.
10. The six functions stay module-level; each carries a one-line reason at its definition

## Conventions this lane relies on (everything needed is here)
**C1 — the adapter contract.** Every adapter verb answers `(value, problem)`. `problem` is
`""` exactly when the forge answered; otherwise `value` is the empty value for its type and
`problem` is one sentence. No verb raises for a failed call, a missing client, a non-2xx
status or unreadable output (`vibey_gh/interfaces/forge_adapter_interface.py:9-16`). A verb
a forge has no equivalent for answers `(<empty>, NotSupported(kind, verb, reason).problem)`,
text `f"{kind.value} does not support {verb}: {reason}"`; the caller reports it like any
other problem (10.f), never special-cases a forge, never skips silently.

**C6 — how this module calls the adapter.**
1. Obtain: each public function gains a keyword-only last parameter
   `forge: ForgeAdapterInterface | None = None` and starts with
   `forge = ForgeSelector().resolve(forge, cfg)` (#332: the injected forge, else
   `select(cfg)`).
2. Bind where today's code called `github_state.repository()`:
   `name, problem = forge.repository_name()`; `if problem: raise RuntimeError(problem)`;
   `bound = forge.for_repository(name)`. Once per public call. On GitHub
   `repository_name()` is `$GH_REPO`, else `gh repo view --json nameWithOwner` — exactly
   `github_state.repository()` (`github_state.py:70-75`).
3. A site that raised keeps raising; a site that returned a bool keeps returning it; a
   site that ignored a result keeps ignoring it.

**C7 — tests (amended for 9.b and the fakes standard).**
- 100% line and branch coverage of `vibey_gh` (`src/vibey_tools/gh/pyproject.toml:64-71`).
  Focused runs need `--no-cov`.
- Substitute only at a declared seam: pass `forge=`. Never `monkeypatch.setattr` a module
  or class attribute (`subprocess.run`, `github_state.gh_json`, a module function),
  never `mock.patch` or `MagicMock`. `monkeypatch.setenv/delenv/chdir` are fine.
- `RecordingForge` (#332): each scripted verb returns its value (or calls it, if callable);
  `repository_name()` defaults to `("o/r", "")`; `for_repository(name)` records and returns
  itself; `.calls` lists `(verb, *args, *sorted(kwargs.items()))`; an unscripted verb raises
  `AttributeError`.
- GitHub argv proofs: the conftest `fake_gh` fixture (`test/conftest.py:87-156`; a real `gh`
  executable first on PATH; `script({...})` keyed by the space-joined argv,
  `invocations()` with argv, cwd and stdin).
- No test leaves the machine unless marked `network` (`test/conftest.py:22-40`). Never
  touch `test/conftest.py`.

**C8 — the formatter trap.** Checked by both `black --line-length 100` + `isort` and the root
`ruff format`. Keep lines ≤ 100 columns (≤ 95 with nested calls); bind long comparisons to a
local before asserting; no implicit string concatenation that would fit on one line; one
argument per line with a trailing comma in multi-line calls; no backslash continuations.
