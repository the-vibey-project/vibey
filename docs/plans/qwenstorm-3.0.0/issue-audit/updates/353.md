## Why
ADR-0044 §2, §3 and §7 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`) put four pure pieces in the domain:

- the RabbitMQ message that points at a `job` row;
- the names of every job exchange and queue;
- the rule that picks a delay tier;
- the configurable prefix (12.c, `src/vibey_tools/gh/docs/doctrines.md:455`), so that vibey's objects stay apart from Plane's Celery queues on a shared broker (`deploy/helm/vibey/values.yaml:248-251`, `plane.amqpUrl`: "Empty means the in-cluster RabbitMQ").

They are pure, so the domain owns them and the 100% domain floor covers them (ADR-0023).

**Only the job side.** The earlier draft also named the loop-service run topology per engine id (`<p>.runs.<engine_id>`, its probe, dead and control objects). Sub-doctrine 8.c (`doctrines.md:196-234`) allows exactly two loops, a single instance per model, and draft ADR-0046 §3 (`specs/ADR-two-loops.md`) replaces those rows with `<p>.runs.<loop>`, `<p>.runs.<loop>.<seat>`, `<p>.runs.<loop>.probe`, a direct `<p>.runs.dlx`, `<p>.runs.<loop>[.<seat>].dead` and `<p>.runs.control`. Those names belong to ADR-0046's run-protocol work (its lane list is still to be filed). Draft ADR-0047 §16 reserves `<p>.surface.*` and draft ADR-0045 uses `<p>.tests.*`; neither collides with `<p>.jobs.*`.

Verified at integration `739536ea`.

## Required behaviour
1. `JOB_DISPATCH_SCHEMA = "vibey.job.dispatch/1"`.
2. `@dataclass(frozen=True, slots=True) class JobDispatch`:
   - `job_id: UUID`
   - `project_id: UUID`
   - `dispatch_seq: int`, which must be ≥ 1
   - `kind: str`, which must be non-empty
   - `not_before: datetime`, which must be timezone-aware

   A violation raises `ValueError` in `__post_init__`. The property `message_id` returns `f"{job_id}:{dispatch_seq}"`.
3. `class JobDispatchCodec`:
   - `encode(d) -> dict[str, object]` has exactly these keys: `schema`, `job_id`, `project_id`, `dispatch_seq`, `kind`, `not_before` (ISO 8601).
   - `decode(raw: Mapping[str, object]) -> JobDispatch` raises the new `MalformedDispatch(VibeyError)` (in `domain/errors.py`) on a wrong or missing schema, a missing or extra key, a wrong type, a naive datetime, or a sequence below 1.
   - `to_bytes(d) -> bytes` is `json.dumps(encode(d), sort_keys=True)` encoded as UTF-8. `from_bytes(b) -> JobDispatch` decodes; invalid JSON or UTF-8 raises `MalformedDispatch`.
   - A module constant `JOB_DISPATCH_CODEC: Final[JobDispatchCodecInterface] = JobDispatchCodec()` (stateless; one instance serves every caller).
4. `class QueueNames(prefix: str = "vibey")` returns exactly these strings. The duration label is `Ns` below 60 seconds, `Nm` for whole minutes below an hour, `Nh` for whole hours, and `Ns` for anything else.

   | method | returns |
   |---|---|
   | `jobs_exchange()` | `"<p>.jobs"` |
   | `project_queue(pid)` | `"<p>.jobs.<pid>"` |
   | `project_key(pid)` | `"job.<pid>"` |
   | `project_bindings(pid)` | `("job.<pid>", "*.job.<pid>")` |
   | `wait_exchange()` | `"<p>.jobs.wait"` |
   | `wait_queue(t)` | `"<p>.jobs.wait.w<label>"` |
   | `wait_key(t, pid)` | `"w<label>.job.<pid>"` |
   | `wait_binding(t)` | `"w<label>.#"` |
   | `dead_exchange()` | `"<p>.jobs.dlx"` |
   | `dead_queue()` | `"<p>.jobs.dead"` |

   There is no `runs_*`, `run_*`, `probe_*` or `control_*` method.
5. `class WaitTierPlan(tiers_seconds: tuple[int, ...])` validates the tiers (non-empty, each ≥ 1, strictly ascending) and raises `ValueError` otherwise. `choose(remaining: timedelta) -> int | None` returns:
   - `None` when `remaining <= 0`;
   - otherwise the largest tier ≤ `remaining` (in seconds);
   - or the smallest tier when `remaining` is shorter than every tier.
6. Nothing in the module reads a clock, performs I/O or uses async.
