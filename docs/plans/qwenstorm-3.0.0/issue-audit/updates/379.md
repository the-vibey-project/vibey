Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §16 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md:571-592`) says a real broker is needed in CI for three things: the contract suite (R18, #365), the topology and relay integration tests (R12, R13), and the RabbitMQ chaos twin. Without one, the ADR's *Verification owed* list is never discharged. Those tests are marked `integration` and skip unless `VIBEY_TEST_AMQP_URL` is set. The default tier (`-m "not integration and not paid"`) needs no outside service, so the broker belongs only to the job that runs the integration tier.

The cluster must also prove four things against the pinned broker image (`deploy/helm/vibey/values.yaml:439-442`):

- the core broker exists (#376);
- each loop's **router** and each declared model's **seat host** consumes its queue, **exactly once**. Sub-doctrine 8.c (`src/vibey_tools/gh/docs/doctrines.md:196-234`) runs "a single instance per model", and ADR-0046 §3 (`specs/ADR-two-loops.md:140-157`) enforces it with exclusive consumers on `vibey.runs.<loop>` and `vibey.runs.<loop>.<seat>`;
- a second instance of a model is refused;
- the RabbitMQ `ScaledObject` becomes Ready (#378).

The original lane asserted one Deployment and one queue per engine id, including `opencode`. That topology is superseded by ADR-0046, and 8.b as amended by #392 repeals OpenCode (`doctrines.md:128-137`).

## Required behaviour
1. **The broker service, on the integration tier.** Today the `gates` job (`.github/workflows/ci.yml:30-94`) runs the whole suite, `integration` included, because `addopts` excludes only `paid` (`pyproject.toml:262`). Add to that job:
   - a service `rabbitmq` with image `rabbitmq:4-management-alpine@sha256:b839b492a91788a1d9406ef3ec0e1d8a8448032c48148a54a9e0c68ed66cde9b`, the same tag and digest as `values.yaml:439-442`;
   - `RABBITMQ_DEFAULT_USER: vibey` and `RABBITMQ_DEFAULT_PASS: vibey`, because the default `guest` account refuses non-loopback connections;
   - ports `5672:5672` and `15672:15672`;
   - health options `--health-cmd "rabbitmq-diagnostics -q ping" --health-interval 10s --health-timeout 10s --health-retries 12`;
   - job env `VIBEY_TEST_AMQP_URL: amqp://vibey:vibey@localhost:5672/`.

   If lane `fakes-ci-no-services` has already split the integration tier into its own job, the service and the variable go on **that** job, never on the job that runs the default tier.
2. **cluster-smoke.** After "Contract - the worker picks up a project created in-cluster" (`ci.yml:956-966`), add:
   - `Contract - each loop's router and each model's seat host consume exactly once`:
     - `kubectl wait --for=condition=available deployment/vibey-vibey-sovereignloop-router deployment/vibey-vibey-sovereignloop-seat-gpt-oss-20b -n vibey --timeout=5m` (the names #377 renders);
     - then, retrying for up to 2 minutes, `kubectl exec -n vibey deploy/vibey-vibey-rabbitmq -- rabbitmqctl list_queues --quiet --no-table-headers name consumers`;
     - assert that `vibey.runs.sovereignloop` and `vibey.runs.sovereignloop.gpt-oss-20b` each show **exactly 1** consumer;
     - assert that no queue whose name starts with `vibey.runs.paidloop` exists, because paidloop is declared-only (8.b).
   - `Contract - a second instance of a model is refused (8.c)`:
     - `kubectl exec -n vibey deploy/vibey-vibey-sovereignloop-seat-gpt-oss-20b -- timeout 60 vibey loop-service --loop sovereignloop --role seat --seat gpt-oss:20b`, capturing its output and exit code;
     - assert that the exit code is neither 0 nor 124 (the timeout), and that the output names 8.c.
     Use the flag names that ADR-0046's CLI lane defines. If they differ from these, use them and say so in the commit body.
   - `Contract - the RabbitMQ ScaledObject reconciles`. Place it after "Contract - the ScaledObject reconciles against real Postgres" (`:973-991`), which installs KEDA, and before "Contract - a worker drains promptly on SIGTERM" (`:993`):
     - `id=$(kubectl exec -n vibey deploy/vibey-vibey-worker -- vibey status --json | python3 -c 'import json,sys; print(json.load(sys.stdin)["project_id"])')`. `vibey status --json` prints `project_id` (`src/vibey/cli/main.py:709-740`);
     - `helm upgrade vibey deploy/helm/vibey -n vibey --set keda.enabled=true --set queue.backend=rabbitmq --set worker.project="$id" --wait --timeout 5m`;
     - wait for the `ScaledObject` `vibey-vibey-worker` to be `Ready=True`, with the same loop as `:980-988`.

     The drain contract then upgrades with `--set keda.enabled=false` exactly as today, which returns the release to the chart defaults.
3. `vibey-vibey-rabbitmq` stays in the availability list (`:904-935`). No job is renamed: `noloss` is a required check (`ci.yml:104`, `.vibey-gh.toml`).
