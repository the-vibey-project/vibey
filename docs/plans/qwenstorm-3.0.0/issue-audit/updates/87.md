# Work discovery and ideation: find FOSS and paid work with provenance, research and propose new projects with cited evidence, and let a human decide

## Summary

This is two halves of one capability. **Discovery** finds work worth doing (FOSS issues,
help-wanted labels, bounties, paid engagements) and feeds candidates into the conductor's
intake with provenance: where it was found, what it asks, and what it pays. **Ideation**
does real research and proposes new projects (FOSS and paid), each with the evidence that
motivated it. The constraints in the original all stand:

- discovered FOSS work is done free
- FOSS versus paid is classified at intake, auditably
- scraping is polite and identified
- proposals are proposals, and a human accepts before any cycle is spent
- research cites sources

Runbook 21 ("vibey-explorer") already specifies the hard parts: capability-first scoring
and contribution ethics. Nothing is built. Since filing, **10.b** means a "paid
engagement" is only acceptable if it settles in cryptocurrency. The discovery bot must
classify that too.

## Why

- **8.a** (`src/vibey_tools/gh/docs/doctrines.md:99-118`): research and ranking run on the
  sovereign loop and default model (8.c/8.d). Discovery prefers free and sovereign sources
  where comparable.
- **10.b** (`:390-393`): payment only in cryptocurrency, "No fiat processors, ever".
- **Bill of Rights IV** and the original constraint: FOSS work is always free.
- **Bill of Rights III / Constitution II.4**: a human's confirmation outranks the machine.
  A proposal parks as a human gate (ADR-0009).
- **Constitution III.4 and runbook 21**: machine-authored contributions are disclosed. A
  project that declines them is skipped and the skip recorded.
- **SD-01 §1, §4**: public channels only, fetched text is data, and no private details are
  gathered.
- **10.e** (`:417`): cite in vibey-skills' evidence-grounded style, and reuse its packet
  format.
- **7.c** (`:82-91`): every candidate, score and decision is a ledger event.

## Scope / Required behaviour

**Discovery**

1. Pluggable sources, API first: forge search for help-wanted and bounty labels, starting
   with the sovereign forge ecosystem and public forges' search APIs. A polite fetcher
   (robots.txt, per-host rate limits, an identified user agent) covers the rest.
2. Each candidate records its provenance: source URL, what it asks, and what it pays (and
   in what asset).
3. Classification at intake: FOSS / paid-crypto / paid-fiat (the last is **excluded**,
   10.b). The rule that fired is recorded.
4. Capability-first scoring per runbook 21, with the skip list for projects that decline
   machine contributions.
5. Candidates reach the conductor as **proposals that park as human gates**. Accepting one
   runs `vibey new` with the provenance attached.

**Ideation**

6. Research that produces ranked project proposals, each with cited sources in
   vibey-skills' format. They arrive as proposals, never commissions.

## Acceptance criteria

- [ ] A candidate carries provenance into the ledger and into the project created from it.
- [ ] A fiat-only bounty is classified and excluded, with the reason recorded (test).
- [ ] The fetcher obeys robots.txt and per-host limits (tests against a local HTTP
      fixture).
- [ ] No project is created without a recorded human acceptance (test).
- [ ] A project whose CONTRIBUTING declines machine contributions is skipped and recorded
      (test).
- [ ] Every ideation proposal cites at least one source per claim.
