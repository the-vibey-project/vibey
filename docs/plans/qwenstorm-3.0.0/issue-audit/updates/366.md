Closing as superseded by draft ADR-0046 (two loops, `sovereignloop` and `paidloop`), whose §10 table lists `domain/run_protocol.py` as "replaces R19". **Nothing from this issue was merged.**

Why: this protocol addresses one loop service per engine id (`vibey.runs.<engine_id>`, ADR-0044 §13). Sub-doctrine 8.c as ratified by #392 (`src/vibey_tools/gh/docs/doctrines.md:196-234`) allows exactly two loops, a single instance per model, and two queue-borne rotation layers. ADR-0046 §3 therefore re-keys the wire to `<loop>` / `<loop>.<seat>`, adds the `vibey.run.route/1` and `vibey.run.routed/1` schemas, adds `loop_id`, `engine_id` and `route_id?` to the run request and `engine_id`/`model` to `RunAccepted`, adds `RunStatus.UNROUTABLE`, and adds a `SUPERSEDE` control command.

What carries over into ADR-0046's run-protocol lane:
- the five ADR-0044 schemas as frozen, slotted, timezone-aware dataclasses (ADR-0046 §3, "Messages");
- the strict codec that refuses any extra key — `resets_at`, `capacity`, `capacity_state`, `credits`, `complete`, `success` — plus the property test that no capacity key survives encoding (non-negotiable 2);
- `RunResult` with no completion, success or capacity field (non-negotiable 3);
- the argument policy (`args[0]` is `run`/`resume` for runs; `--version`, `doctor`, `run --help` for probes), now applied per adapter binary of the loop (ADR-0046 *Security impact*).

Evidence: `specs/ADR-two-loops.md` §3 (lines 140–191) and §10 (line 302); ADR-0044 §13 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md:370-477`). ADR-0046's lanes (L01–L39) are still to be filed; the replacing issue will be linked here when it is.
