## Why
Sub-doctrine 10.e (`src/vibey_tools/gh/docs/doctrines.md:417`): a capability gap is closed by teaching the family, not by writing a private copy in one consumer. The family's only consumer machinery is Azure Service Bus (`vibey_bootstrap/servicebus/consumer_wrapper.py:26-35` for its Protocols, `:53-92` for `_settle`), and it is sync. Its settle vocabulary is `complete`, `abandon` and `dead_letter`. ADR-0044 §14 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`) puts the RabbitMQ transport in `vibey_bootstrap.amqp` under that vocabulary, so that vibey's queue backend (#359–#363), the test harness queue (draft ADR-0045) and the surface lanes (draft ADR-0047) all use one client and one in-memory double.

This lane ships the part every later lane's unit tests need first: the contract (interfaces), the value types, and `InMemoryAmqpClient`, a real in-memory broker with no network. It imports nothing from `aio_pika`. Child 2 adds the aio-pika transport behind the same contract.

Verified at integration `739536ea`.

## Required behaviour
1. **`settings.py`:** `AmqpSettings`, a frozen dataclass:
   - `url: str`, which must start with `amqp://` or `amqps://`, else `ValueError`;
   - `connection_name: str = "vibey"`;
   - `heartbeat_seconds: int = 60`;
   - `publish_timeout_seconds: float = 10.0`;
   - `redacted_url() -> str` replaces the password with `***` (a URL with no password is returned unchanged).
2. **`properties.py`:** `AmqpProperties`, a frozen dataclass: `message_id: str | None = None`, `correlation_id: str | None = None`, `reply_to: str | None = None`, `type: str | None = None`, `content_type: str = "application/json"`, `delivery_mode: int = 2`, `priority: int | None = None`, `headers: Mapping[str, object] = field(default_factory=dict)`.
3. **`errors.py`:** `AmqpError(Exception)`, `AmqpPublishError(AmqpError)`, `AmqpNotConnected(AmqpError)`.
4. **`interfaces/client_interface.py`:** two `@runtime_checkable` Protocols.
   - `AmqpDeliveryInterface`: attributes `body: bytes`, `properties: AmqpProperties`, `routing_key: str`, `redelivered: bool`, `delivery_count: int` (read from the `x-delivery-count` header, 0 when absent); async `complete() -> bool` (= `basic.ack`), `abandon() -> bool` (= `basic.nack(requeue=True)`), `dead_letter() -> bool` (= `basic.reject(requeue=False)`). Each returns `True` when it settled and `False` when the delivery was already settled.
   - `AmqpClientInterface`: async `connect()`, `close()`, `declare_exchange(name, kind)` (`kind` in `direct`, `topic`, `fanout`; durable), `declare_queue(name, *, arguments=None, durable=True, exclusive=False, auto_delete=False) -> str` (returns the real name; `""` asks for a server-named queue), `bind(queue, exchange, routing_key)`, `publish(exchange, routing_key, body, properties, *, mandatory=True)`, `consume(queue, *, prefetch, handler) -> str` (returns the consumer tag), `cancel(tag)`, `get(queue) -> AmqpDeliveryInterface | None` (`basic.get` without auto-ack).
5. **`memory.py`:** `InMemoryAmqpClient` implements `AmqpClientInterface` with no network, and its deliveries implement `AmqpDeliveryInterface`:
   - direct, topic (`*` matches one dot-separated word, `#` matches zero or more) and fanout routing; FIFO queues;
   - `consume` pushes to the handler up to `prefetch` unsettled messages per consumer, and pushes the next one as each settles;
   - `abandon` requeues at the head of the queue and increments `x-delivery-count`;
   - a queue declared with `x-delivery-limit` dead-letters, to its `x-dead-letter-exchange` with the routing key kept, any message whose count would exceed the limit;
   - `dead_letter()` routes to the queue's dead-letter exchange (dropped when it has none);
   - `simulate_channel_close(tag)` returns every unsettled delivery of that consumer to its queue, with its count incremented, and cancels the consumer;
   - `expire(queue)` dead-letters every message of a queue declared with `x-message-ttl` to its dead-letter exchange, keeping the routing key. Tests call it instead of sleeping;
   - `published` is a list of `(exchange, routing_key, body, properties)` for assertions;
   - a mandatory publish that routes to no queue raises `AmqpPublishError`;
   - declaring the same exchange or queue twice with equal arguments is a no-op; with different arguments it raises `AmqpError` (the broker's `PRECONDITION_FAILED`);
   - every settle calls `vibey_bootstrap.heartbeat.record_message_settled()` and every push calls `record_consumer_iteration()` (`vibey_bootstrap/heartbeat/__init__.py:41`, `:51`), as child 2's real client does.

   Keep each queue's messages and consumers as plain per-queue lists, so the later lanes that teach this client queue depth, consumer count, exclusive consume and an exclusive-queue lease (ADR-0046 §10 lane L21, ADR-0045 T21, ADR-0047 S07) can add them without restructuring it.
6. **`__init__.py`** exports `AmqpSettings`, `AmqpProperties`, the three errors, the two interfaces and `InMemoryAmqpClient`. Its module docstring states the 10.e reason: "The family had no AMQP client; the management HTTP API's `get` is a diagnostics endpoint with at-most-once, prefetch-free semantics (vibey/infrastructure/bus/rabbitmq.py). ADR-0044 §14."
7. **Packaging.** `src/vibey_tools/bootstrap/pyproject.toml` `[tool.setuptools] packages` (`:196-249`) gains `"vibey_bootstrap.amqp"` and `"vibey_bootstrap.amqp.interfaces"`, directly after `"vibey_bootstrap.alerts"`. `test/test_packaging.py` fails without them.

### 2. feat(bootstrap): AmqpClient, the aio-pika transport behind vibey_bootstrap.amqp
New `vibey_bootstrap/amqp/client.py` and `delivery.py`, and their exports in `__init__.py`. `AmqpClient(settings, *, connector=aio_pika.connect_robust)`: the connector is injected so unit tests pass a fake connector object, with no patching. `connect()` opens a robust connection with `client_properties={"connection_name": ...}` and `heartbeat`, plus one publish channel with `publisher_confirms=True`; any other method before `connect()` connects lazily; `close()` closes it. `declare_exchange`/`declare_queue`/`bind` map to `channel.declare_exchange`, `channel.declare_queue`, `queue.bind`. `publish(..., mandatory=True)` waits for the confirm and raises `AmqpPublishError` on a nack, a return (unroutable while mandatory) or a timeout (`publish_timeout_seconds`). `consume` opens a dedicated channel per consumer with `set_qos(prefetch_count=prefetch)`, calls `handler(AmqpDelivery)` per message and `record_consumer_iteration()` per message; `cancel(tag)`; `get(queue)` is `queue.get(no_ack=False, fail=False)`. `AmqpDelivery` wraps `aio_pika.abc.AbstractIncomingMessage`: `complete` = `ack()`, `abandon` = `nack(requeue=True)`, `dead_letter` = `reject(requeue=False)`, each calling `record_message_settled()` and returning `False` when already settled. Tests: `test/amqp/test_client_unit.py` (a fake connector, channel, exchange, queue and message written as small classes in the test module: declares, publishes and waits for the confirm, raises on a nack/return/timeout, sets qos per consumer, maps the three settles) and `test/amqp/test_client_integration.py` (`@pytest.mark.integration`, skipped without `VIBEY_TEST_AMQP_URL`: `test_round_trip_against_a_real_broker`, `test_quorum_delivery_limit_dead_letters_after_channel_closes`). Checks as child 1, plus the integration run when `VIBEY_TEST_AMQP_URL` is set. The unit tests must cover every line of `client.py` and `delivery.py` (tenant 100% floor). Depends on #350 (R03, aio-pika locked) and child 1.
