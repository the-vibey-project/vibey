Part of the **QwenStorm for 3.0.0**. A local sovereign lane (qwenloop until ADR-0046's rename lands) implements this issue; the result is reviewed and verified before it becomes a pull request.

## Why
ADR-0044 §2 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`) names every exchange and queue the job backend uses, and fixes their arguments:

- quorum work queues with a delivery limit, at-least-once dead-lettering and a per-queue consumer timeout;
- TTL wait tiers that dead-letter back into the dispatch exchange;
- one dead queue.

Declaring them in code at start is sub-doctrine 12.c (`src/vibey_tools/gh/docs/doctrines.md:455`): the topology is declared, not clicked. This lane also carries the first integration checks of the upstream facts the ADR says it owes, against the pinned `rabbitmq:4-management-alpine` (`deploy/helm/vibey/values.yaml:437-442`). Only the job topology is here; the loop-service run topology is draft ADR-0046 §3's (its lane list is still to be filed).

It also sets up `tests/infrastructure/queue/` for the lanes after it. That directory is not under `tests/infrastructure/db/`, whose conftest marks every test `integration` (`tests/infrastructure/db/conftest.py:17-19`). So its conftest must mark any test that reaches PostgreSQL or a real broker `integration` itself; otherwise the default run (`-m "not integration and not paid"`) would need PostgreSQL.

Verified at integration `739536ea`.

## Required behaviour
1. `class RabbitMqJobTopology(client: AmqpClientInterface, names: QueueNamesInterface, settings: QueueRabbitMqConfigInterface)` (the interfaces from #351, #353 and #348).
2. `async def declare_base(self) -> None` declares:
   - exchanges `names.jobs_exchange()` (topic), `names.wait_exchange()` (topic) and `names.dead_exchange()` (fanout);
   - the queue `names.dead_queue()` with `{"x-queue-type": "quorum"}`, bound to the dead exchange with key `""`;
   - for every tier in `settings.wait_tiers_seconds`, the queue `names.wait_queue(t)` with `{"x-queue-type": "classic", "x-message-ttl": t * 1000, "x-dead-letter-exchange": names.jobs_exchange()}`, bound to the wait exchange with `names.wait_binding(t)`.

   It is idempotent, and runs its declarations once per instance.
3. `def project_arguments(self) -> dict[str, object]` returns exactly:
   ```python
   {"x-queue-type": "quorum", "x-delivery-limit": settings.delivery_limit,
    "x-dead-letter-exchange": names.dead_exchange(),
    "x-dead-letter-strategy": "at-least-once", "x-overflow": "reject-publish",
    "x-consumer-timeout": settings.consumer_timeout_seconds * 1000}
   ```
4. `async def declare_project(self, project_id: UUID) -> str` calls `declare_base()` if needed, then declares `names.project_queue(pid)` with `project_arguments()`, binds both of `names.project_bindings(pid)` to the jobs exchange, and caches the project id. It returns the queue name.
5. `.importlinter`: `vibey.infrastructure.queue.interfaces` joins the `source_modules` of `[importlinter:contract:infrastructure-interfaces-declare-only]` (`.importlinter:108-133`).
6. `tests/infrastructure/queue/conftest.py`:
   - re-exports the database fixtures so later lanes can use PostgreSQL here: `from tests.infrastructure.db.conftest import database_url, pg_pool, pg_conn, migrated_pool, project_id  # noqa: F401`;
   - provides `memory_amqp` (a fresh `InMemoryAmqpClient`) and `amqp_url` (skips unless `VIBEY_TEST_AMQP_URL` is set);
   - defines `pytest_collection_modifyitems` that adds `pytest.mark.integration` to every item whose `fixturenames` include any of `database_url`, `pg_pool`, `pg_conn`, `migrated_pool`, `project_id` or `amqp_url`. Items that use only `memory_amqp` stay unmarked.
7. **Registry.** If `tests/fakes/registry.py` exists on the integration branch when the lane starts, register `AmqpClientInterface → InMemoryAmqpClient` in `REGISTRY` and add `AmqpClientInterface` to `DRIVER_SEAMS` (this is the first root lane to consume the seam).
