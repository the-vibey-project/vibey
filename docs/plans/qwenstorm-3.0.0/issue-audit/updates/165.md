# vibeyos: an AI-first, fully sovereign Arch Linux flavour for vibey to live in, starting with making vibey first-class on Arch

## Summary

The operator wants **vibeyos**: "a new flavor of arch linux that is AI-first rather than
AI-last and fully sovereign so vibey has an operating system to live in that is FOSS
forever". Since this was filed, sub-doctrine **8.h** has made **Arch Linux the default
sovereign operating system**: "every feature works on Arch Linux, the installer serves it,
and every change is proven on it". That gives the epic a first rung that is concrete,
doctrinal and unmet. vibey is not yet first-class on Arch: the installer has no `pacman`
path, there is no Arch CI job, and no AUR package exists. Only after that rung does a
distribution make sense: a declared archiso profile, a signed package repository, a
reproducible image build, and a first-boot that brings up the sovereign stack. The
"AI-first" meaning of the distribution needs the operator's definition before design.

## Why

- **8.h** (`src/vibey_tools/gh/docs/doctrines.md:326-333`): Arch Linux is the default
  sovereign OS, and macOS the default paid OS, with the same standing. A change working on
  only one is not done.
- **8.a / 8.b** (`:99-194`): sovereign, self-hosted and free by default. An OS image could
  carry every sovereign surface of 8.b ready to run.
- **8.d** (`:236-269`): the default local model is chosen by the machine it runs on. An OS
  can size and preload it.
- **2.b** (`:30`) and **ADR-0019**: installable wherever users are. The AUR is in runbook
  09's channel list.
- **12.c** (`:455`): an OS profile is declared state (archiso profile, package lists,
  keys) reconciled from the repository.
- **10.a** (`:385-388`) and **Bill of Rights V**: "FOSS forever", with no lock-in.
- **12.b** (`:435-447`): if "vibey ships its own OS" binds future decisions, it is a
  sub-doctrine as well as an ADR.

## Current state

Evidence cutoff: integration tree `cce648ef`, read 2026-09-22.

- **No vibeyos artifact:** `git grep -i vibeyos` returns nothing. There is no archiso
  profile, PKGBUILD, package repository or image pipeline. `deploy/` has only `docker` and
  `helm`.
- **8.h's installer requirement is unmet:** `vibey install` has one target, `--postgres`
  (`src/vibey/cli/main.py:1155-1182`). Its implementation supports `brew`, `apt-get` and
  `dnf` only (`src/vibey/infrastructure/postgres.py:248-253`, `:305`). There is no
  `pacman`. QwenStorm #391 ("vibey install sets up local Ollama and this era's default
  model") is open.
- **Rung 0 is already being specified:** the QwenStorm draft "`vibey install` installs
  everything a developer needs on the two default OSes, from one declared catalogue"
  (storm spec `specs/ADR-installer.md`, proposed, unfiled). Its lane specs are queued in
  `specs/installer-queue.txt`: catalogue, host runner, service runner, orchestrator,
  PostgreSQL, Ollama (#391), container runtime, toolchain, broker/cache, VS Code, paid
  engine CLIs, composition, CLI, and doctor. It covers pacman (official `extra`) and AUR
  (through `paru`/`yay` as the user, never root) on Arch, and Homebrew on macOS. It fixes
  the missing pacman path (`specs/installer-postgres.md`). It does not add an Arch CI job
  or an AUR package *of vibey itself*.
- **No Arch proof in CI:** no workflow job runs on an Arch Linux container. Runbook 09
  lists AUR as "Open" (`docs/runbooks/expansion/09-package-managers.md:26`, `:51`), and
  ADR-0019 lists Arch AUR among self-served Linux channels
  (`docs/architecture/decisions/0019-installable-wherever-its-users-are.md:47`).
- **The sovereign stack already exists to put on an image:**
  - the Helm chart with every 8.b surface (ADR-0043)
  - the Ollama chart (`deploy/helm/vibey/templates/ollama.yaml`)
  - the sovereign surface adapters with in-memory fakes under `src/vibey/infrastructure/`
- The 2026-09-17 triage's scoping points stand: new product line, trademark and licence
  posture, build infrastructure, hosting large artifacts.

## Scope / Required behaviour

**Rung 0: vibey is first-class on Arch Linux (8.h).** This needs no new product decision.

1. `vibey install` serves Arch through `pacman` for every target it supports (PostgreSQL
   today, and Ollama/model and RabbitMQ as #391/#380 add them).
2. CI proves install and a smoke run on an Arch Linux container, beside macOS.
3. A PKGBUILD lives in the repository and publishes to the AUR from the release pipeline
   (runbook 09 item 5).

**Rung 1: decide vibeyos.** This needs an ADR (and a sub-doctrine if it binds conduct)
covering: what "AI-first" means as testable properties, in-repo or separate, desktop,
server or both, hardware targets, licence and trademark posture, and where large images
are hosted (sovereign: the blob surface, Garage).

**Rung 2 onward, if rung 1 says go:**

4. A declared archiso profile.
5. A signed package repository (keys in OpenBao, 8.b).
6. A reproducible image build in CI with a QEMU boot test.
7. A first boot that installs and starts the sovereign stack and the default model sized
   to the machine (8.d), and proves one vibey run end to end.

## Acceptance criteria

- [ ] Rung 0: `vibey install --postgres` succeeds on a clean Arch container in CI. The
      AUR package installs `vibey` and `vibey doctor` passes. Both recorded as CI evidence.
- [ ] Rung 1: ADR (and, if needed, a ratified sub-doctrine) merged by the operator.
- [ ] Rung 2+: an image built reproducibly from the repository boots in QEMU in CI and
      completes a scripted vibey run with no network beyond the local machine.

## Proposed child issues

1. **File and land the installer lanes** from the storm draft (`specs/ADR-installer.md`,
   `specs/installer-*.md`, the order in `specs/installer-queue.txt`). The PostgreSQL lane
   is the exact pacman fix: `pacman`, `initdb` and a role. This is the bulk of rung 0 and
   needs no new design here.
2. **ci: an Arch Linux container job** that runs `vibey install --postgres`, the gates'
   quick suite and `vibey doctor`. Today CI runs on `ubuntu-latest`, plus `macos-latest`
   rows for some tenant jobs (`.github/workflows/ci.yml:413-437`). Nothing runs on Arch.
3. **build(packaging): a PKGBUILD in the repository and AUR publication from the release
   workflow.** Design first: how the AUR git push is authorised (runbook 09's "AUR
   account + ssh key").
4. **Design needed first — ADR: vibeyos scope** (rung 1).
5. **Design needed first — archiso profile and signed repository** (after 4).
6. **Design needed first — image build, hosting and QEMU boot test** (after 5).

## Open questions for the operator

1. **What makes an OS "AI-first"?** For example: the default model preloaded and sized to
   the hardware, the sovereign stack running at first boot, vibey as a system service, an
   agent shell? Which of these is the point?
2. **Desktop, server or both?** Which hardware (the M5 laptop class of 8.d, or x86_64
   workstations and servers)?
3. **In this repository or a new one?** ADR-0021 made the family one tree.
4. **Licence and name:** redistributing Arch packages brings their licences, and Arch
   Linux's trademark policy applies to a derivative's name. Should the name and posture be
   checked first?
5. **Is rung 0 (first-class on Arch) enough for now**, with vibeyos itself later?
