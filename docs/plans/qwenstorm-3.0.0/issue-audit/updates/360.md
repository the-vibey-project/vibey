## Why
ADR-0044 §4 and §7 (`docs/architecture/decisions/0044-job-queue-port-and-loop-services.md`). The outbox rows #357 and #358 write must reach the broker with publisher confirms. The relay is what gives at-least-once publish:

- a due dispatch goes straight to the dispatch exchange;
- a future dispatch goes to the largest wait tier no longer than its remaining delay;
- a row is marked sent, and the job's `dispatched_at` stamped, only after the confirm;
- rows a crashed relay left in `sending` are reclaimed through #352's `reclaim_stale`.

Two classes keep the broker half free of the database: `DispatchPublisher` (routing and confirm; no database) and `DispatchRelay` (the outbox drain; reaches PostgreSQL only through `PostgresOrmInterface.autocommit()`, `specs/orm-tables.md:59-63`). #363's unit tests then run the real publisher over `InMemoryAmqpClient` with an in-memory relay fake, and need no database. Every tunable is a key (12.c, `src/vibey_tools/gh/docs/doctrines.md:455`): the reclaim age and both batch sizes come from `QueueRabbitMqConfig` (#348).

Verified at integration `739536ea`.

## Required behaviour
1. `class DispatchPublisher` is constructed with `client: AmqpClientInterface`, `names: QueueNamesInterface`, `topology: RabbitMqJobTopologyInterface`, `tiers: WaitTierPlanInterface`, `clock: Clock` (`vibey.application.interfaces.system`, `:11`). `async def publish(self, dispatch: JobDispatch) -> None`:
   - `remaining = dispatch.not_before - clock.now()`; `tier = tiers.choose(remaining)`;
   - `await topology.declare_project(dispatch.project_id)`;
   - when `tier is None`, publish to `names.jobs_exchange()` with key `names.project_key(pid)`; otherwise to `names.wait_exchange()` with key `names.wait_key(tier, pid)`;
   - the body is `JOB_DISPATCH_CODEC.to_bytes(dispatch)`; the properties are `message_id=dispatch.message_id`, `type="job.dispatch"`, `correlation_id=str(DELIVERY_CORRELATION.for_project(pid))` (`src/vibey/domain/correlation.py:63`, `:79`) and `delivery_mode=2`;
   - it raises `AmqpPublishError` on a failed confirm.
2. `class DispatchRelay` is constructed with `orm: PostgresOrmInterface`, `publisher: DispatchPublisherInterface`, `records: DispatchingJobRecordsInterface`, `settings: QueueRabbitMqConfigInterface`, `logger: Logger` (`vibey.application.interfaces.observability`, `:23`), `clock: Clock`.
   - `async def publish(self, dispatch) -> None` delegates to the publisher (#363 re-delays through it).
   - `async def drain(self, limit: int | None = None) -> int`: in `async with self._orm.autocommit() as conn`, build `AsyncOutbox(conn, table="job_outbox", track_claims=True)`, call `reclaim_stale(timedelta(seconds=settings.relay_reclaim_seconds))`, then an `AsyncOutboxDrainer` whose sender decodes the payload with `JOB_DISPATCH_CODEC.decode`, calls `publisher.publish`, then `records.mark_dispatched(job_id, dispatch_seq)`. It drains `limit or settings.relay_batch` rows and returns the count sent. It logs `queue.relay_drained` at `debug` with `sent`, `reclaimed` and `elapsed_ms` (8.g).
   - `async def flush_soon(self) -> None` calls `drain(settings.relay_flush_batch)`, logs any exception at `warning` as `queue.relay_failed`, and never raises. It is the best-effort fast path after a commit.
3. A publish that fails leaves the row back at `pending` with `attempt_count + 1`, via #352's `mark_failed`, and `dispatched_at` untouched.
4. **Interfaces:** `DispatchPublisherInterface` and `DispatchRelayInterface` (`publish`, `drain`, `flush_soon`) in `src/vibey/infrastructure/queue/interfaces/dispatch_relay_interface.py`.
5. **The in-memory fake** in `tests/fakes/queue.py`: `FakeDispatchRelay(publisher: DispatchPublisherInterface, writer: FakeDispatchOutboxWriter, records: FakeDispatchingJobRecords)` implements `DispatchRelayInterface`. `drain(limit=None)` takes the writer's written-but-unsent dispatches in order, calls `publisher.publish` (the **real** publisher over `InMemoryAmqpClient`), then `records.mark_dispatched`, and marks each sent; a publish that raises leaves that dispatch unsent and counts nothing. `flush_soon` swallows. `publish` delegates. `fail_next: int` makes the next N publishes raise `AmqpPublishError`. Register it (`REGISTRY`, `DRIVER_SEAMS`).
