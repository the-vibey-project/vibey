# Continuation prompts

A project is alive while someone can pick it up. These prompts are written so that **anyone
with any capable AI agent** — including the sovereign default, gpt-oss on Ollama — can pick
vibey up cold: no memory of past sessions, no knowledge of who built it, no access to anyone
who did. Each one is self-contained. Paste it into an agent whose working directory is a
clone of this repository, and it says what to read, what to run, what never to do, and how
to know the work is done. Sub-doctrine 10.l is the law they keep, and
[ADR-0080](../architecture/decisions/0080-continuation-prompts.md) is how.

They are not left to rot. `scripts/continuation_prompts.py check` runs on every pull
request and fails when a prompt names a file, command or workflow that no longer exists, when
a lane or an agent skill is covered by no prompt, or when a page's generated state is stale.
And GitHub runs them: every week the
[Continuation prompts](https://github.com/the-vibey-project/vibey/actions/workflows/continuation-prompts.yml)
workflow keeps every scheduled workflow enabled, refreshes these pages, and runs each prompt
on a GitHub-hosted runner with an open-weights model — the *act* prompts may open draft pull
requests, the *drill* prompts verify that every instruction still holds and report what
does not. Nothing it runs can merge, approve, release, delete, or touch a ruleset or a secret.

## If everything else is gone

Start with [Rebuild](rebuild.md). It assumes nothing survives but a copy of the code — a
clone, a release's source distribution, or the book — and walks back from there.
