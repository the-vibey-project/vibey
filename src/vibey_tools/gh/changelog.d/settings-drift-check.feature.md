**`vibey-gh check --ci` now reports repository settings that drifted from `[repository_profile]`** (#1594, part of #145). Each declared setting whose live value differs prints as `settings drift: <field> is <live>, declared <declared>`: the flags, the squash-commit title and message when declared, the description and the topic set. It is read-only and advisory by default; `[repository_profile] fail_check = true` makes drift fail the build. A setting the forge withheld from the token, or a read that could not be made (no `gh`, no token, another forge), prints as `not surveyed` and is never counted as matching. The list of settings is now one declaration shared by the workflow that writes them and the audit that reads them.
