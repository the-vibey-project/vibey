**A Bitbucket transport for the forge standard** (`vibey_gh/bitbucket_transport.py`, behind `ForgeTransportInterface`; first slice of #298). `BitbucketTransport` talks to the Bitbucket Cloud 2.0 REST API with stdlib `urllib` only, like the Forgejo and GitLab transports: an access token is sent as a Bearer credential, a `username:app-password` as HTTP Basic, and an empty token sends no credential. A GET that answers a listing is followed to its last page and returned as one list; the walk follows a `next` link only if it stays on the transport's own host over HTTPS (the request carries the credential), stops at 100 pages with a problem rather than returning a partial list, and fails whole if any page fails. HTTP errors become a problem carrying Bitbucket's own message. Nothing selects it yet: `kind = "bitbucket"` is still refused at config load until the adapter exists.
