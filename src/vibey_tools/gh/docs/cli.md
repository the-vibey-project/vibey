# CLI reference

All commands return zero on success and a nonzero status on validation, policy, or
transport failure. Run `vibey-gh COMMAND --help` for argparse's generated reference.
`python -m vibey_gh COMMAND` is the same entry point, for an interpreter that has the
package but not the `vibey-gh` script on its `PATH`.

| Command | Arguments and options | Behavior |
|---|---|---|
| `check` | `--apply`, `--commits RANGE`, `--quiet`, `--ci` | Verify assets, fingerprints, documentation, provenance, that every `scan_workflows` entry present in `.github/workflows/` can fire for a pull request, and optionally a commit range. `--apply` adds missing headers and collapses a header duplicated within a file; `--ci` skips the local hooks-path check and additionally surveys the clean-repo cloud clutter classes (sub-doctrine 9.a) — merged-and-undeleted remote branches, draft releases, orphan tags — reporting them as named problems and never deleting anything. Advisory unless `[tidy] fail_check = true`; `[tidy] enabled = false` turns the survey off. The survey is read-only in both directions: it never deletes, and it never fetches or prunes the clone, so it judges the remote-tracking refs the clone already has. A class it could not look at — no `gh` on PATH, an unauthenticated or rate-limited runner — is reported as `clutter: not surveyed — …` and left out of the verdict entirely, never counted as clean and never a failure. Under `--quiet` the survey runs only when `[tidy] fail_check = true`, the one setting under which it could still change the exit code. |
| `install` | none | Render configured workflows, install/chains hooks, and install release-site assets. |
| `version` | `--since REF` (default `origin/main`), `--dev BUILD`, `--apply`, `--explain`, `--config PATH` | Derive, explain, or write the semantic version. `--config` derives against an alternate configuration — a second distribution the same repository publishes — without moving the root: a monorepo holds several version lines, and one `.vibey-gh.toml` holds one. The paths inside an alternate config stay repository-root-relative, because the deriver reads them with `git show <rev>:<path>`, which resolves only from the top of the tree. |
| `trailer` / `trailer-key` | none | Print the configured provenance trailer or only its key. |
| `conventional-message` | `--file COMMIT_EDITMSG` or stdin | Normalize the first line without changing the remaining bytes. This git-hook helper is intentionally CLI-only because it edits a local file or stdin. |
| `conventional-check` | required `--commits BASE..HEAD` | Audit every subject in an explicit revision range. This local/CI git helper is intentionally CLI-only, not a remote automation capability. |
| `merge-train` | `--method squash\|rebase\|merge`, `--pr N`, `--dry-run`, `--label LABEL`, `--summary FILE`, `--admin-fallback` | Revalidate and merge one or all policy-ready exact heads. A pull request whose author is not in `[merge_train] trusted_authors`, or that carries `vibey-gh:external-repair`, is never merged unattended — approved or not, gates green or not — and is reported "needs a human merge". A merge GitHub refuses is reported "needs a human merge" with GitHub's reason, and the pass continues. `--admin-fallback` retries a refused merge with `gh pr merge --admin`; it is off by default, a per-run decision for a person at the keyboard, and no configuration key turns it on. Unattended callers never pass it (ADR-0053, sub-doctrine 12.d). |
| `approve-check` | required `PR`; optional `--head SHA`, `--approve`, `--body TEXT` | The delegated approver's grant, enforced by code (sub-doctrines 12.f and 12.j, ADR-0049, ADR-0053). Exits `0` only when EVERY condition of [`[unattended_approval]`](configuration.md#unattended_approval) holds for the pull request, and otherwise `1`, printing each condition that did not — every one, not the first, because the refusals are the reportable part (12.d). The conditions: `enabled = true` and the repository variable `switch_variable` names reading exactly `switch_value` (absent, `off`, empty, malformed and unreadable are all refusal); the author in `authors`, `@codeowners` expanded from `.github/CODEOWNERS`; the base branch matching a `branches` glob; no changed file matching a `forbidden_paths` entry — the whole pull request is refused, never a safe subset, and a file listing that failed or came back shorter than GitHub's count refuses too; when `require_all_gates`, every current check on the head reports `COMPLETED` with an explicit passing conclusion (`SUCCESS`, `NEUTRAL` or `SKIPPED` — a missing or null status or conclusion is not a pass), every commit status reports `SUCCESS`, and both merge-train gates succeeded; the account `gh` is authenticated as neither the pull request's author nor an author of any of its commits, and every commit names at least one author and every author an account login — an author that cannot be named might be the approver (GitHub also refuses a self-approval outright); and an open, non-draft pull request. `forbidden_paths` globs match the way `[merge_train] protected_paths` does — case-sensitive, whole root-relative path, `*` crossing `/` — and a `**/` additionally matches zero directories, so `**/x` forbids a root-level `x` too: a path either reading forbids is forbidden. `--head` refuses unless the head is exactly that commit; run it immediately before approving so that what was examined is what is approved. Whether the approving session wrote any of the diff is not visible to a command and stays with the approver. Without `--approve` it is read-only. With `--approve`, which requires `--head`, it submits ONE approving review pinned to that commit (body `--body`, or a default naming the check) only after every condition held, confirms the forge recorded it as `APPROVED`, and exits non-zero otherwise; a refusal submits nothing. That is the delegated approver's only write. The approver runs it as `python -m vibey_gh.approval_check` — same arguments, same exit codes — and its agent definition grants it only that module form, never `vibey-gh approve-check` and no `gh pr review` or `gh api`: the module executes only the check's transitive `vibey_gh` import closure, all of which `forbidden_paths` covers, so this CLI (which the approver could otherwise approve changes to) is never between the approver and the check. `vibey-gh approve-check` remains as a thin delegate for people. The check never raises — a condition that fails to evaluate, an unreadable CODEOWNERS included, is a refusal. |

| `pr-automation ready-draft` | required `--pr N --head-sha SHA` | Convert a stable exact draft head to ready-for-review. |
| `pr-automation record-review` | required `--pr N --input JSON\|FILE\|-` | Persist a structured exact-head review. Use `-` for large stdin payloads. |
| `pr-automation record-repair` | required `--pr N --input JSON\|FILE\|-` | Persist a structured repair attempt. |
| `pr-automation mirror-fork` | required `--pr N` | Create a linked repository-owned replacement when a fork needs edits. |
| `pr-automation ensure-labels` | none | Create or reconcile all managed labels idempotently. |
| `issue-automation evaluate` | required `--issue N` | Classify one issue and emit stable JSON, including the derived solution branch and a Conventional Commit `pr_title`. |
| `issue-automation context` | required `--issue N`; optional `--output FILE`, `--max-bytes N` | Render one issue as a bounded, explicitly untrusted briefing. Writes to stdout when `--output` is omitted; parent directories are created. |
| `issue-automation record-solution` | required `--issue N --input JSON\|FILE\|-` | Persist a structured solution attempt against the issue's content lineage. |
| `issue-automation list-eligible` | none | Emit the JSON array of open issues a recovery sweep should dispatch. |
| `issue-automation ensure-labels` | none | Create or reconcile the issue automation labels idempotently. |
| `github-release` | required `--target SHA`; optional `--version VERSION` | Create or reuse an immutable tag and GitHub Release. |
| `promote` | `--method rebase\|squash\|merge`, `--dry-run`, `--wait` or `--no-wait`, `--summary FILE`, `--admin-fallback` | Open the integration-to-release PR, or rewrite the open one's title and body from the current derivation (its body records the version it was opened at, and says when that changed). Event-driven `--no-wait` is the default. With `--wait` it merges the promotion itself; a merge GitHub refuses is reported "needs a human merge: <reason>". `--admin-fallback` (only with `--wait`) retries it with `gh pr merge --admin`: off by default, a person's per-run decision, never a configuration key; unattended callers never pass it (ADR-0053, sub-doctrine 12.d). |
| `realign` | none | Bring the integration branch forward after release without rewriting it. |
| `flatten` | `--onto REF` (default `origin/<integration branch>`), `--message TEXT`, `--push`, `--orphan-comments`, `--dry-run` | Rewrite the current branch as one commit on its base, subject normalized and trailers re-derived: every author of the range becomes a `Co-Authored-By` and every `Co-Authored-By` the range already declares is carried with them (this repository credits collaborators by trailer while the git author is the operator, so credit read off authorship alone would drop all of them), the provenance trailer is added, and breaking changes survive whichever commit of the range declared them — every `BREAKING-CHANGE:` footer is carried and deduplicated across both spellings, and a `!` on a commit whose subject is not the one reused re-marks the composed subject instead of being turned into a footer nobody wrote. Issue-closing keywords survive the same way and for the same reason, because nothing re-derives them either: every `Closes #12` / `Fixes #12` / `Resolves owner/repo#12` in the range is collected, deduplicated by issue, kept in the verb its author used, and written in a paragraph of its own above the trailer block — above it because a closing keyword is not `token: value`, and a trailer block containing one stops being a trailer block. Nothing is invented; a range that never promised to close an issue does not start here. Trailers are looked for only where git keeps them, in the message's trailing run of trailer paragraphs, so a body sentence opening `Made-With:` no longer suppresses the provenance trailer and a body line quoting `Co-Authored-By:` no longer suppresses a real attribution. The RUN and not only the final paragraph, because `.githooks/commit-msg` appends the provenance trailer as a paragraph of its own — an ordinary commit here therefore ends in two, and a reader stopping at the last one sees the provenance trailer and misses every `Co-Authored-By:` above it, which is a silent loss because a dropped co-author looks exactly like a commit that never named one. A paragraph that is not entirely trailer lines still ends the run. This repairs the two branches no other command can. A commit authored through the GitHub web UI or API never meets `.githooks/commit-msg`, so it carries no `Made-With:` trailer and the provenance gate refuses it — `check --apply` writes file headers, not commit trailers. And `conventional-check` refuses outright any range containing a merge commit, which is every range that took the integration branch into a topic branch. `--onto` is fetched first, from the remote its own name gives, so `--onto upstream/main` needs no second configuration key — and that remote is fetched from and nothing more: the push goes to the BRANCH's own upstream remote, or `origin` when it has none, so an `--onto` on a fork cannot send a topic branch there. A fetch that FAILS is refused rather than shrugged at: a stale `origin/<base>` makes the ancestry check below agree about a base the remote moved past, and the resulting commit — whose parent omits every integration change since — force-pushes successfully, because the lease protects the topic branch and says nothing about the base. The new commit is built with `git commit-tree` from the branch's existing tree object: nothing is staged, the working tree is never read, and the built tree is compared against HEAD's before the ref moves, so content cannot change. Refused: a detached HEAD; any permanent branch (the configured integration and release branches, plus the literal `develop` and `main`); an uncommitted tracked change; a range with nothing in it; a range of only merge commits with no `--message`; a base that is not an ancestor of HEAD — that one would present the branch's tree as the whole of both and silently revert everything the base gained, so it is refused naming the merge that keeps both sides; and a branch whose open pull request has unresolved review threads, unless `--orphan-comments` says otherwise. Those threads are anchored to the commits being replaced, so the force-push marks every one of them outdated: each detaches from the code it was about, collapses, and stops prompting anyone to answer it. The refusal lists them — author, file, line, first line of the body — so it can be acted on, and `--orphan-comments` proceeds with the notes still naming what it cost. If `gh` is missing, unauthenticated, or fails, the notes say the check **could not be made** and the flatten proceeds; a check that did not happen is never reported as one that passed. The notes and `--dry-run` also list the issues and discussions the range's commits reference, whose "referenced this in commit" timeline entries will name commits that stop existing — reported only, because nothing can preserve them. It rewrites history, so both refs are pinned: the branch move takes the pre-rewrite SHA and `--push` takes a `--force-with-lease` on what this clone last saw the remote holding — its remote-tracking ref, which is what somebody else's push makes stale — anything landing in between refusing rather than being clobbered. (Leasing on the pre-rewrite LOCAL SHA instead refuses the ordinary case, since a branch about to be flattened usually carries a commit the remote has never held.) A branch the remote does not have yet is created without a lease — there is no remote value to pin and a lease naming one cannot be satisfied, so the first push of a branch would otherwise fail as a refused lease; the remote is asked with `ls-remote` rather than the answer being read off a failed push, and a remote that cannot be asked keeps the lease. A refused lease names the retry, a `git fetch` and a push leasing on what the fetch brought back. Without `--push` that exact command is printed instead, lease and all, so pasting it does what `--push` would have done, and the success note names the remote it reached; `--dry-run` reports the plan and changes nothing at all — not even the fetch, so it reads the base as this clone already has it and says so. |
| `report-superseded` | required `--index pypi\|testpypi --project NAME --version VERSION`; optional `--governance-since REF` | Report which prior releases on the index the given version supersedes. PyPI exposes no yank API, so this prints the release list and the management URL for a human to act on; it never yanks anything itself. With `--governance-since`, the release range is checked against `[yank] governance_paths`: a RATIFIED governance change (Article V.4) names every previous release, overriding `keep` and the per-index switches — zero exceptions; an unreadable ref is reported loudly, never silently waived. |
| `paper` | required `--author NAME`; optional `--source docs/paper.md`, `--output paper/paper.tex`, `--journal`, `--keywords` | Render the repository's research paper (docs/paper.md, markdown with LaTeX math inline) as an IEEEtran-class document — conference two-column by default, `--journal` for the journal layout. `$...$`, `$$...$$`, and ```latex fences pass through untouched; prose is escaped; `## References` becomes `thebibliography`. The LaTeX-to-PDF compile belongs to the workflow (TeX Live/tectonic), keeping the package dependency-free. |
| `book` | required `--site-dir DIR --title T --author A`; optional `--config-file properdocs.yml`, `--output-dir book`, `--subtitle`, `--publisher`, `--description`, `--language en`, `--edition`, `--identifier`, `--date YYYY-MM-DD`; interior `--trim 6x9`, `--gutter 0.5in`, `--margin-outside 0.5in`, `--margin-top 0.75in`, `--margin-bottom 0.75in`, `--font-size 11pt`, `--line-height 1.5`, `--font-family "Georgia, serif"`, `--code-font-family monospace`, `--running-head-length 60` | Export the built docs site as a book: a valid EPUB 3.0 (Dublin Core metadata with `dc:date`, chapters spined in nav order, a landmarks navigation, `xml:lang` on every document, and a `dc:identifier` derived from title, author, language and edition, so the same book keeps one identity across builds — `--identifier` overrides it, e.g. with an ISBN URN) and a KDP print-ready HTML interior that a headless-Chrome print-to-PDF turns into a paperback: mirrored margins with the gutter on the binding side, a page number at the foot of every body page and none on the front matter, each chapter's title as the running head of its recto pages and its nav section's on the verso, a part page per nav section, justified and hyphenated text in the book's `<html lang>`, code and figures kept whole, and tables allowed to flow across pages with repeated headers and intact rows. The contents, printed and EPUB alike, keeps the nav's section grouping at any depth, and chapter titles lose YAML quotes and markdown backticks. Every physical dimension is a flag; bare numbers are inches (points for `--font-size`). KDP's minimum gutter grows with the final page count — 24–150 pages 0.375in, 151–300 0.5in, 301–500 0.625in, 501–700 0.75in, 701–828 pages 0.875in, with at least 0.25in outside, top and bottom — so the 0.5in default suits 151–300 pages. Chapters come from the nav, so the doctrine order carries into the book. Stdlib only; the PDF step lives in the workflow, not the package. |
| `announce` | required `--channel NAME --branch NAME --sha SHA`; optional `--site-dir channel-site`, `--version V` (release path; default: the version files), `--repository OWNER/NAME` (default `$GITHUB_REPOSITORY`), `--server-url` (default `$GITHUB_SERVER_URL`), `--run-id` (default `$GITHUB_RUN_ID`), `--dry-run` | Post a published docs channel's concise changelog to the Discord webhook in `$DISCORD_WEBHOOK_URL`, configured by `[announce]`: breaking changes first, then the named groups and Other, capped with `…and N more`, noise counted, subjects escaped, under 2000 characters. The integration channel announces the commits since the previous accepted announcement, read from the Actions API; the release branch announces its `CHANGELOG.md` section and the tag range. An unknown range is said, and falls back to the one commit. Always exits 0: no webhook is a notice, a failed post a `::warning::`, and the URL is never printed. `--dry-run` prints the message instead. |
| `local-authority` | optional `--repos PATH...` or `--root ~/git`, `--interval 120`, `--once`, `--protected a,b`, `--no-check` | The capped-lane sync loop (#206): every pass, any clean, provenance-green local branch ahead of its upstream is pushed with an explicit pre-fetch `--force-with-lease`, so remote tracks local in near-realtime while local is the source of truth. Permanent branches (each repo's own integration/release names by default) are never touched; dirty trees and check-failing branches are held; unseen remote work always refuses the push. Discovery scans `--root` for work trees carrying `.vibey-gh.toml` — the opt-in marker. Safe to leave running in healthy periods: nothing-ahead is a no-op. |
| `failover` | optional `--config PATH` (default `~/.config/vibey-gh/failover.toml`), `--state PATH`, `--once` | The operator-seat failover engine (#208): when the paid lane's probe stops answering, the seat moves to the first healthy local agent (gptossloop, then opencode, by default) and moves back the moment the probe succeeds — the paid lane always leads. Machine-level config, off until the operator enables it; every probe, launch, and health check is an operator-supplied command judged by exit status. Lossless: seats share the working tree and `local-authority` keeps both fronts synced throughout. |
| `tidy` | optional `--apply`, `--ci` | The clean repo (sub-doctrine 9.a): surveys every technical-clutter class a forge and a clone accumulate — merged-and-undeleted remote branches, merged and gone-upstream locals, prunable worktrees, draft releases, orphan tags — and with `--apply` removes exactly the provably-lossless classes (two proofs: ancestry for merge-commit flows, the forge's own deletion-at-merge event for squash/rebase flows via `trust_forge_deletions`). Drafts, orphan tags, stashes, and untracked files are reported for the human, never machine-removed; human messiness is expressly welcome and untouched. `--ci` limits judgment to the cloud classes. |
| `local-review` | `--diff FILE` or stdin; optional `--model`, `--base-url`, `--max-chars`, `--timeout` (default from `[pr_automation.fallback]`), `--role fallback\|sovereign`, `--scope diff-groundable\|full`, `--context-dir DIR` | Review a diff with a local Ollama-compatible model. By default it answers only `pass`, `summary`, and `findings` — the sovereign lane's diff half, or the fallback when the paid review returned no verdict. `--scope full` (only with `--role sovereign`) answers the whole review, documentation-contract judgments included, judged against the files under `--context-dir`: what the sovereign lane runs when no paid review is declared (8.b). Every verdict names the halves it answered under `scope`. Never executes repository code. |
| `doctor` | none | Offline adoption preflight: reads `.vibey-gh.toml`, `pyproject.toml`, and `.github/workflows/` to catch a config key silently landing in the wrong section, `pr_automation.enabled` with no installed gate workflows (a merge train stuck forever — an error wherever `[install] workflows` takes `pr-evaluate.yml`, `pr-review.yml` or `merge-train.yml`, and an `info` note when it declines them all, as the starter config does), a ruff `E501` select that conflicts with the provenance header width, two workflows contending over GitHub Pages, and files still carrying a superseded fingerprint header. No network, no credentials, no execution; exits nonzero only on error-level findings, and prints `info` notes without counting them as warnings. |

| `fit` | optional `--model`, `--queue`, `--payload-bytes`, `--deadline`, `--observed-seconds`, `--base-url`, `--journal` or `--no-journal` | The fit calculus: decide whether this machine should take a given piece of work, from the model actually wanted, the queue already ahead of it, the payload size and the caller's deadline. The model is read from `--base-url`, else `VIBEY_OLLAMA_URL`, else `[pr_automation.fallback] base_url`. A model the runner holds but has not loaded is read from its metadata rather than refused. `--observed-seconds` records what a payload really took. Every decision is journalled, and the measurements already in the journal are read back, so repeated calls form a self-adjusting estimate rather than a fixed guess. The journal is `--journal`, else `VIBEY_GH_FIT_JOURNAL`, else `~/.local/state/vibey-gh/fit.jsonl`; `--no-journal` turns it off. The full model is documented under [The fit calculus](configuration.md#the-fit-calculus--vibey-gh-fit). |
| `estimate` | required `--operation STAGE`; optional `--from STAGE`, `--json`, `--model`, `--base-url`, `--payload-bytes`, `--online`, `--journal` or `--no-journal` | The operation estimate, run before a job starts (#134). It judges feasibility over the six-materials state vector at every stage from `--from` (default: the first stage) through `--operation`. The default stages are `install`, `interview`, `feature-branch`, `develop`, `develop-deployment`, `develop-validation`, `main`, `main-deployment` and `main-validation`, and `[estimate]` can replace them. The fit calculus measures two coordinates: hardware availability and software availability. The other sixteen are reported as `unknown`, each naming what would measure it, and the confidence reported drops accordingly. Shortfalls are listed agency first. The local model's service time is projected from the fit journal through the shared graded estimator. The journal is read and never written. The stages' duration, the cost and the repair ranking are reported as `unknown`, with the reason for each. The command is offline by default: a model runner that is not on this machine is read only with `--online` or `[estimate] offline = false`. Exits `0` when feasible, `1` when a measured coordinate falls short, `3` when feasibility is unknown, and `2` for a stage that does not exist. Documented under [`[estimate]`](configuration.md#estimate-and-vibey-gh-estimate). |
| `slots corpus` | required `--pool FILE`, `--out FILE`; optional `--segments` (16), `--segment-length` (3), `--strata` (`16384,32768,49152`), `--min-per-stratum` (2), `--seed` | Draw a stratified corpus of turn segments from a `vibey-gh/turn-pool/1` pool: proportional to the pool's prompt depths, with every non-empty stratum kept, so the deep tail is always replayed. Documented under [`[local_models]`](configuration.md#local_models-and-vibey-gh-slots). |
| `slots calibrate` | required `--corpus FILE`; optional `--model`, `--context-window`, `--base-url`, `--binary`, `--port`, `--max-runs`, `--num-predict` (768), `--seed` (42), `--no-repeat-baseline`, `--extra N@CONTEXT`, `--server-setting OLLAMA_NAME=VALUE`, `--interval` (1.0), `--lock`, `--wait-idle` (1800), `--if-requested`, `--log-dir`, `--out` | Sweep N = 1, 2, 3, ... concurrent runs of the model on this device, beside an idle production runner, and record the evidence keyed to this device's fingerprint. Every completed step is checkpointed and `--out` is rewritten after it, so an interrupted sweep resumes. Stops at a broken bound or a plateau. Exits `1` when the device cannot be fingerprinted, the production runner never idles, no clean reading could be taken, or the calibration ran on another runner version (then nothing is recorded). |
| `slots allowed` | optional `--model`, `--base-url`, `--json`, `--strict` | Print how many runs of the model may run at once on this device -- the number a queue reads -- with the reason on stderr. `[local_models] concurrent_runs = 1` probes nothing. Missing or stale evidence prints `1` and requests a calibration. `--strict` exits `2` when a declared number was refused. |
| `api`, `mcp`, `sdk` | `CAPABILITY`, `--arguments JSON_ARRAY` | Invoke a canonical capability through that adapter. |
| `webhook` | `CAPABILITY`, `--arguments JSON_ARRAY`, required `--delivery ID` | Sign and dispatch locally using `VIBEY_GH_WEBHOOK_SECRET`; claims persist by default. |

`VIBEY_GH_WEBHOOK_STATE_DIR` overrides the default
`.vibey-gh/webhook-deliveries` store. The CLI atomically creates a mode-0600 SHA-256 marker
for every accepted delivery ID in a mode-0700 directory, so rejection survives restarts
and concurrent invocations. Put it on durable storage when the CLI receives webhooks.

## Library and server adapters

SDK, API, MCP, and webhook implementations are dependency-free application callables, not
bundled network daemons. Adopters own TLS, authentication, process management, rate limits,
and request-size limits in their chosen server framework.

```python
from vibey_gh.surfaces import api_dispatch, mcp_dispatch

status, response = api_dispatch("POST", "/v1/capabilities/check", b'{"arguments":["--ci"]}')
tools = mcp_dispatch({"jsonrpc": "2.0", "id": 1, "method": "tools/list"})
```

Map HTTP `POST /v1/capabilities/{name}` to `api_dispatch` and MCP JSON-RPC objects to
`mcp_dispatch`. For an inbound webhook, retain the sender's raw bytes and signature:

```python
from pathlib import Path
from vibey_gh.surfaces import WebhookDispatcher

webhooks = WebhookDispatcher(secret, delivery_dir=Path("/var/lib/vibey-gh/deliveries"))
status, response = webhooks.dispatch(delivery_id, signature_header, raw_body)
```

Never put the secret in arguments or logs. The convenience CLI computes its signature for
integration and smoke testing; an HTTP adapter must forward and verify the sender's HMAC.
