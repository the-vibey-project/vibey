**The paper's release-cadence figure no longer reads `git tag`.** It counts the releases in the tracked `docs/paper_releases.toml` (version, tag, commit, instant), so deleting, moving or cutting a tag on the forge can no longer turn `scripts/paper_figures.py --check` red, as it did on 2026-11-13. `scripts/paper_releases.py sync` reads a tag once to propose an entry (the daily documentation updater runs it and opens the entry in its refresh pull request); `check` fails out loud when the release branch ships a version with no entry, and never holds a feature pull request for an unreleased one. The pin guard also stops accepting a pin merely because a tag holds it. The caption now says "recorded release" rather than "tag"; the drawn figure and its numbers are unchanged.
