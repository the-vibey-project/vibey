`vibey acp`: a session now follows a project's ledger. The project is the one whose repository holds the session's folder (the deepest when repositories nest), or the one the hub's last reply named, which wins; it is also what a prompt's commands default to. The editor shows the project's phase plan (Design, Visual design once seen, Build, Review and the three deploy phases), re-sent when the phase changes, and each new ledger event as one plain-text message, `[<phase>] <kind>: <summary>`, cut to `[acp] live_message_chars`. History is not replayed. The feed polls from a ledger position (sub-doctrine 10.g), so a hub restart neither skips nor repeats an event; a failed read is reported once and retried after `[acp] live_poll_seconds`. With `[acp] live_between_turns = false`, events between turns are held (at most `pending_events_max`) and sent when the next prompt starts. A gate's event is only ever a message; a spend gate's says once to answer it on the host. Right after `session/new` the editor gets every `/` command with its usage as the input hint, and `session/set_mode` switches between the offered modes with a `current_mode_update` (a gate held back in observe is offered after a switch to drive). A defect in reaching the hub is no longer reported as the hub being unreachable: only a connection failure is, and any other error keeps its own name and is logged with its traceback.
