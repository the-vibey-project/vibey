`vibey mcp` and `vibey acp` now read and send the agent token only to a hub whose process holds the hub's lock (`serve.lock`) and is the one its runtime record names, as `vibey hub pair` already did for the host token. On loopback over plain http, after a hub dies, another account on the computer could bind the port its stale record names and receive the token. A stale record is now treated as no hub at all: nothing is sent, and a tool call runs `vibey hub start` once as it does when there is no record. The lock proves that the hub's process is alive and named by its record, not that it already owns the port: a hub writes its record a moment before it binds, so a token sent in the milliseconds before a failed bind clears the record could still reach an account that bound the port first (binding first is a follow-up).
