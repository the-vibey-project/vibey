**A process with no `vibey.toml` now reads its operational surfaces from the environment** (#323). `build_app` loaded the environment overlay only when `./vibey.toml` existed, so a Helm worker (which runs in `/work` with no file) ignored the `VIBEY_TRACKER_*`, `VIBEY_DOCS_*` and the other surface variables the chart injects, and every surface stayed in memory. A new `StartupConfigResolver` reads the file when there is one and the environment otherwise, and says once in the log when a `vibey.toml` or a variable cannot be used instead of swallowing it. A process with neither behaves as before. `load_config_from_path` takes the environment as a parameter, and `load_config_from_environment` is new.
