New `vibey inputs add PROJECT_ID (--paste TEXT | --paste-stdin | --file PATH)` and `vibey inputs list PROJECT_ID [--json]` give every BUILD run of a project the same pasted texts and files, whichever loop runs it (SP-LOOPS Phase 3; ADR-0104, proposed). Inputs are stored once by SHA-256 in your own state folder, keyed by project id (`<state folder>/inputs/<project id>/`), never in the project's checkout and never in PostgreSQL; the ledger records each input's digest, kind and size, never its content. Each BUILD run gets `.vibey/inputs/<run id>/attachments/` and `paste.md` in its worktree and a fenced `## Run inputs` section in its prompt, marked as data the person supplied and not instructions. The new `[inputs]` table of your own `vibey.toml` sets the limits (`max_item_bytes` 1 MiB, `max_project_bytes` 8 MiB, `max_items` 64, `max_prompt_bytes` 64 KiB); a project's `[inputs]` is never applied. ACP intake (an `/input` command for embedded resources) is not built yet.
