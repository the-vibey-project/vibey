`vibey mcp` now reads `[hub]` from your own `vibey.toml`, in your configuration folder, as `vibey acp` already did, never from the folder the client opened. A cloned repository's `vibey.toml` could name a `[hub] state_dir` holding a planted runtime record and agent token, and so decide which token the MCP server presented and where (Task 9b had already confined the address to this computer's loopback). The opened folder's `vibey.toml` is now heard on `agent_scopes` only, and only to narrow it: what both grant is kept, and a `[hub]` there that cannot be read is refused rather than ignored. A hub `vibey mcp` starts now runs in your configuration folder, so it reads the same file.
