`vibey acp`: sessions are kept and can be loaded, resumed, listed and closed. The hub keeps each session's history (migration 0023: `acp_session` and `acp_session_event`, append-only by the ledger's own trigger, `SELECT` and `INSERT` only for the application role) on four new routes under `/api/v1/acp/sessions`, each needing `view` and reading or writing only the creating principal's sessions; `vibey acp` writes through them as the agent principal, behind each turn and in order, resending from where a failed send stopped and holding at most `[acp] pending_events_max` events. What is kept is what a turn showed (your messages, vibey's replies, tool calls and their outcomes), the title, mode switches, the project followed and the close; live ledger messages are not, and a tool call's input is not. `session/load` replays the history before it answers, every stored event rebuilt from checked fields with its text shown by the same plain-text rule as live hub text, never as a command, a permission request or a gate; `session/resume` restores mode and project without replaying. Both resend the `/` commands, follow the project, and keep a session that is still open as it is. A session is found only by its UUID for the folder it was started in, and any other answers `RESOURCE_NOT_FOUND` the same way. `session/list` pages newest first with a cursor. `session/close` cancels a running turn, withdraws its permission requests, stops its live feed and records the close; a later prompt finds no session. New errors E0084 to E0086.
