`[inputs]` in your own `vibey.toml` now says where run inputs are stored (ADR-0105, proposed): `store = "local"` (the default; an optional absolute `store_dir` replaces the state folder) or `store = "seaweedfs"` with `endpoint`, `bucket`, `prefix`, `region` and `timeout_seconds`, reached over the S3 API and signed with the same SigV4 signer the Garage blob store uses. Credentials come only from the environment variables `access_key_env` and `secret_key_env` name; a credential written into `[inputs]` is refused without being echoed. The ledger is now the authority on which inputs exist: a run is given the stored rows that match its recorded adds one to one (digest, kind, size and the SHA-256 of the name, in ledger order); a BUILD run whose store lacks a recorded input fails before the engine starts and names the input, and any other row is withheld. The worker reads `[inputs]` only when a BUILD run has inputs to give, never at start. `vibey doctor` gains a `run-inputs` line naming the store in force, the config file it came from, and whether it answers; `vibey inputs` exits 69 when the store cannot be reached.
