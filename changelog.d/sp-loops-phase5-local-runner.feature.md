A BUILD run on `gptossloop` or `qwenloop` is now given the loop capability bundle from your own `[loops]` (SP-LOOPS Phase 5; ADR-0103, and ADR-0092's 2026-11-25 amendment), as a run on `claudeloop` already is. vibey starts it with `run --capabilities PATH`, and `vibey loops` reports its plugin system as the new `vibey-bundle`: the snapshot's skills and plugin commands, which the model lists and reads on demand through the new `skills_list` and `skill_read` tools, and its MCP servers, with no plugin hooks or agents. The local runner's full-access gaps are now none. Its system prompt lists the skills, commands and servers, then the repository's `CLAUDE.md` and `AGENTS.md`, within the new person-only `[loops] capability_prompt_tokens` (default `3072`, from 512 to 4096); the listing falls back to names, then to a count, and says so, and an instruction file that does not fit is named, never cut. `mcp_list` and `mcp_call` reach exactly the snapshot's servers (never `~/.claude.json` or `QWENLOOP_MCP_CONFIG` in such a run, and never the worktree's `.mcp.json`): a local one over stdio through the scrubbed launcher, a remote one over streamable HTTP with no redirect, cookie, credential, environment or proxy. Each server keeps one persistent session for the run, started on first use and closed when the run ends, SIGTERM included (qwenloop now exits `130` on SIGTERM, as claudeloop does). `mcp_list` returns one tool's input schema when asked for it, whole or refused with both sizes, and every on-demand answer is held to the new `[loops] capability_answer_tokens` (default `3000`, from 256 to 8192); claudeloop ignores both keys. A failing MCP server is a tool error the model reads, never the end of the run, and qwenloop's own `[mcp]` table bounds the sessions (`request_timeout_seconds`, `restarts`, `close_grace_seconds`, `remote_calls_per_session`, `max_tools`). The capability document becomes version 2. **Behaviour change:** a `gptossloop` job whose snapshot cannot be resolved now parks on a `loop_capabilities_unresolved` gate instead of running without it, and a document the runner refuses exits 78, which the `engine_misconfigured` gate parks.
