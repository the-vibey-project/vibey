`vibey acp` sets the computer up when an editor first connects (`[acp] auto_bootstrap`). After `session/new` has answered -- never before -- it runs `vibey doctor`'s local sections as a tool call, one update per finished section, and, with `[acp] auto_connect`, registers `vibey mcp` with each user-level client whose config folder already exists (never a project file, never a folder it would create, backups kept, one broken client a `WARN`; once per vibey version). Inside the first prompt of a `drive` session it offers a missing PostgreSQL as a permission request: only "Install PostgreSQL" installs, with the same fixed commands as `vibey doctor --install-postgres`, stdin closed, output captured, each bounded, and `sudo -n` -- vibey never asks for or types a password, and says when to run the install yourself; "Not now", a timeout, a cancel or `observe` install nothing and say the hub runs degraded. A second editor window leaves these steps to the first. `vibey doctor`'s sections are now doctor probes both share; its output, text and `--json`, is unchanged. A failed hub read no longer runs `vibey hub start` where it stands: `vibey acp` tries at most once per `[acp] hub_start_seconds` (new, default 60) on a thread of its own, says at once that the hub is away, and its `vibey hub start` child (as `vibey mcp`'s) no longer inherits the protocol's stdin.
