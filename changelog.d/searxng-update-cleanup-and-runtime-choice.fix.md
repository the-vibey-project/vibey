`vibey searxng install` (and the editor's update offer): an update to a newer pinned image now removes the old container and then the earlier image once the new one is pulled and recorded, saying so, or saying the `rmi` that removes it when the runtime will not; `uninstall --purge` of an install from an earlier pin now removes that image too. Install, and the unit at every start, refuse a Docker CLI whose current context points at another machine (`ssh://`, `tcp://`) or cannot be read, even with no `DOCKER_HOST`, and the unit runs the container pinned to the local endpoint it checked, so a later `docker context use` cannot move SearXNG to another machine. With both podman and docker installed, a podman whose machine is stopped now gives way to a docker that answers. The SearXNG unit now passes its own label to `vibey searxng serve`, so a unit left loaded from an earlier `[supervisor] label_prefix` refuses with how to unload it instead of running a second container beside the current one; run `vibey searxng install` once to rewrite an existing unit.
