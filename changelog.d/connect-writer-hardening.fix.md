`vibey connect` and `vibey acp`'s connect step no longer write through a `.vibey.bak` that is a hard link to another file: the old backup is removed and the new one created with `O_EXCL`, so the other file keeps its content and mode. `vibey connect` now writes each client on its own: a file that cannot be written, or is swapped to a symbolic link mid-write (`ELOOP`, `ENOTDIR`), is one cleaned `WARN <client>: not connected ...` line on stderr for that client while the others are still written, and the command exits 1 (before, the first such failure stopped the rest). A test now pins that project configs `vibey connect` creates (`.mcp.json`, `.vscode/mcp.json`) are 0600, like every new file it writes. `vibey acp`'s connect step no longer runs at every launch for a client it will never write as things stand -- a config folder that resolves outside your home folder, or a config file that is a symbolic link (a dotfile-managed config, now a `WARN` saying to add the entry by hand where it points, unless it already carries it): `acp-connect-<version>.json` records such a client as settled, with the folder's real path or the link's target, and the step runs again when either changes.
