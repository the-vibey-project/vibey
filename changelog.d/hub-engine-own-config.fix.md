`vibey hub start`, `vibey hub stop` and `vibey hub status` now read `[hub]` from your own `vibey.toml`, in your configuration folder, never from the folder they run in, and `start` launches the hub in that configuration folder (made 0700), so it reads the same `[hub]` as `vibey mcp`, `vibey acp` and `vibey hub pair`. Before, a cloned repository's `vibey.toml` could choose the state folder the hub kept its host and agent tokens in, and plant a runtime record: one naming process id `-1` made `vibey hub stop` send SIGTERM to every process of your account. A runtime record naming process id -1, 0 or 1, a boolean, or a port outside 1 to 65535 is now unreadable everywhere it is read. Whether a hub runs is now asked of the hub's own lock (`serve.lock`) instead of whether its process id exists: a record whose lock nobody holds is stale and nothing is signalled, one whose lock another process holds is refused with exit 1, and `stop` signals only the process that holds the lock and names itself in the record. `vibey doctor`'s `hub-exposure` line now reads your own `[hub]` and record too. One visible change: a hub started by `vibey hub start` runs in your configuration folder, so with `lane_roots` empty it now looks for lanes there, not in the folder you ran the command in; list your lane folders in `[hub] lane_roots`.
