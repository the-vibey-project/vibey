**A pull request now runs only the CI jobs its diff can affect, on a small matrix** (`ci.yml`, SP1-B of the optimization program). The `noloss`, `postgres-compatibility`, `tools`, `tools-lint`, `krypton-app`, `vibey-core`, `app`, `desktop`, `image`, `chart` and `cluster-smoke` jobs and the two VS Code checks read the `CI plan` job's outputs in a job-level `if:`; `tools`, `postgres-compatibility` and `desktop` take their matrix from it (`fromJSON`), the full rows living in `.github/ci-matrices.toml`. `gates`, `lint`, `uv-lock` and `ci-result` always run. Every `if:` replaces the implicit `success()` with `!cancelled()` and tests only `uv-lock` and `lint` by name, so a failed, timed-out or cancelled plan cannot skip a job and a lint failure still does; an absent output runs the job. The VS Code matrix became two plain jobs whose names, `VS Code extension (ubuntu-latest)` and `VS Code extension (macos-latest)`, are the required checks byte for byte. The automation bootstrap now accepts `gates` only on `success`, never `skipped`. A test evaluates every expression with the plan's outputs absent and at their defaults and rejects any construct outside the subset it models.
