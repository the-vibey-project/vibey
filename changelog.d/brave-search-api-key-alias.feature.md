Web search accepts the Brave Search key under `BRAVE_SEARCH_API_KEY`, the name Brave's own tools read, as an alias of `VIBEY_BRAVE_API_KEY`; `VIBEY_BRAVE_API_KEY` wins when both are set, and Brave is still chosen only when SearXNG is not configured (or `VIBEY_SEARCH_PROVIDER = brave`). The key stays in vibey's own processes: the alias, and the older `WEBSEARCH_BRAVE_API_KEY` form vibey also reads, join the rule under every child's environment allow-list, so no engine session or gate can be given the key even by a declared name or prefix, and it is never in a `repr`, an error or a log line. **Breaking:** a project whose `[engine_environment]` or `[gates] env_allow` declares `BRAVE_SEARCH_API_KEY` or `WEBSEARCH_BRAVE_API_KEY` (so its own code could use Brave) is now refused by `vibey new` and when the worker is built (`... can never be passed to a child process`); give the project's own key another name in its own environment, for example `PROJECT_BRAVE_API_KEY`, and declare that. No other name configures the key (`WEBSEARCH_BRAVE_SEARCH_API_KEY` does not). The worker's web-search line now says which of the three variables configured Brave (`configured via BRAVE_SEARCH_API_KEY`), never the key, and the not-configured hints name the alias.
