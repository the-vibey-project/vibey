`scripts/install.sh --full` now takes a new macOS or Linux machine to where a first project runs on the local engine. After the install it runs, in order, and stops at the first step that fails (naming it and the command that re-runs it): `vibey install --postgres`; the new `vibey install --database`, which makes the database and its owner and application roles, keeps their passwords in `~/.pgpass` (never printed; each DSN is password-free and still proves a password with scram-sha-256) and migrates; `vibey migrate` only for a database of your own; Ollama (skipped when it is installed; Homebrew on macOS, Ollama's own installer on Linux, `VIBEY_OLLAMA_INSTALLER`); the new `vibey install --model`, which pulls the model `vibey models --default-tag` names (about 12 GB for the default) unless it is there; and `vibey connect --yes`. Each step can be skipped (`VIBEY_FULL_POSTGRES`, `VIBEY_FULL_DATABASE`, `VIBEY_FULL_MIGRATE`, `VIBEY_FULL_OLLAMA`, `VIBEY_FULL_MODEL`, `VIBEY_FULL_CONNECT` set to `0`), and the script says before a step that sudo may ask for a password. At the end it prints the `export VIBEY_PG_URL=...` line for your shell profile and the `pg_hba.conf` step that is still yours. The installer now installs `vibey-engine[hub]` (`VIBEY_ENGINE_EXTRAS`, default `hub`), so `vibey serve`, `vibey hub` and the hub `vibey mcp` starts work after a plain install; the bare engine failed with `No module named 'fastapi'`. It also finds `vibey` in uv's tool directory when it is not on `PATH` (and fails with the line to add when it is not there either), prints `--help` when piped, and names an uninstall command that exists after a piped install, only when krypton was installed.
