**`vibey-gh pin-actions --refresh` moves commit pins that have gone stale, and a weekly check says when one has.** A pinned `uses: owner/repo@<sha> # v4` never moved by itself, and Dependabot cannot take over because it ignores a dependency, not a file. `--refresh` re-resolves each pin's `# <ref>` comment and rewrites the SHA when the ref now names another commit, printing `path:line: action (ref) <old> -> <new>`; a pin with no readable ref comment, a ref that does not resolve, an expression ref or a use that is not pinned is listed as `path:line` and the run exits 1 while the others still move. `--check-stale` does the same without writing, and with `--tracking-issue` keeps one open issue while any pin is stale or unchecked and closes it when none is (`.github/workflows/pin-freshness.yml`, weekly). A new `[pin_actions]` table in `.vibey-gh.toml` takes `hold` (actions a refresh leaves alone) and `labels`. `pin-actions` also no longer rewrites files it had nothing to change in, lists a ref that is an expression instead of failing the whole run on it, and reports a forge answer that is not JSON as a resolve error.
