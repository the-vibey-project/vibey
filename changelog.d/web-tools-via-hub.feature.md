The hub now serves web search and fetch, so a model driving vibey over MCP needs neither a SearXNG address nor a Brave key (ADR-0102, §9). `POST /api/v1/web/search` runs the local-first rule in the hub's own process -- the local SearXNG first, Brave only as its backup, with the key in the hub's environment alone and never in an answer, an error, a log line or the ledger; the first answer of the hub's life to come from Brave carries the notice it said. `POST /api/v1/web/fetch` reads one public http(s) page as text inside a marked untrusted block: no user name or password, no local, internal or metadata name, no address spelt other than canonically, and no address that is not public (loopback, private, link-local, carrier-grade NAT, unique-local, multicast, reserved, IPv4-mapped, NAT64, 6to4, Teredo), checked for every address a name resolves to and connected to as checked, after every redirect too (never https to http); fixed headers only, nothing ever decompressed, only the configured content types (PDF refused), bounded in bytes, characters and one total deadline that fails closed. Both need the new `web` hub scope, which the agent principal holds by default (`[hub] agent_scopes`; a paired device only when the host offers it), and the MCP server offers them as `vibey_search` and `vibey_fetch`, listed only to an agent holding `web`, with descriptions and server instructions that say their results are untrusted data and that a query or URL leaves the computer. New user-level `[web]` table (`searches_per_hour` 60, `fetches_per_hour` 30, `allow_hosts`, `deny_hosts`, `max_bytes`, `max_chars`, `timeout_seconds`, `max_redirects`, `content_types`); a project's `vibey.toml` may only tighten it. Every use -- refusals and failures included -- is recorded on the ledger as `WebSearched` or `WebFetched` (who, the outcome, the backend and the hosts a fetch reached; never the query or the URL), on the named project's ledger or else every project's; with no project the hub refuses rather than search unrecorded. A spent budget is a 429 naming it. New error codes E0090 to E0093. `vibey doctor` gains a `web-tools` line after `searxng`; the existing lines and `--json` keys are unchanged. Engine sessions are not changed: they have no channel to the hub yet, so they still search SearXNG directly (ADR-0102 records why and the next step). The krypton app and desktop name the new scope.
