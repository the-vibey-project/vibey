The hub now serves web search and fetch, so a model driving vibey over MCP needs neither a SearXNG address nor a Brave key (ADR-0102, §9). `POST /api/v1/web/search` runs the local-first rule in the hub's own process -- the local SearXNG first, Brave only as its backup, with the key in the hub's environment alone and never in an answer, an error, a log line or the ledger; the first answer of the hub's life to come from Brave carries the notice it said. `POST /api/v1/web/fetch` reads one public http(s) page as text inside a marked untrusted block: no user name or password, no local, internal or metadata name, no address spelt other than canonically, and no address that is not public (loopback, private, link-local, carrier-grade NAT, unique-local, site-local, multicast, reserved, and IPv4-mapped or well-known NAT64 forms of one; local-use NAT64, 6to4 and Teredo refused outright), checked for every address a name resolves to and connected to as checked, after every redirect too (never https to http); fixed headers only, nothing ever decompressed, only the configured content types (PDF refused), bounded in bytes, characters and one total deadline that fails closed; the page's charset is used only when it is a text codec; the title and text come back in one nonce-marked block. Both need the new `web` hub scope, which the agent principal holds by default (`[hub] agent_scopes`; a paired device only when the host offers it), and the MCP server offers them as `vibey_search` and `vibey_fetch`, listed only to an agent holding `web`, with descriptions and server instructions that say their results are untrusted data and that a query or URL leaves the computer. New user-level `[web]` table (`searches_per_hour` 60, `fetches_per_hour` 30, `allow_hosts`, `deny_hosts`, `max_bytes`, `max_chars`, `timeout_seconds`, `max_redirects`, `content_types`); a project's `vibey.toml` may only tighten it. Each search or fetch the hub makes -- refusals and failures included -- is recorded on the ledger as `WebSearched` or `WebFetched` (who, the outcome, the backend and the hosts a fetch reached; never the query or the URL) on the latest project's ledger and, when named, the `project_id`'s too. The hub checks it can write the record before it sends anything and refuses with 503 when it cannot (no project, or one in a phase this vibey does not know); a record that still fails after the act marks the answer `audited: false` and is said on the hub's stderr. The MCP gateway never sends a request again once it may have reached the hub, and waits longer for a web call than the hub's own web deadline. A spent budget is a 429 naming it. New error codes E0090 to E0093. `vibey doctor` gains a `web-tools` line after `searxng`; the existing lines and `--json` keys are unchanged. Engine sessions are not changed: they have no channel to the hub yet, so they still search SearXNG directly (ADR-0102 records why and the next step). The krypton app and desktop name the new scope. A paired device that held every scope loses vibey commands the hub does not classify, sent to the workflows (`vibey -w`), until the host offers it `web` too: an unclassified command needs every scope.
