`vibey hub pair`, `vibey hub devices` and `vibey hub revoke` now read `[hub]` -- the state folder holding the host token and the hub's runtime record -- from your own `vibey.toml`, in your configuration folder, never from the folder they run in, and send the host token only to this computer's loopback (by the fixed loopback literal the record's host maps to, as `vibey mcp` does). Before, they read the runtime record from whatever state folder the current directory's `vibey.toml` named and connected to whatever host it said, so a cloned repository could see the request. A hub you bound to a LAN address (`vibey serve --host 192.168.1.5`) is now reached with the new `--host` option, which takes a private-network address literal (`10/8`, `172.16/12`, `192.168/16`, `100.64/10`, `fc00::/7`) or loopback, never a name, a zone, or a public, link-local or oddly spelt address; a record naming anything off the loopback without `--host` is refused with exit 2 before anything is sent.
