New commands under `vibey loops` manage what every loop is given, in your own `vibey.toml` only (SP-LOOPS; ADR-0103): `marketplace add NAME SOURCE [--ref REF]` declares a marketplace and fetches nothing; `marketplace update [NAME]` fetches, checks and locks it (with no name, the shipped marketplace and every declared one; `vibey` re-locks the shipped one after you have looked at a change a run refused); `marketplace list [--json]` says what the lock holds of each; `plugin add NAME@MARKETPLACE` and `plugin remove NAME`; `mcp add NAME --local -- CMD...` (the argv stored exactly, never through a shell) or `--remote URL` (https only), with `--env-allow VAR`; `mcp list [--json]`; `skills list [--json]`, which resolves the bundle as a run would, from the lock and with no network, so a fresh install lists the research skills; and `snapshots prune [--older-than-days N]` (default 7), which removes old run snapshots and never follows or removes a symlink. Bare `vibey loops [--json]` is unchanged. None of them reads or writes the `vibey.toml` of the folder you run them in, and only `marketplace update` of a git source reaches the network. A source must be an `https://` URL without credentials, an `ssh://` or `git://` URL, `user@host:path`, or an absolute folder (copied without git); transport helpers (`ext::` and any `<name>::`), `file://`, `http://`, relative paths and anything starting with `-` are refused with exit 2. git is run as four fixed commands with the source after `--`, only the https, ssh and git protocols allowed, your global and the system git configuration not read, no hooks, submodules or LFS, a scrubbed environment and a 300-second deadline, into a private staging folder; the copy is checked (at most 256 MiB, a tree that hashes, a manifest that reads) and only then locked, so a failed update leaves the old copy and lock as they were. The store is `<your configuration folder>/loops/` (`lock.json`, `marketplaces/`, `snapshots/`), and the shipped marketplace is locked as `vibey-engine <installed version>`. A change to `[loops]` is checked by the same rule a run reads it with and written by a new writer that changes `[loops]` alone, keeps every other byte and comment, and replaces the file atomically with mode 0600; a comment inside `[loops]` is never dropped: the command refuses with exit 78 and prints the table to paste. Marketplace text (skill names, descriptions, skipped rows) and what git said are printed as one line of visible characters; `--json` keeps the raw values. The lock file is now read, changed and written under a file lock, so a run locking the shipped marketplace and `marketplace update` cannot drop each other's entry. `vibey_skills` now ships a `py.typed` marker.
