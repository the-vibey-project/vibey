A BUILD run handed over to another engine at a wind-down now gets its run inputs in its prompt: the gate-verified seed byte for byte, then the same `## Run inputs` section the run it replaces had, built from exactly the inputs that run was given (the wind-down pins their digests in the follow-up job, `handoff_input_digests`). Nothing added since the handoff is slipped in and no lowered limit drops one. The no-loss gate and its rules are unchanged. A pinned input the store no longer holds parks the job as a new gate kind, `handoff_inputs_missing` (error E0097, `vibey answer ID --raw '<json>'` once the input is added again); a store that does not answer is retried. Follow-up jobs enqueued before this change keep the seed alone.
