Engine sessions search and fetch through the hub, each as a principal of its own that holds only the `web` scope (SP-LOOPS Phase 6, ADR-0106). When a hub is running, the worker mints every BUILD run on claudeloop, claudeloop-local, gptossloop and qwenloop its own grant, writes the token to `<run folder>/web-token` (0600) and gives the session only `VIBEY_HUB_URL` and `VIBEY_WEB_TOKEN_FILE`; the grant is revoked when the session ends and expires at the run deadline plus one hour. The session's `vibey search` and `vibey fetch` ask the hub, never their own process, so a session now has the hub's Brave backup, its guarded fetch, a ledger record, and a budget: each call counts against the new `[web] session_searches` (default 30) or `session_fetches` (default 15) and against the agent's hourly budget, and a project's `vibey.toml` may only lower them. claudeloop reaches the same two tools through a `vibey-web` MCP server in its run snapshot, served by the new `vibey mcp --scope web --token-file PATH`; Claude Code's own `WebSearch` and `WebFetch` stay off. A session with no grant is given only `VIBEY_WEB_STATE=none:<reason>` (`no-hub`, `no-run-folder`, `no-token`, `not-given`) and its commands say why and exit 78; the hub's refusals exit 67 (token ended), 69 (no hub), 75 (budget), 77 (forbidden). **Breaking:** no session is told the SearXNG address, its marker or any `WEBSEARCH_*` name any more, and a session marked only by `WEBSEARCH_PROVIDER` or `WEBSEARCH_COMMAND` is refused rather than searched in-process.
