* **There is one hub per user, and `vibey hub start | stop | status` run it** (#1186). `vibey serve` now holds an exclusive lock on `<state_dir>/serve.lock` and a second one refuses with the running hub's process id (exit 1) instead of splitting the paired devices and the port; the kernel drops the lock when a hub dies, so a crash leaves none behind. `vibey hub start` launches the hub detached (output in `<state_dir>/hub.log`) and is idempotent; `vibey hub stop` sends SIGTERM and never SIGKILL; `vibey hub status` exits 3 when none runs and reports a record whose process is gone as stale. Closing a UI never stops the hub. This is the engine side; the krypton UIs' own buttons and autostart follow.
