**krypton desktop has a Keyboard shortcuts dialog, and its icon-only controls are named for screen readers** (#1699, part of #1665). The header menu gains **Keyboard shortcuts** (`Ctrl+?`), which lists every command and its keys. The menu, that dialog and the registered accelerators now read one table (`kr-commands`), and krypton refuses to start if the table and the registered actions disagree. Refresh, Main menu, Start a project, each project's actions menu and the warning marks carry explicit accessible names, and a test fails when an icon-only control is made without one (a heuristic over the source, said so). Not done, and recorded as "not run" in the new `clients/desktop/ACCESSIBILITY.md`: no one has run Orca or VoiceOver over it, and the Linux tray has never run against a real StatusNotifier host.
