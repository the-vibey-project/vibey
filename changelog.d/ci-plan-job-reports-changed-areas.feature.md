**CI now works out which areas a diff touches, and says so, before anything is allowed to skip** (`vibey-gh ci-areas` and `vibey-gh ci-matrix`, `.github/ci-areas.toml`, `.github/ci-matrices.toml`, the report-only `CI plan` job in `ci.yml`; SP1-B of the optimization program). A diff becomes a set of areas, a tier (`pr` or `full`) and the matrix rows each tenant, PostgreSQL and desktop job would run, read from two declared TOML maps and never from inline shell. Anything the map does not cover, an empty diff, a diff that cannot be computed, a broken map, an unknown event, a merge-queue run and a pull request into the release branch all answer the full tier. The tenant rows are chosen with their dependants, derived from each row's own `pip install` line, so a change to `vibey-runners-common` still runs `vibey-gh`, `vibey-bootstrap`, `claudeloop` and `codexloop`. Nothing reads the plan yet: this slice only reports, so no job is skipped and no check name changes.
