`vibey hub pair`, `devices` and `revoke` now send the host token only when the process the hub's runtime record names holds the hub's lock (`serve.lock`): a stale record's port, which another account could have bound after the hub died, is sent nothing and the command says the record is stale (exit 3). A host token or hub certificate that cannot be read is now one line (exit 2), not a traceback. When your own `[hub]`, or the opened folder's, cannot be read, `vibey mcp` and `vibey acp` now offer the agent no tools at all (as calls already failed), instead of the default scopes: a folder can no longer break its own `[hub]` to have more listed than you granted, and `tools/list` agrees with doctor's `FAIL`.
