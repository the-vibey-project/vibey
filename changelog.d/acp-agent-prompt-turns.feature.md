`vibey acp`: an editor such as Zed can now launch vibey as an Agent Client Protocol (ACP v1) agent over stdio. It answers `initialize`, `authenticate` and `session/new` (absolute `cwd` required; client MCP servers are ignored, and the client is told so), and runs each `session/prompt` through the hub's chat as the scoped agent principal, shown as one tool call followed by the hub's reply. The session mode is enforced before anything reaches the hub (`observe` reads only), and only the text the user typed is read for a command or option: an attached resource is data, sent only as a new project's description (`/new`, `/ask`). `session/cancel` ends the turn as `cancelled`, even when it arrives in the same read as the prompt; a hub call already in flight gets `[acp] cancel_grace_seconds` to report its real outcome, else the client is told it may still apply, with its request id. Standard output carries protocol messages only: fd 1 is pointed at stderr first, so a stray print or a child process cannot corrupt the stream. `--no-bootstrap` turns `[acp] auto_bootstrap` off for one process.
