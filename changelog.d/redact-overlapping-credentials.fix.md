The ledger redactor no longer leaves bytes of a credential behind when credential shapes overlap, and it redacts in time and memory linear in the text. Each pattern used to be substituted in turn, so a shorter shape inside a longer credential was replaced first and the longer pattern could no longer match across the marker: `Bearer sk-AAAAAAAAAAAAAAAA.rest` came out as `Bearer [REDACTED].rest`, and `Bearer AKIA…extra`, a JWT with a fourth segment, a Slack token or JWT with an `sk-` run inside, and a Google key holding an `sk-` run all kept a fragment. A credential glued to the one before it (`sk-…sk-…`, `ghp_…ghp_…`) also kept its whole body, because matching resumed where the previous match ended. The credential patterns are now declared as shapes (`CredentialShape`: a fixed-width prefix, then character-class runs), each matched at every start in the original text; a forward-only cursor per segment reads each character at most once, overlapping matches are merged into one `[REDACTED]` as they stream out, and a single search for any prefix returns most strings untouched. The result no longer depends on the order of the shapes, redacting twice changes nothing, adversarial strings such as `"xoxb-" * 400000` or `"eyJ" * 400000` redact in a fraction of a second (the old regex scan was already quadratic on the second), and redaction holds no more than the redacted copy in memory. Output changes only where matches overlap: such a run now becomes a single `[REDACTED]` (for example `Bearer sk-…` becomes `[REDACTED]`, not `Bearer [REDACTED]`, and a run of overlapping AWS key ids becomes one marker). Text with non-overlapping secrets, and secrets that merely touch, redact exactly as before. Rows already written to a ledger, and the `.vibey/handoff/ledger.jsonl` copies made from them, are not fixed retroactively: a fragment such as `Bearer [REDACTED].tail` stored before this change stays as it was, and redacting it again cannot recover it. Shapes and the cursor are configuration (`SecretTextRedactor(shapes, cursor_factory)`), behind `CredentialShapeInterface`, `RunCursorInterface` and `SecretTextRedactorInterface`; a shape the matcher cannot honour (an unbounded or bracket-matching prefix, a separator inside the run before it, adjacent runs that share a character, a shape that matches inside the marker) is refused with a `ValueError` when it is made.
