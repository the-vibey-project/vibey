The ledger redactor no longer leaves bytes of a credential behind when credential shapes overlap. Each pattern used to be substituted in turn, so a shorter shape inside a longer credential was replaced first and the longer pattern could no longer match across the marker: `Bearer sk-AAAAAAAAAAAAAAAA.rest` came out as `Bearer [REDACTED].rest`, and `Bearer AKIA…extra`, a JWT with a fourth segment, a Slack token or JWT with an `sk-` run inside, and a Google key holding an `sk-` run all kept a fragment. A credential glued to the one before it (`sk-…sk-…`, `ghp_…ghp_…`) also kept its whole body, because matching resumed where the previous match ended. Every pattern is now matched at every start in the original text and the overlapping matches are merged into one `[REDACTED]`, so the result no longer depends on pattern order and redacting twice changes nothing. Output changes only where matches overlap: such a run now becomes a single `[REDACTED]` (for example `Bearer sk-…` becomes `[REDACTED]`, not `Bearer [REDACTED]`); text with non-overlapping secrets, and secrets that merely touch, redact exactly as before. The patterns now live on `SecretTextRedactor` (with `SecretTextRedactorInterface`), which takes them as configuration.
