`vibey acp` now guards standard input as it already guarded standard output: the protocol's input is read through a private, non-inheritable duplicate and fd 0 is pointed at `/dev/null`, so a child a doctor section starts (a `launchctl`/`systemctl` query, the Sabbath location lookup) or any other child can never read a byte of the editor's messages; a closed standard input is handled too. `vibey supervisor`'s service-manager queries and the Sabbath location lookup also start their children with standard input closed.
