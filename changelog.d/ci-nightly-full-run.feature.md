**CI runs the full matrix every night on develop's tip, skips the night when nothing changed, and keeps one issue open while it is red** (`ci.yml` `schedule` at 06:17 UTC, `vibey-gh ci-nightly`, the `nightly-report` job; SP1-B Task 4 of the optimization program). Pull requests into develop run only what their diff can affect, so the nightly is where every dropped row (every Python and PostgreSQL version, desktop on every OS, both VS Code jobs, the image, chart and cluster smoke) is still proven daily. The skip guard is a position, not a time: the `plan` job reads the head commit of the last GREEN scheduled run from the Actions API (`vibey-gh ci-nightly last-green`) and `vibey-gh ci-areas --last-green` answers a new `skip` tier only when the tip is that exact commit, declared in `.github/ci-areas.toml` as `[events] skip_unchanged = ["schedule"]` (an event whose checks gate a merge is refused there). Any doubt runs the nightly. A skipped nightly runs `uv-lock`, `plan` and `ci-result` and reads green; `lint` can skip on a `schedule` only. A red nightly opens, or comments once per run on, ONE tracking issue through the family's tracking-issue primitive, and the next green nightly closes it. Nothing the nightly does publishes anything, and no required check or ruleset changes.
