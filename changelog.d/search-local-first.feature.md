Web search is local first. Every search vibey controls (`vibey search`, the DESIGN research stage, and the gptossloop and qwenloop `web_search` tool, which runs `vibey search`) asks a local SearXNG first: `VIBEY_SEARXNG_URL`, else `http://127.0.0.1:28180` (loopback, on vibey's own uncommon port), so search is always configured and `vibey worker` always tells sessions where it is. Nothing there is believed until it proves it is a SearXNG: a GET of its `/config` must answer SearXNG's JSON and, when `VIBEY_SEARXNG_INSTANCE` is set, that `instance_name`; something else on the port (HTML, other JSON, a redirect, another instance) counts as SearXNG being unavailable, and its results are never read. A proof is kept per process for `VIBEY_SEARCH_IDENTITY_TTL` seconds (default 60). Brave is only a backup: a query goes to Brave only when that SearXNG gave no usable answer (unreachable, not finished within `VIBEY_SEARCH_TIMEOUT` in all, any HTTP error, not JSON or nested too deep to read, no results list, no results with every enabled engine unresponsive or none enabled) and a Brave key is set; an empty answer from a healthy SearXNG, or one with only some engines unresponsive, never does. The first Brave answer in a process is said once on standard error (`local SearXNG unavailable (<reason>); this query went to Brave Search`, never the query), and every answer names its backend (`backend` in `vibey search --json`, kept beside `provider`; a `backend:` line in its text output; the DESIGN evidence's source). With SearXNG down and no key, a search fails saying where it looked and how to fix it. `VIBEY_SEARXNG_URL` must now be an `http(s)` URL with a host, a port from 1 to 65535 if it names one, and no user name, password, query or fragment (exit 2 otherwise), so no credential can reach a session. Search backends now follow a redirect only to the same origin, reach a loopback SearXNG (including `localhost.` and `*.localhost`) without a proxy, and give each request a total deadline. Result titles, snippets and fetched pages lose every terminal escape sequence and control character, and a result whose URL holds one is dropped. Inside an engine session a failed search never mentions a Brave key. `vibey doctor` and `vibey acp`'s doctor step gain `web-search` (the local SearXNG answering, or a `WARN` with the fix, including when something other than SearXNG is listening) and `web-search-backup` (configured via which variable, never the key); existing lines and `--json` keys are unchanged. Engine sessions still never receive the Brave key, so a session's search is the local SearXNG alone. **Breaking:** `VIBEY_SEARCH_PROVIDER=brave` is refused (exit 2, and the worker will not start): unset it and keep the key, which is then used automatically when SearXNG is down. A Brave key alone no longer makes Brave the backend: install or start a local SearXNG (or point `VIBEY_SEARXNG_URL` at yours), or every search goes to Brave with the notice.
