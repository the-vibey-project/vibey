`vibey acp`: open gates are now put to the editor as permission requests. After each prompt turn, the open gates the hub lists that the session has not seen yet (oldest first, at most `[acp] max_gate_prompts_per_turn`, each once per session, and only in `drive` mode) appear as a tool call with one `session/request_permission`: an option per choice for a choice or verdict gate (labels in `[acp] reject_words` offered as refusals), "Accept the defaults" for a design question, "Acknowledge" for a gate that takes any answer, and on every gate vibey's own "Leave it open". The pick answers the gate through the hub as the scoped agent principal, with the option's label as the answer: gate text is never read as JSON or a command, and a gate option labelled like one of vibey's is shown as `Answer: <label>`. A cancelled, failed, timed-out or unknown answer, or "Leave it open", answers nothing. Spend gates (`budget_exhausted`, `deploy_*`, or any the hub flags as spending) and the deployment opt-in after REVIEW are never offered: you are told to answer them on the host or in the desktop or mobile app. A gate whose id is not a UUID is not offered. `session/cancel` resolves a permission request still out at once. `/answer 1` and a bare number now mean in an ACP session what they mean at the hub, and a bare number is shown as a gate answer until the hub says what it ran. Do not let an ACP client auto-approve vibey's gate prompts: it would answer non-spending gates with nobody looking.
