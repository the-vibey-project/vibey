`vibey loops` no longer claims MCP for `codexloop`: nothing in codexloop passes an MCP server to Codex, so its `mcp` is now `null` (unknown) and its evidence says why, and `codexloop`'s full-access gaps now include `mcp`. Every capability a loop's descriptor claims is pinned to the runner code that implements it by a new meta-test (`tests/meta/test_loop_capability_evidence.py` over `tests/meta/loop_runner_facts.py`), which fails when a claim has no code behind it or the code moves.
